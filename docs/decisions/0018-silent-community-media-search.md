# ADR-0018：默认媒体发现必须安静运行

- **状态**：已采纳
- **日期**：2026-09-04
- **修正范围**：取代 ADR-0017 中依赖 OpenCLI、Chrome 扩展和已登录浏览器的运行方式；多平台证据、GitHub 真文件核验和免费边界继续有效。

## 背景

OpenCLI 的后台窗口仍然要启动和控制 Chrome。即使窗口尽量放在后台，整条链路仍可能创建标签页、抢占浏览器资源、受扩展或登录状态影响，也无法向用户承诺零干扰。发现 Skills 可以多等一会，但不应影响用户正在使用的浏览器。

## 决定

1. 默认媒体线索只保留 YouTube、B 站和公众号，再与 Hacker News、skills.sh、GitHub 和可信目录合并。
2. YouTube 继续使用 `yt-dlp` 只读公开元数据，明确禁止视频、音频和字幕下载。
3. B 站由 SkillBox 直接请求公开导航接口获取当日 WBI 签名参数，随后以匿名、不携带 Cookie 的方式请求视频搜索接口。签名参数只在运行内存中缓存 20 小时。
4. 公众号由 SkillBox 直接请求搜狗微信公开搜索页，在本地只提取标题、作者、短摘要和时间。记录中保存不带临时 token 的公开搜索页地址，不保存 HTML、全文或页面临时凭据。
5. 这两个原生来源使用独立的短命网络会话，关闭 Cookie 和磁盘缓存。它们不获取、不读取、不复用用户 Chrome 中的任何数据。
6. 小红书和抖音退出当前搜索链路，即使用户在需求中点名也不启动浏览器。未来只能在独立登录容器、明确的当次用户同意和可见来源状态都具备后重新评估。
7. B 站或公众号遇到超时、风控、验证码或页面变化时，当次直接降级为“本轮未参与”。不使用 OpenCLI 或用户浏览器自动补救。

## 理由

搜索质量来自“多人提及的媒体线索＋GitHub 真文件核验”，不依赖浏览器自动化本身。先保住安静、可预期和零搜索费用，比勉强补齐每个平台更符合当前产品体验。

## 存储与费用

- OpenCLI 和 Chrome 扩展不再是 SkillBox 依赖。与旧候选方案相比，用户不需为 OpenCLI 及其依赖准备约 31.0 MiB。
- 新增 B 站签名和公众号页面解析都在应用内，不增加全文镜像、向量库、媒体缓存或无头浏览器。应用包固定增量目标仍小于 1 MiB，以最终 Release 实测为准。
- `yt-dlp` 仍是唯一可选的外部搜索工具，当前 Mac 实测占用约 35.4 MiB。所有搜索服务仍为免费，只有用户选择的模型 API 可能产生费用。

## 回退

默认媒体来源由单一工厂组合。如果某个公开来源长期失效，可单独移除该来源，保留其他媒体、Hacker News、skills.sh、GitHub 和可信目录的已核验结果。
