# ADR-0014：用户自有 Agnes API 与手动获取 Skill 介绍

- **状态**：已采纳
- **日期**：2026-09-02
- **取代**：ADR-0013

## 背景

用户希望 SkillBox 帮忙把 Skill 的作用、适用场景、使用流程和启动提示词讲清楚，但不希望应用在后台自动上传本地 Skill。用户愿意自行申请 Agnes API Key，自己承担账号、额度和费用，并且在每份 Skill 需要介绍时主动点击。

这条路径也删除了 SkillBox 中转服务带来的账号、运维、成本、限流和数据保留责任。

## 决定

1. 用户在“设置 → AI”中填写自己的 Agnes API Key，完成连接测试后才能使用 Skill 介绍。API Key 只保存在 macOS 钥匙串。
2. Skill 介绍固定使用 Agnes 配置，默认模型为 `agnes-2.5-flash`。“发现 Skills”选择 DeepSeek 或其他服务商时，Skill 介绍不跟随切换。
3. 打开应用、切换 Skill、新增 Skill、来源检查和内容变化均不发起介绍请求。
4. 用户点击“获取 Skill 介绍”就是当次发送授权。该动作可恢复、不改文件，因此不再叠加第二个确认弹窗。
5. 客户端只读取并脱敏 `SKILL.md`、`README.md`、`agents/openai.yaml`、`agents/` 和 `references/` 内有上限的文字。脚本、二进制、图片、密钥、绝对路径和完整文件夹不进入请求，Skill 中的任何内容都不会被运行。
6. 客户端直接请求 Agnes 官方 HTTPS OpenAI 兼容接口。SkillBox 不包含共享 Key，不建设转发服务。
7. 结果按 `Skill ID + 内容指纹 + 提示词版本` 保存在本机。并发重复点击共用一个进行中请求。
8. Agnes 失败时保留已有介绍或本地保底说明，不静默切换其他服务商。用户稍后可以主动再次点击。
9. 钥匙串读取分为两条路径：启动、状态恢复和后台任务只允许静默失败；用户点击“保存并测试”或“获取 Skill 介绍”时允许 macOS 显示一次钥匙串确认。确认成功后继续使用原 Key，不要求重新粘贴；用户取消时不发送 Skill 内容。

## 界面合同

- 未连接介绍服务时，Skill 详情显示“AI 介绍”和“连接 AI”，并将用户引导到 AI 设置；具体服务商名称只在设置页出现。
- 已连接且没有 AI 介绍时显示“获取 Skill 介绍”；已有 AI 介绍时显示“重新获取”。
- 请求开始后立即显示进度。已有介绍在请求期间继续可读，成功后原地替换。
- 按钮悬停说明用一句话告知用户：点击后才会把当前 Skill 的说明文件发给 Agnes。
- 设置页只用一句话提示：若 macOS 询问钥匙串权限，选择“始终允许”后同一应用身份不再重复询问。

## 后果

- 调用权、额度和费用直接归属用户的 Agnes 账号。
- SkillBox 不承担模型转发服务的运维与用户内容处理责任。
- 用户需要完成一次 API 配置，换取每次发送都由自己决定的清晰控制感。
- ad-hoc 安装包更新后可能由 macOS 视为新的应用身份，下一次用户主动操作最多重新确认一次；稳定 Developer ID 签名可跨版本延续授权。
