# ADR-0003：中央原件库与事务式实体复制

- **状态**：已采纳
- **日期**：2026-08-14

## 背景

软链接能即时共享原件，但部分 Agent 不跟随软链接，且原件修改会在用户没有确认的情况下同时影响多个产品。普通复制兼容性高，却容易漂移和误覆盖。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 全部软链接 | 一处修改立即生效 | 兼容性不一致，变化难感知 |
| 直接复制 | 兼容广 | 缺少所有权、预览与恢复 |
| 中央库 + 事务式复制 | 兼容广，可预览、追踪和撤销 | 需要指纹、清单和备份机制 |

## 决定

中央仓库保存可信原件；目标 Agent 使用实体复制。每次写入由计划、备份、暂存、校验、替换和事务记录组成。

SkillBox 只自动更新或移除自己管理且没有外部漂移的目标。未管理冲突和外部改动必须阻塞并交给用户处理。

## 后果

- 用户明确知道一次同步会发生什么，也能恢复。
- 核心模块必须把扫描、计划和执行隔离，并为中途失败、目标消失和撤销冲突提供测试。

## 2026-08-22 事务收口

- 现有目标目录与暂存目录通过 macOS 同卷原子交换完成替换；交换后校验被换出的真实旧内容，确保最终提交边界发生的外部改动不会被覆盖。
- 删除与从废纸篓恢复都必须先持久化运行中事务。应用在文件移动后退出时，下一次启动按日志恢复到操作前状态。
- 分项 JSON 继续作为兼容镜像，但 `library-state.json` 保存完整 `LibrarySnapshot` 并最后原子写入，作为跨文件状态的唯一提交点。启动只从该完整代际恢复；旧版分项数据会自动迁移。
