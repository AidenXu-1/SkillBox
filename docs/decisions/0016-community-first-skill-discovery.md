# ADR-0016：先看社区反复提及，再回 GitHub 核验 Skill

- **状态**：已被 ADR-0017 扩展
- **日期**：2026-09-04
- **取代范围**：修正 ADR-0015 中“先从 Skill 目录和 GitHub 大量召回，再按正文排序”的首要发现顺序；其免费、正文核验、限流和存储边界继续有效。

## 背景

真实体验暴露出两个根本问题。第一，模型把“卡兹克的写作 Skill”误解成《英雄联盟》角色写作，丢失了用户指名的作者身份。第二，“去文案 AI 味”已经召回数千至数万次安装的候选，但排序把最近更新和说明长度放在实际使用与社区口碑之前，冷门候选反而占据首屏。

用户要找的并非理论上最像需求的仓库，而是同类需求下被不同用户反复提及、随后能在 GitHub 核验为真实 Skill 的选择。搜索时间可以稍长；搜索、索引、向量和媒体接口本身不得产生费用，只有用户选择的模型调用可以使用 Agnes 免费方案或用户自备 API。

## 决定

发现链路改为两层证据：

1. 先查询无需付费和额外账号的优质技术社区。首个来源采用 Hacker News 的公开 Algolia 搜索入口。每条结果只有明确包含 GitHub 仓库链接时，才可形成 Skill 线索；同一作者的重复帖子只算一位提及者。
2. 把媒体线索中的仓库名和可能的 Skill 名交给现有 GitHub 搜索，读取真实 `SKILL.md`、仓库资料和安装量。无法核验真实文件的线索不进入候选。
3. 本地排序先保证能直接完成任务，再比较独立社区提及人数和可信互动量，然后比较实际安装量、作者官方来源、维护状态和说明完整度。多 Skill 仓库的总 Star 继续不能替子 Skill 证明质量。
4. 用户写出的原始目标不可被模型改成另一个故事背景。初次寻找始终保留原句；“某人的某类 Skill”按作者、品牌或项目名处理，补充原文、常见英文写法和精确 Skill 名查询。只有用户明确说到角色、游戏或模仿角色时，才按虚构人物理解。
5. 媒体线索是可失败的增强层。它超时、限流、结构变化或没有命中时，skills.sh、GitHub 和版本化可信目录继续工作，并保留已经核验的结果。

## 免费来源边界

- 不采用需要持续付费的商业网页搜索、Embedding、向量库或托管索引。
- 不采用 Bing RSS。当前响应中的许可文字把结果用途限制为个人、非商业 RSS 聚合，无法作为 SkillBox 的长期产品依赖。
- 不把 Reddit 数据接口设为产品依赖。当前新应用需要审批，无法满足普通用户零配置和稳定免费的边界。
- Hacker News 社区搜索不需要 Key 或付费；按可替换来源接入，设置响应上限、超时和失败降级，避免把非正式公开入口误写成永久承诺。

## 验收题

- “帮我找到卡兹克的写作 Skill”必须保留“卡兹克”这个身份，并把 `KKKKhazix/khazix-skills` 中的 `khazix-writer` 放在 `hv-analysis` 前；不得自行补成英雄联盟角色写作。
- “帮我找一个去文案 AI 味的 Skill”中，被多位社区用户独立提及且有真实安装量的 `blader/humanizer` 应排在只有关键词或最近更新时间优势的冷门候选前。
- 只检测 AI 痕迹、明确不改写的 Skill 不得进入“去 AI 味”推荐。
- 媒体结果没有明确 GitHub 身份时不得让模型猜仓库；同一作者重复发帖不得虚增“多人提及”。
- 媒体来源失败时，其他免费来源的已核验结果仍可展示，界面明确搜索未完全完成。

## 存储边界

- 不新增本地全文镜像、搜索索引、向量数据库或模型，固定长期存储新增为 0。
- 每个候选最多保存 5 条社区证据；每条只含平台、帖子编号、作者、标题、公开链接、时间和互动数，不保存帖子正文。
- 社区证据进入原有寻找记录，继续受全部寻找记录累计 64 MiB 的硬上限约束。按每条证据约 1 KiB 的保守上限计算，96 个详细候选的最坏新增量不超过约 0.47 MiB；实际通常远低于此值。

## 回退

社区来源由独立 `SkillDiscoveryProvider` 接入。移除该 Provider 即可恢复 ADR-0015 的目录、skills.sh 与 GitHub 路线；持久化字段向后兼容，旧寻找记录无需迁移或删除。
