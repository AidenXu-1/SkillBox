# ADR-0008：可选 AI、Skill 发现与安全复核

- **状态**：已采纳，v2.1 根因修复与质量优先检索实施中
- **日期**：2026-08-17

## 背景

SkillBox 已能从本机与 GitHub 导入、更新和安全分发 Skill，但普通用户仍需要解决三个问题：不知道应该找什么 Skill、难以从作者资料中快速判断是否适合、面对脚本和权限提示时难以理解真实影响。

本机 `find-skills` 的搜索方法证明了“需求理解、目录搜索、来源与流行度核对”的价值；`skill-vetter` 的来源、全文件、权限和风险四步检查提供了安全审查骨架。两者也存在不能直接产品化的部分：安装量和 Star 不能证明质量，关键词命中不能证明恶意，AI 结论也不能代替可重复的本地证据。

## 决定

1. AI 定位为可选的解释与二次复核层。文件完整性、安装范围、风险阻止、覆盖授权、备份和撤销继续由本地确定性规则决定。
2. “发现 Skills”作为左侧一级导航，与“我的 Skills”并列。总览页提供一个只用于 Skill 发现的自然语言快捷输入，提交后进入同一发现状态。产品不建立通用聊天首页或办公助手，但会保留与「找 Skill」直接相关的结构化寻找记录。
3. “添加 Skill”只处理用户已经知道地址的电脑目录与 GitHub 来源；“发现 Skills”处理用户只有目标、还不知道具体 Skill 的情况。用户描述目标后，SkillBox 搜索公开目录、补充 GitHub 资料、先做本地筛选，再用 AI 对少量候选解释相关性。
4. 推荐由相关性、来源身份、维护状态、安装量、仓库级 Star、结构完整性和安全结果组成。各信号分别展示，不合成百分制，也不接受付费排序。Star 必须明确属于 GitHub 仓库，多 Skill 仓库不得把同一个数字包装成每个 Skill 的独立评价。
5. 安全审查固定为来源、内容、权限和上下文四层。全部安装文件先由本地规则读取且不执行；AI 只接收脱敏证据和必要片段，负责解释上下文与发现可能遗漏的语义关联。
6. 用户界面只显示“未发现明显问题、需要了解、需要确认、无法添加”。不得宣称绝对安全；需要了解以上的结论必须给出真实文件、位置、命中内容与下一步。
7. 首发 AI 服务商为 Agnes、DeepSeek 和自定义 OpenAI 兼容接口。用户自行提供 API Key，密钥只存 macOS 钥匙串。客户端不包含共享密钥，服务商之间不静默转发内容。
8. AI 与搜索都由用户主动触发。私人或本地 Skill 第一次发送前必须预览范围并单独确认；未配置 AI 或外部服务失败时，SkillBox 核心功能保持完整。
9. AI 输出采用版本化结构，并由本地验证文件路径、行号和内容身份。Skill 文本视为不可信输入，不启用工具调用、网址访问或代码执行；无法核对的结论直接丢弃。
10. AI 在服务层统一，在界面层按任务出现：发现候选、整理用户说明、解释安全与版本变化。用户说明优先读取作者展示资料、明确的用户章节和示例；缺失项省略，不把内部执行规则改写成教程。
11. 首发不建设 SkillBox 服务端。发现目录与 AI 都通过可替换 Provider 接入；缓存按内容身份与模型版本绑定，可清理且不参与安装真相。
12. 寻找记录只保存用户目标、补充条件、候选快照和选中状态。开始新寻找不自动删除旧记录；用户可继续、单条删除、全部清空或在 Finder 中打开保存位置。删除记录不得删除已加入中央库的 Skill。
13. “发现 Skills”用 `planDiscovery` 理解本轮目标，再用 `evaluateCandidates` 分批比较已经核对的真实候选。批次只控制上下文，不限制候选总数；每条用户消息最多保存一条 AI 真正生成的最终回复。进度与系统故障不进入聊天记录。
14. 搜索始终包含用户当前目标的原始查询；AI 只能增加最多 3 条语义查询，不能用改写结果替代原话，也不能把全部历史消息拼成搜索词。筛选反馈只更新意图。
15. 第二阶段只接受本轮真实候选 ID。未知 ID、虚构路径和无法回到公开证据的结论一律丢弃；AI 未配置、超时或返回损坏 JSON 时继续使用确定性搜索与质量分层，并保留上一轮有效结果。
16. 候选进入“推荐”前必须核对 Skill 级资料或真实 `SKILL.md`。skills.sh 安装量和仓库 Star 只作为知名度证据，仓库简介单独折叠展示，不得冒充 Skill 用途。
17. DeepSeek 等结构化任务必须按服务商能力发送 JSON 输出与思考模式控制。连接测试必须完成一次最小结构化输出；HTTP 成功不等于任务成功，空内容、截断、损坏 JSON 和字段校验失败分别记录脱敏诊断。
18. 发现召回同时覆盖 skills.sh、GitHub 真实 `SKILL.md` 与版本化可信来源目录。搜索持续到完整一轮没有新增通过质量门槛的候选；不设置 5、8、13、15 等产品数量上限。
19. 推荐必须同时满足真实 Skill 内容可读、需求高度匹配、来源可追溯且没有阻止导入的问题。安装量、Star 或作者身份不能单独使候选进入推荐。

## 服务边界

- `SkillDiscoveryProvider`：公开候选批量搜索、去重、Skill 详情补全和证据缓存。
- `CandidateQualityEvaluator`：相关性、来源、维护、使用和结构信号。
- `SkillSafetyReviewService`：编排来源、内容、权限和上下文检查。
- `PermissionInferenceEngine`：归纳文件、命令、网络和凭据范围。
- `AIProvider` / `OpenAICompatibleProvider`：Agnes、DeepSeek 和自定义模型连接，并提供 `planDiscovery` 与 `evaluateCandidates` 两个结构化发现接口。
- `AIInputPackager` / `SecretRedactor`：最小化并脱敏发送内容。
- `AIResponseValidator`：结构、证据和内容身份复核。
- `AIReviewStore`：按指纹、任务、提示词、服务商和模型缓存结果。
- `AIKeyStore`：钥匙串保存、测试与删除。

## 不选择的方案

- **让 AI 自动决定安装文件**：不可重复，可能再次删除关键运行文件，并破坏 ADR-0007 的无损与可恢复边界。
- **把 skills.sh 排行榜直接当推荐**：安装量只代表被安装过，不能证明适配当前任务或安全。
- **关键词命中即拒绝**：正常的清理、网络或凭据说明容易被误伤，必须结合文件类型、目标范围和数据流。
- **在客户端打包共享 Agnes Key**：桌面应用中的共享密钥可以被提取，无法控制滥用和成本。
- **把首页做成通用 AI 聊天框**：会让用户期待办公问答、长期记忆和工具执行，扩大产品边界，并遮住资产状态、更新与冲突等核心管理任务。
- **AI 失败时自动切换服务商**：会在用户不知情时改变数据接收方。
- **首发建设 SkillBox 中转服务**：引入账号、成本、数据保留、风控和运维，超出当前本地优先产品边界。

## 后果

- 用户可以从总览快捷输入或一级“发现 Skills”走到可解释候选、安全结论和中央入库，无需使用终端。
- AI 能力拥有一致的数据、安全和证据合同，但不会把 SkillBox 变成通用聊天产品。
- 安全报告更容易理解，但仍保留可核对证据和本地硬边界。
- 新增网络、隐私、密钥、缓存和模型兼容测试；正式开发前必须先确认“总览智能搜索、发现 Skills、发现详情、我的 Skill 用户说明、安全报告、AI 设置”可操作原型。
- skills.sh、GitHub 或模型服务不可用只影响对应辅助功能，不影响用户已经拥有的 Skill。
