# ADR-0020：用确定路由分开精确查找与社区场景发现

- **状态**：已采纳
- **日期**：2026-09-04
- **修正范围**：在 ADR-0019 的质量与稳定性边界之上，分开不同用户意图的召回来源与展示门槛。

## 背景

经过独立对抗审查，现有链路最大的结构性问题是：用户点名某个 Skill 和用户只描述一个任务，都会进入同一条“媒体＋目录＋skills.sh＋GitHub＋模型比较”链路。这会造成三类失真：

1. 精确名称未命中时，相似但更热门的 Skill 被当成替代品。
2. 场景发现中，目录或 GitHub 自己召回的项目可以没有任何社区推荐便进入结果。
3. 媒体只提一个名字时，同名的多个仓库可能同时继承这条推荐。

底层原则是：一条推荐只能证明它真正指向的那个对象，而用户明确给出的对象不应再被热度和模型推测改写。

## 决定

1. 在任何模型调用之前，用本地规则将请求分为精确、场景和混合三类，并保存最小的名称、仓库、路径或作者实体。
2. 精确查找只使用可信目录、skills.sh 和 GitHub，不查媒体，不调用模型规划或比较。用户给出 GitHub Skill 路径时直接读取对应 `SKILL.md`。
3. 精确查找只保留同名、同仓或同路径的真实候选。没有命中时说明没有精确结果，不混入相似 Skill；同名多结果全部列出。
4. 场景发现只返回能绑定公开社区推荐证据且已读到真实 `SKILL.md` 的候选。目录、skills.sh 和 GitHub 是后续定位与核验工具，不再单独产生场景推荐。
5. 作者加能力、或已知 Skill 加口碑问题使用混合链路；保留原始请求和作者别名，允许媒体证据与直接来源交叉。
6. 媒体名称线索只在有唯一已核验候选时绑定。多个仓库同名时，这条线索保持未解析并向用户透明展示。
7. 排序先比较任务和交付物的直接匹配，再比较独立社区作者、跨平台覆盖、热度和安装量。

## 效率、Token 与存储

- 精确查找直接少掉媒体搜索、规划模型和候选比较模型；用户给出 GitHub 路径时，还少掉整仓代码搜索。
- 场景搜索不再额外并行三路独立目录结果；目录、skills.sh 和 GitHub 只在媒体线索需要定位真实 Skill 时使用，减少重复召回与无效上下文。
- 精确查找的候选比较 Token 为零；场景与混合查找仍沿用每轮最多 6 个候选、12,000 字符证据和 1,500 输出 Token 的上限。
- 路由元数据每轮小于 2 KiB，不新增数据库、索引、完整仓库或媒体正文缓存；全部寻找记录继续受 64 MiB 总上限约束。
- 不新增任何付费搜索服务。只有用户自选的大模型 API 可能产生费用。

## 回退

路由层与三条来源组合都可独立替换。如新路由出现回归，可回退应用包而不修改寻找记录、Skill 库或 Agent 安装目录；旧记录缺少路由字段时按场景发现读取，不丢失历史数据。
