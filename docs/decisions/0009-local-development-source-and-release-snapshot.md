# ADR-0009：本地开发来源与安装快照

- **状态**：被 [ADR-0011](0011-global-skill-source-and-installation-snapshot.md) 部分取代
- **日期**：2026-08-21

## 背景

私人本地 Skill 经常在用户自己的项目目录中持续迭代。开发项目同时包含测试、设计稿、笔记和其他开发资料；把整个项目直接安装会污染 AI 应用目录，而每次手工复制到另一个纯净目录再导入又会产生重复劳动和版本漂移。

## 候选方案

| 方案 | 优点 | 主要问题 |
|---|---|---|
| 每次手工提炼纯净目录 | 实现简单 | 重复劳动，容易漏文件或导入旧版本 |
| 把开发项目迁入 SkillBox 保存位置 | 路径统一 | 应用数据与用户项目职责混合，备份、Git、编辑器和卸载边界变差 |
| SkillBox 直接把开发目录安装到应用 | 更新即时 | 开发文件泄漏，修改会绕过预览、备份和撤销 |
| 外部开发来源 + 内容规则 + 安装快照 | 保留开发习惯，纯净、可预览、可撤销 | 需要持久来源状态、打包规则和重连流程 |

## 决定

1. 用户选择的外部开发文件夹是该 Skill 的唯一来源，SkillBox 对其只读，不移动、不改写、不执行。
2. 每个 Skill 保存独立的 `LocalPackageRecipe`，使用相对于 Skill 根目录的精确包含路径。`SKILL.md` 及其明确引用内容为强制项。
3. SkillBox 先把选中内容物化到临时目录，完成目录安全、指纹和静态风险检查后，才允许生成或更新安装快照。
4. 外部开发文件夹是内容原件；安装快照是一次安装使用的不可变材料。AI 应用继续使用事务式实体复制，不直接链接开发来源。
5. 检查本地更新只在用户主动触发时执行。未确认前不写安装快照和应用；确认后复用现有更新、联合安装、备份、失败恢复和撤销流程。
6. 开发文件变化不提示 Skill 更新。已选路径消失、新增可能运行路径或入口引用关系变化时，状态改为需要确认。
7. 位置访问同时保存安全作用域书签与可读路径。来源不可用时保留所有现有内容；重新关联必须核对 Skill 身份并展示差异。
8. 每份受管理 Skill 必须持续保有来源。用户可以重新关联同一份本地开发来源，或通过完整删除流程移除该 Skill；不提供“停止跟踪后留下无来源副本”。

## 后果

- 用户可以在原项目中继续用 Git、编辑器和现有开发流程。
- SkillBox 与 AI 应用只接触确认过的纯净内容，开发资料不会随项目更新自动泄漏。
- 一个项目可以承载多个 Skill，每个 Skill 独立更新和重连。
- v1 采用手动检查，不增加文件监听、构建系统、双向同步或后台任务。

## 回退

若本地来源暂时不可用，当前安装快照、历史版本、事务记录和应用副本保持原样，Skill 标记为“来源暂不可用”。用户重新选择文件夹并通过身份核对后恢复；若不再管理，则走完整删除流程，不制造无来源 Skill。
