# ADR-0019：搜索质量优先，同时约束等待、上下文与失真

- **状态**：已采纳
- **日期**：2026-09-04
- **修正范围**：在 ADR-0018 的静默媒体搜索基础上，补齐作者意图、媒体线索、免费核验、并发超时和模型预算边界。

## 背景

独立盲审确认，当前链路已经能后台搜索公开媒体并核验真实 `SKILL.md`，但仍有几处会直接伤害用户体感：补充要求可能冲掉上一轮作者名；媒体标题可能把网址误认成 Skill 名；无法立刻对上 GitHub 的真实讨论会被静默丢弃；慢来源可能拖住整轮；skills.sh 默认接口需要身份而匿名请求必然失败；模型会重复比较过多候选并携带不必要的社区文字。

搜索质量的底线是两层事实不能混在一起：社区讨论证明“有人提过”，真实 `SKILL.md` 证明“它确实存在且能完成任务”。前者不能越权成为推荐，后者也不能让用户看不到尚待核实的口碑线索。

## 决定

1. 用户只是在追问“更热门、质量更高”时，上一轮的作者、品牌和精确 Skill 名继续参与规划；只有明确切换目标才替换旧意图。
2. 媒体名称提取拒绝 `http`、`https`、`www` 和域名后缀，并保留标题中明确标注的中英文 Skill 名。
3. 无法绑定真实 `SKILL.md` 的讨论不进入候选列表，但每轮最多保留 8 条平台、作者、标题、链接和短摘要元数据，在界面明确说明，供继续深挖和问题复盘。
4. 可信目录、skills.sh、GitHub 和媒体层独立并发，最终仍按固定来源顺序合并。单个候选来源最长等待 55 秒，单个媒体平台最长等待 45 秒；超时只降级该来源，用户取消会结束全部进行中任务。
5. skills.sh 使用无需登录的 `/api/search`；精确媒体名称先由内置可信目录核验，再尝试 skills.sh，最后才依赖 GitHub 的匿名搜索额度。
6. 每次寻找或继续深挖只把本地排序最高且尚未送评的 6 个候选交给模型一次比较。模型只接收数字化的社区作者数、平台数和归一热度，不接收媒体标题、作者原文或无关上下文。未送评候选继续保留到下一次深挖。
7. `yt-dlp` 显式忽略本机配置，禁止读取浏览器 Cookie 和其他 Cookie，并关闭磁盘缓存；SkillBox 不启动浏览器，也不依赖 OpenCLI。

## 质量与稳定性边界

- 社区讨论只能增加可解释的口碑证据，不能绕过能力匹配与真实文件核验。
- “去 AI 味、改得更自然”属于改写任务；只检测或打分、不执行改写的 Skill 必须判为能力错配。
- 任一来源失败都保留其他来源的已核验结果，并如实显示未参与、超时、未绑定和待继续核验的事实。
- 模型仍可能因服务商结构化输出失败而在既有安全边界内重试，但产品侧每轮只有一个、最多 6 个候选的逻辑比较批次，输出上限保持 1,500 Token。

## 存储与费用

- 不新增数据库、本地索引、向量库、Embedding、全文镜像或付费搜索服务。
- 未绑定讨论最多 8 条／轮，典型新增小于 8 KiB，并继续计入全部寻找记录原有的 64 MiB 总上限；不会因为本决定提高上限。
- 唯一可选外部工具仍是免费的 `yt-dlp`，当前 Mac 实测约 35.4 MiB。OpenCLI 已退出 SkillBox 运行依赖，其本机旧副本是否清理由用户另行决定。
- 只有用户选择的模型 API 可能产生费用；Agnes 免费方案和用户自备模型配置保持不变。

## 回退

并发、超时、媒体线索保存、skills.sh 接口和模型批量上限都有独立实现与回归。若某一来源或排序策略出现新问题，可以单独关闭该来源或恢复上一批量边界，不影响用户数据、Skill 库和 Agent 安装关系。替换应用前继续保留完整旧应用备份。
