# ADR-0013：内置 Agnes Skill 介绍服务

- **状态**：已被 ADR-0014 取代
- **日期**：2026-09-02
- **后续决策**：用户确认改为自带 Agnes API Key 与逐次主动触发，详见 ADR-0014。本文仅保留为已经被推翻的历史方案。

## 背景

“我的 Skills”要让普通用户看懂每份 Skill 的作用、适用场景、使用流程和启动方式。公开 GitHub Skill 往往有可复用的介绍，本机开发和私人 Skill 却经常只剩原始 `SKILL.md`。让每个用户理解服务商、申请 API Key、测试连接和逐个授权，会把一项基础阅读能力变成技术配置任务。

同时，将共享 Agnes Key 打包进开源 macOS 客户端会必然泄露，也无法做费用上限、限流和滥用处理。

## 决定

1. Skill 介绍成为 SkillBox 内置基础能力，接收方固定为 Agnes 2.5 Flash。
2. 首次发送前只出现一次简洁确认，同时说清接收方、会发送的说明文字和不会发送的内容。“暂不用”后不反复弹出；可从设置重新开启。
3. 同意后，应用在运行期间顺序整理现有、以后新增及内容变化的已管理 Skill。按 `Skill ID + 内容指纹 + 提示词版本` 缓存，同一内容不重复请求。
4. 客户端只读取并脱敏 `SKILL.md`、`README.md`、`agents/openai.yaml`、`agents/` 和 `references/` 内有上限的文字。脚本、二进制、图片、密钥、绝对路径和完整文件夹不进入请求，也不运行 Skill。
5. 客户端通过 `BuiltInUsageGuideService` 只调用 SkillBox 固定 HTTPS 端点。请求合同没有 API Key 字段，客户端不包含共享 Agnes 密钥。
6. SkillBox 服务端保存 Agnes 凭据，并负责鉴权、限流、缓存、防滥用、费用上限和不保留 Skill 原文。这个服务不存储用户 Skill，不建立 SkillBox 账号或云端 Skill 库。
7. 服务不可用时，客户端保留当前完整缓存或本地确定性保底说明；同一内容在当次应用会话中不反复重试，不静默切换 DeepSeek 或任何其他接收方。
8. 关闭服务后取消未完成整理，停止新请求，已经保存在本机的介绍不删除。

## 发布门槛

- 客户端没有配置真实 SkillBox 服务端点时，必须把服务判定为不可用，不展示伪造的正在整理状态。
- 真实用户开启前，必须独立验证服务端鉴权、限流、费用上限、日志脱敏、原文不保留、删除策略和隐私文案。
- 端到端验收必须使用不含私人内容的专用样例 Skill，不得为测试上传用户真实本地 Skill。

## 后果

- 普通用户不需要理解 API Key 即可获得完整 Skill 介绍。
- 项目新增一个真实服务端与运维责任；在它通过发布门槛前，客户端实现只能称为“已完成合同和界面、尚未接通真实服务”。
- 发现 Skills 中的用户自定义 AI 仍保留独立密钥、服务商和主动触发合同，不与内置介绍服务混用。
