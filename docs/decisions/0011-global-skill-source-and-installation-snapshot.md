# ADR-0011：全局 Skill 唯一来源与安装快照

- **状态**：已采纳
- **日期**：2026-09-01

## 背景

旧模型把 Agent 目录、本地文件夹、GitHub 和停止跟踪后的中央副本都视为可能来源，同时把中央保存内容称为母版或原件。来源、安装材料和应用副本因此互相混淆，首次扫描还会制造大量重复与冲突整理任务。

用户确认 SkillBox 只服务于跨项目使用的全局 Skill。真实来源只有专门的本地开发文件夹和 GitHub 仓库；项目级 Skill 完全退出产品边界。

## 决定

1. 每个受管理 Skill 必须且只能关联一个来源，类型限于本地开发文件夹或 GitHub 仓库。
2. Agent 与通用全局 Skills 目录只能作为安装目标和现有内容保护依据，不得创建新的 Skill 来源。
3. 本地开发文件夹或 GitHub 是原件。SkillBox 在用户确认后冻结不可变安装快照，再把同一快照实体复制到多个 Agent。
4. SkillBox 内部保存的内容只称为当前安装快照和历史快照，不再承担母版或原件身份。
5. 项目级 Skill 不扫描、不导入、不展示、不安装，也不设计跨 Agent 项目目录兼容逻辑。
6. 发现页候选加入后使用 GitHub 来源，不产生新的来源类型。
7. 历史 `agentDirectory` 记录仅为无损迁移而可读取，不允许新增。用户关联本地开发文件夹或 GitHub 前，不得从该记录发布新版本；现有内容和安装副本不得自动删除。

## 理由

用户的核心任务是把一份全局 Skill 安装到多个 Agent。唯一来源、一份经确认的安装快照和多个使用副本，已经覆盖全部必要状态；其他来源类型只会增加解释成本和数据歧义。

## 后果

- “添加 Skill”只保留本地开发文件夹和 GitHub 两个入口。
- 首次扫描不再把 Agent 副本导入“我的 Skills”，也不再生成重复版本整理中心。
- 安装与更新必须绑定来源身份和快照指纹。
- 旧 `agentDirectory` 数据需要兼容读取和显式迁移，不能静默删除或伪装成正式来源。
- ADR-0003 中“中央仓库是长期原件”的用户概念被本 ADR 取代；事务复制与恢复机制继续保留。
- ADR-0009 中“中央发布快照是部署真相源”调整为“来源是原件，安装快照是一次部署的不可变材料”；“停止跟踪后成为普通本地副本”废止。

## 回退

若新模型无法完成真实迁移，可回退产品入口与写入限制；已保存的历史记录、安装快照和 Agent 副本保持原样，不自动恢复从 Agent 目录新建来源。
