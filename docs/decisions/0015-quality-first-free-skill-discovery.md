# ADR-0015：质量优先且不引入付费搜索的 Skill 发现

- **状态**：已采纳
- **日期**：2026-09-03

## 背景

现有发现链路主要依赖 skills.sh 与 GitHub 关键词搜索，并在读取真实 `SKILL.md` 前先用 Star 和安装量收窄候选。这样虽然省请求，却会把刚发布、用途很窄或位于多 Skill 仓库中的优质内容挡在门外；中文目标也容易漏掉只写英文说明的 Skill。用户接受多等待一会，但要求搜索工具和索引本身免费，只有模型调用可以使用 Agnes 免费方案或用户自备的付费 API。

## 候选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| 购买商业搜索、向量库或 Embedding 服务 | 接入快，语义检索成熟 | 持续费用和服务依赖不符合产品边界 |
| 在本机保存完整 Skill 镜像与全文向量索引 | 离线搜索强，可做复杂召回 | 首次下载、更新和磁盘占用明显，模型与索引格式也要长期维护 |
| 随应用发布轻量可信目录，结合免费公开接口、实时正文核验和小批模型比较 | 零搜索费用，来源可控，能保留低热度候选，固定空间很小 | 搜索会多花一些时间，目录随版本更新，公开接口限流时只能部分完成 |

## 决定

采用第三种方案。应用内置由 OpenAI、Anthropic 和 GitHub 公开仓库生成的版本化目录，对抗审查后更新为 921 个 Skill，搜索命中后仍在线重读真实 `SKILL.md`。目录明确区分“作者官方维护”与“平台收录”：Anthropic 作者仓库的 19 项为官方，OpenAI 插件仓库与 GitHub 合集中的 902 项只表示已收录；仓库内部 `.github/` 与 `.agents/` 配置不进入目录。同时扩大 skills.sh 与 GitHub 召回，取消热度准入门槛，并用本地中英文扩词覆盖常见中文需求。

跨语言召回由读取候选正文前的模型查询规划和免费本地扩词完成，补充查询在继续深挖时仍会沿用。候选比较模型只接收已经通过本地相关性与独立品质门槛的真实候选：每轮取下一批尚未送评的 30 个，每组 6 个；靠前候选用轮转方式分散到不同小组，多组完成后把各组第一名再做一次最终比较。候选正文按不可信资料处理；候选名称只帮助召回，必须由已核验的 Skill 摘要建立相关资格。本地使用中英否定词族和前后作用范围区分“缺少邮件能力”与“支持邮件，但缺少日历能力”。模型推荐必须引用一段真实正文，应用再独立检查原句存在、与用户目标相关、表达的不是否定能力，且候选材料不含已知的评级干预语句。模型结果只可解决本地合格候选的末端并列，不能新增、隐藏或降级推荐资格，最终比较也只调整各组优胜者的顺序。reply、reason 和其他自由文本不进入产品。独立品质证据只来自作者官方来源、至少 500 次 Skill 级安装量，或“近两年维护 + 有实际使用结构的正文”；平台收录只帮助召回和末端排序，不能形成品质证据，也不再用 600 字单点分界。排序优先看任务和交付物匹配，再看作者官方来源、维护和说明完整度，然后看 Skill 级安装量；多 Skill 仓库的 Star 不能使子 Skill 进入推荐，单 Skill 仓库 Star 也只能作末端并列参考。模型漏评、返回未知候选、引用无法验证、引用否定能力或结构损坏时，整组结果丢弃。

搜索完整性也是产品结果的一部分。初次每个查询读取 64 个候选，深挖依次扩展到 160、320、640 和 1,000；skills.sh 接口的单词实际上限为 200，到上限就保守标记为可能未完成。GitHub 同时使用服务端总数和 `incomplete_results` 判断是否还有后续。每个来源单轮最多合并 1,000 个候选，三来源累计最多保留 3,000 个。为保护 GitHub 免费额度，目录、skills.sh 和 GitHub 每次分别核验下一批 12、4、8 个候选，并记住进度。GitHub 限流状态在来源间共享，触发后立即停止后续请求并显示可重试时间。来源失败、查询失败、读到上限、核验失败、待核验数和限流分开记录，并保留已经通过的结果。

## 理由

搜索质量的关键是先让真正相关的候选进入赛场，再用完整正文判断能力。热度适合证明“很多人见过”，不适合证明“正好能完成这件事”。轻量目录提供稳定入口，公开接口提供实时广度，正文核验防止目录陈旧，分组比较让模型在有限上下文中做更细的选择。

这条路线不购买搜索 API、向量数据库、Embedding 或托管索引。只有用户明确选择的模型请求可能产生费用；Agnes 免费方案可继续作为默认选择。

## 存储边界

- 当前目录文件为 432,373 字节，约 0.41 MiB；随应用资源一同发布，目标始终小于 1 MiB。本轮 Release 候选应用比当前已安装版多 744 KiB，约 0.73 MiB。
- 不在磁盘保存公共仓库镜像、全文索引、向量数据库或额外模型。
- 内置目录远端正文缓存最多 128 份、合计 8 MiB，6 小时过期；skills.sh 的仓库与证据缓存分别最多 128 与 256 项。这些是运行内存，应用退出后释放，不占用长期磁盘。
- 每个公开来源单轮最多合并 1,000 个候选，三路累计最多 3,000 个；每份进入搜索模型的正文证据最多 8,000 字符。
- 寻找记录中，最多 96 个当前最需要的候选保留每份最多 8,000 字符的 `SKILL.md` 摘要，其余候选仍保留名称、来源和质量证据，不再重复保存正文。测试中的 150 个满长正文候选记录小于 1.5 MB。
- 全部寻找记录的累计硬上限为 64 MiB，旧版记录迁移需计入临时备份后的实际占用。达到上限后停止新增并提示用户先清理，不自动删除旧记录；若迁移会越界，只在当次内存中使用已压缩结果，不扩大磁盘占用。

## 后果

- 正面：低 Star、小众和跨语言 Skill 能进入真实正文核验；热门但能力不符的结果更难占据推荐；固定新增磁盘不到 1 MiB。
- 负面：一次完整搜索会增加公开网络请求和模型轮次，GitHub 匿名额度不足时可能只得到部分结果。
- 后续需要注意：每次发布前可运行目录更新脚本并检查来源变更；真实搜索质量仍要用中文、英文、窄任务和易混淆任务的回归样例持续观察，不能用测试通过冒充用户体验通过。
