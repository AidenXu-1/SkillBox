# ADR-0007：GitHub 来源与可安装 Skill 分离

- **状态**：已采纳
- **日期**：2026-08-17

## 背景

GitHub 仓库常同时保存 Skill 运行文件、README、许可证、CI、测试和发布脚本。把整个仓库当成 Skill 会制造无意义冲突和风险提示；仅按固定目录或文件名过滤，又可能删掉 `templates/` 等真实运行内容。

## 决定

1. SkillBox 把“来源快照”和“可安装内容”视为两个不同对象。中央库、内容指纹、更新差异和应用部署只使用可安装内容。
2. 解析优先级固定为：作者上传的 Release ZIP；明确 Skill 子目录；可选 `skillbox.json`；根目录混合仓库的一次性用户确认。
3. Release ZIP 仍执行全部安全与结构检查。多个 Skill 或多个 ZIP 都必须让用户选择，不因 Release 身份自动猜测。
4. 安装清单和用户确认都保存为 `GitHubPackageRecipe`。规则使用精确相对路径，并绑定仓库稳定 ID、仓库名、跟踪方式、Skill 子目录和确认版本。
5. 更新检查比较规则所选内容的稳定身份。仓库包装变化不提示 Skill 更新；已选路径消失、来源身份变化或出现可能进入 Skill 的新路径时暂停并要求重新确认。
6. 旧完整源码 Skill 通过可恢复事务迁移。不得只改中央文件而留下错误的来源记录或半更新的应用副本。

## 不选择的方案

- **全局文件名黑名单**：无法证明 README、LICENSE、自定义目录或脚本一定与运行无关。
- **根目录只保留 `SKILL.md`**：会破坏包含脚本、参考资料、资源或模板的 Skill。
- **要求所有作者发布纯净 ZIP**：作者提供 ZIP 时体验最好，但不能把第三方仓库是否规范变成用户能否使用 SkillBox 的前提。
- **用 AI 猜测运行文件**：结果不可重复、难以审计，也会增加网络、隐私和成本。

## 后果

- 边界明确的来源自动完成，普通用户无需理解仓库结构。
- 边界不明确时只确认一次，后续沿用规则；异常变化才再次打断。
- 现有 GitHub 来源需要 Schema v3 迁移。Release Asset 和明确子目录可自动补齐规则；根目录完整源码保持原样，直到用户确认纯净候选。
- 完整来源快照只作临时输入，可清理、可重新下载，不再冒充 Skill 原件。
