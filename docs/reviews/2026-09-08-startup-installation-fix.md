# 启动扫描、安装响应与整理交互

## 确认的问题

1. 产品规格要求只识别安装位置，旧 `scanInstalledSkills` 仍递归发现所有目标目录的 Skill。单项安装/卸载还会在结束前等待这一步。未知安装副本不应该成为来源候选，现已取消日常流程中的这段扫描。
2. 单项确认原先 `reload → refreshPlan` 同步比对所有已管理副本，再次扫描后才返回给确认窗。改为只核对所选 Skill 与目标，保留同一位置的所有权记录，在界面线程之外比较，并只合并当前项的计划结果。复制、备份、写入前复查、撤销机制不变。
3. 文件夹保存原先也会触发全安装计划比对；现只更新整理记录。Skill 行自定义同组排序与文件夹的系统拖放没有接通，文件夹本身也没有清晰前后落点；完整交互替换待预览确认。

## 验证

- 新增 `InstallationResponsivenessTests`：启动不发现其他应用已有副本；单项安装与卸载保持其他待处理项、文件比较不占界面线程；整理不重新生成安装计划。
- 完整脚本 524 项计入结果，523 项实际通过、1 项既有公网用例跳过。完整日志暂存 `/private/tmp/skillbox-review-BpMq7p/install-all.log`。
- Release 与严格签名、隐私检查通过。候选 `scratch/installation-fix-20260908/SkillBox.app`，程序 SHA-256 `352499505226ee9f65d5b117946d6ed3cb5f8c3ef9f3615493ebe80875f89193`。
- 独立原生 QA：临时 Claude 目录包含 10,010 个无关子目录；界面显示三份模拟主 Skill，无启动错误。实际点击 agent-team 安装与卸载，各自确认窗关闭，矩阵先变为已安装后恢复可安装。磁盘文件先存在后移除；中央内容保持、无关目录全部保留，两条事务均为 succeeded。原始状态记录、QA 入口放在同名 scratch 目录。
- 交互预览的跨文件夹移动与文件夹末尾排序经真实浏览器拖动验证。预览仅模拟数据，尚未实施原生拖动、自动滚动或行让位优化。

## 限制与后续

- 对方“一打开就弹出”的完整“找到了 Skill”错误，本次未复现。当前源码的该错误由本地来源预览/检查抛出，启动扫描只产生诊断；不能据此指认对方选错文件夹，也不能把取消启动扫描宣称为该弹窗已被完全消除。需要对方版本和可复现的启动条件。
- 手动选择过大的父目录仍受通用扫描预算约束；此次不取消本地包验证、路径和内容预算。
- 保留正式 App、正式资料和公开发行；没有调用付费模型。
