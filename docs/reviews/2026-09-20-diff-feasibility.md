# 更新文字对比实现成本实测

日期：2026-09-20。范围是可行性与成本验证，不是正式功能交付。

结论：原生样式和窗口返回成本低，正式两入口接入属于小到中等改动，不需要新增第三方依赖。没有必要因成本取消旧版删除线。

## 实测方法

隔离 Swift 原生程序共105行（包含数据、计时、断言和示例窗口）。使用标准库按行识别增删，UTF-16范围生成原生富文本；复用产品现有NSTextView的只读、选取和自动换行方式，保留完整原文与连续段落。点击父窗口右上查看更新，在SwiftUI sheet中显示两份文本，关闭后父窗口仍在。

先独立运行性能测量，再启动原生实验窗口测量一次。合成中文及emoji样例，450pt单列宽度，优化编译；统计差异计算加样式生成，以及强制完成两列全文排版。不是用户点击到显示的端到端延迟，也不是所有Mac的性能保证。

| 样例 | 差异与样式，两次实测 | 两列全文排版，两次实测 |
|---|---:|---:|
| 300行普通文档 | 2.6 / 2.2 ms | 29.0 / 27.2 ms |
| 3000行少量修改 | 4.5 / 4.5 ms | 238.4 / 227.2 ms |
| 3000行全部改写 | 253.6 / 247.4 ms | 220.3 / 210.4 ms |

## 已验证

- 真实原生窗口的删除线、浅黄文字背景、连续段落、自动换行，以及关闭后返回确认窗口。
- 完整文字保持；相同文本、重复行、中文emoji修改的差异数量断言通过；空文档场景仅验证文字保持，尚未完成生产级空行语义验收。

## 正式接入仍需做的工作

- 给已有只读文本组件增加可选样式范围。样式更新不能只看原文是否变化，还要看另一侧引起的差异范围变化。
- 我的Skills已有前后正文，接入较直接；安装确认目前只有文件摘要，要按当前目标目录与中央版本读取两份SKILL.md，并正确标注比较方向。
- 在现有确认sheet内打开独立只读详情，不调用主更新页的取消或安装逻辑，以免误清理原来的更新状态。
- 长文差异在后台计算并缓存，文档未变化不重复计算；还需检查更大或密集改写文档、长文首屏布局、缺失文件与异步关闭。3000行压力样例已说明不能把全文计算排版全部塞在点击回调中。
- 正式阶段需要两真实入口回归；本轮验证并未将实验窗口算作SkillBox集成验收，也未修改或替换当前Build22。

建议按已确认的显示范围实施：SKILL.md、按行识别变化但连续文本展示、旧文删除线、新文浅黄背景、安装确认右上入口与关闭返回。逐字最小差异和其他任意文件预览不纳入首版。
