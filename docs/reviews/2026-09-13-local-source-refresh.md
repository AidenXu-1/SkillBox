# 本地来源更新检查修复

> 后续变更：本日已升级至 Build 9，并按用户要求轮换为唯一上一版回退资料。本文原备份路径已清理，右上角刷新也已完成前台补验；当前恢复路径与结果见 [备份维护记录](2026-09-13-backup-retention.md)。以下保留当时检查事实。

## 问题与结果

用户修改本地开发 Skill 后，SkillBox 仍展示旧的一致结果；详情中的本地来源卡片只在状态异常时显示，卡片里的“检查更新”也随之隐藏。右上角刷新仅调用安装状态检查，本地来源没有自动检查入口。

本轮按用户“修复”授权恢复既有卡片，并接入本地来源检查：

- 本地来源卡片始终显示。未发现变化时保留“检查更新”；发现变化后显示“查看更新”。
- 右上角刷新检查本地来源和安装状态，悬停说明明确 GitHub 继续使用原有来源菜单。
- 启动后立即检查本地来源，之后每轮间隔 30 秒检查；文件操作或更新预览期间延后。
- 文件读取在界面线程之外完成；自动检查只保存状态，不打开更新确认、不替换安装快照或 Agent 副本。
- 旧的一致结果写成“上次检查一致”。读取失败保存原因并提供重试；旧格式本地状态继续兼容。
- 来源关联或安装基线变化后，迟到的检查结果不能覆盖新记录，也不能恢复已停止的跟踪。
