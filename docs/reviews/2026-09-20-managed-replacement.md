# 安装差异处理入口与 Finder 误报补齐

## 原因

受管副本后来变化被 planner 记为 externalModification，既没有向预览提供两个实际版本的校验值，也没有确认替换出口；未受管同名副本则已有完整替换路径。因此同一个橙色图标产生了不一致的用户行为。此前 Build 24 只解决与中央完全相同的副本记录过时，未补齐此入口。

实机进一步核对 ai-news WorkBuddy：与中央版本相比，仅普通 `.DS_Store` 字节不同，其余路径、权限与内容相同。旧记录的“真实不一致”不代表正文不同；先前报告中有关 ai-news 的判断不完整，本报告予以更正。安装状态仍采用含系统文件的严格比较，导致 Finder 操作误报。

## 变更

- 可读取的受管内容变化复用已有比较窗口：应用现有版本对比中央版本、右上角查看更新、取消和用我的版本替换。橙色图例改为内容待确认；路径不可读/不可写等实际故障仍阻断。
- 对确认的受管替换，仅在临时计划快照中使用现有替换授权路径，持久安装归属保持，由原事务执行器备份/替换/恢复。授权不会持久保存为后续自动覆盖许可；确认后内容再变则停止，中央版本变化亦要求重新确认。
- 安装副本与中央相同但只有普通 `.DS_Store` 差异时，校正实际完整部署记录，并使用排除 Finder 元数据的实质比较显示已安装。完整写入与恢复校验继续使用实际完整指纹。权限、链接和其他隐藏内容不忽略，不删除任何系统文件。
- 点击时重新核对所选位置并更新该项计划，避免沿用旧缓存状态；不读取无关副本以准备单项操作。

## 验证

- 红绿测试复现受管编辑后无法比较/替换；通过正常替换、恢复到编辑前内容、确认后再次变化不覆盖、恢复后不自动重用授权。
- Finder 元数据测试先复现 blocked，再验证已安装、系统文件保持，以及刷新后 Finder 再变化仍可正常打开卸载确认。
- 最终全量脚本退出 0：Swift 报告 632 项，631 实际通过、1 公网跳过；Python 28 项通过。中间全量中删除提示计时受并发负载失败一次，定向复核与最终全量均通过，未修改该测试。日志 scratch/managed-replace-final-tests.log、managed-replace-targeted.log。
- release/隐私/签名检查通过。本机最终 0.2.5 Build 26，程序 SHA `ef523f250383da9ff8c6a683d86ceed19bebbc09a7179de89ea0de1b6f33dd01`。本轮中间 Build 25 验证替换入口，发现系统文件原因后补齐为 Build 26；两次替换临时旧包均清理。
- 原生 Build 25 的 ai-news 确认窗口具有查看更新、取消和用我的版本替换，截图 scratch/managed-replace-20260920/confirmation.png，取消成功；没有执行真实替换。
- 原生最终 Build 26 的 ai-news WorkBuddy 显示绿色已安装，点击进入正常卸载确认并取消。截图 final-installed.png；全部 6 个文件的字节与修改时间保持，content-verification.json。每次替换期间 168 份资料文件保持。
- 没有实际替换/删除用户 Skill，未公开发布。长文本详情的原生自动化断线缺口仍见前一报告，本轮未重复触发该工具故障；不据单项确认窗口证明所有正文详情交互。
