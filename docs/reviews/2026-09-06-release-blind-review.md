# 宣发前独立复核与本机交付

日期：2026-09-06。合同：Spec v2.46。交付版本：0.2.2 / Build 5。

## 结论

此前三项风险的事实基本成立；“没有跨来源累计预算”不等于生产发生无限调用，条件问题的严重度也取决于用户要求的性质。独立审查另发现新查找分流、候选指代、来源完成状态三类遗漏。六类问题已修复，保留精确查找与原三栏。

最终完整 509 项检查通过；正式应用已可恢复替换并在真实窗口验收，DMG、校验文件和来源清单已生成，挂载 App 与正式 App 的 17 个文件完全一致。公开发布、另一台 Mac／干净账户的首次放行体验尚未执行，不能把本机通过写成所有发行门都通过。

## 盲审如何进行

第一阶段由独立 Agent 检查当前需求、源码和测试，不读取前一风险报告、进度日志或旧实验；报告冻结后才对照旧结论。初次 Spec 检索附带返回过历史版本索引，已在第一阶段报告披露，因此不声称完全未接触历史索引。每个发现均有当前代码的独立输入与复现。

第一阶段：`scratch/blind-release-review/blind-findings.md`。旧报告：`docs/reviews/2026-09-06-discovery-risk-review.md`。交付预检：`scratch/blind-release-review/distribution-preflight.md`。

| 问题 | 最终处理 |
|---|---|
| 必须免费／离线／不上传已保存却未限制推荐 | 增加独立资料检查，冲突和未证实分别说明；未知价格不能当免费；不消耗模型比较这些未达标对象 |
| GitHub 搜索与普通额度混用 | 普通、搜索、代码搜索分别计额；共同的二次限流仍共同暂停；跳转前后身份分别归属 |
| 缺少跨来源累计预算，部分媒体未计数 | 每轮直接 HTTP 含跳转最多 256 次，API 最多 12 次；媒体工具最多两次，内部 HTTP 数量明确未知；重复读取复用 |
| “找能对比 PDF 的 Skill”等新查找被截走 | 明确查找优先，不被“比较”“去掉”词语误导 |
| 序号／未知名称／同名作品引用错误 | 按序号和仓库确定对象，歧义澄清；不能默认拿前两份或当前选中对象作答 |
| 未使用 AI 被写成来源未完成 | 来源完成程度由失败、延后、截断和预算事实决定；AI 是否参与独立说明 |

修复本身也经过反例检查：纠正“不需要联网”“无需付费订阅”的否定误伤，补齐组合条件与反向条件。真实旧会话中模型曾把“AI 风格、文案写作”放入 mustHaves；最终模型不能新增硬条件或排除项，旧会话按用户原始消息核对仍存在的条件。撤回项不从历史重建；历史依据不完整时保守保留并提示。普通补充、澄清和继续深挖都使用同一边界。

真实窗口又收尾两处提示：零推荐不再显示正在查看某候选；未知对象的说明不再要求用户重复已经给出的名称。

## 宣发边界

免费来源可能超时、限流、未收录或改变页面结构；目录和有限别名不能承诺全网查全。作者资料与热度也不等于每份 Skill 的实际效果、完整安全或费用保证。资料无法证实必须条件时，当前采用保守推荐策略，可能少推荐，但不会把未知写成已满足。
