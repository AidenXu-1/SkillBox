# 备份检查改为启动与手动触发

用户认为七天备份没有必要每小时检查，要求改为打开应用时或在设置中手动检查。按 Spec v2.57 取消备份检查循环，并停用 Codex 自动化 `skillbox`。本次只调整备份维护触发，原有本地 Skill 来源更新检查保持。

## 用户入口与成本

- 每次启动 SkillBox 检查一次；“设置 → 存储与记录”顶部使用现有设置卡片样式，显示“只留上一版，保留 7 天”和“检查并清理备份”。检查中防止重复点击，结束后显示清理数量、无需清理或未完成原因。
- 新操作成功后仍立即清理被替代的旧 Skill 备份。应用更新脚本仍在新备份完整生成后清理上一套，避免数量积累。
- 七天后实际删除改为下一次启动或手动检查触发，不再定时唤醒应用或 Codex；长期不启动会延后删除。检查仅消耗本机文件读取与清理所需资源，不联网、不调用 AI。
- 应用回退资料的登记位置写入本机应用资料的 `rollback-maintenance.json`。已安装 App 用原生代码读取原有登记格式，不依赖 Python 或项目脚本执行；没有登记时跳过此项。保留原脚本作为本机更新的备份创建入口。
- 原生维护与脚本共用文件锁；只处理明确登记的目录，清理前核对标记与完整内容摘要，拒绝越界、目录连接和被改动的备份，保留简短清理记录。

- 新增四项检查：Python 登记与原生清理兼容、七天到期及重复检查、备份改动与路径连接保护、手动入口忙碌与完成反馈。含原有回退检查共 9 项定向通过。
- 最终完整 Swift 检查 549 项实际通过、1 项公网跳过；Python 6 项通过。输出 `scratch/backup-launch-targeted-tests.log` 与 `scratch/backup-launch-full-tests.log`。
- 测试初次失败来自 macOS 临时目录 `/var` 与 `/private/var` 的别名。夹具改为向 Python 传入系统真实路径后，原生摘要与 Python 登记兼容通过，没有放宽生产路径检查。
- Codex 自动化已回读为 `PAUSED`，没有新增其他计划任务。完整检查通过后再打包与本机验收。
