## 判断

SkillBox 已经具备清楚的用途和有价值的工程基础：维护一份经过确认的 Skill，再分发给多个 AI 应用，并保留失败恢复的能力。这很适合同时使用多个 AI 应用、经常维护自己 Skill 的用户。

当前可以给出“主要功能可用、值得继续维护”的评价。还不能给出“异常边界充分可靠、整体已经达到成熟高质量软件”的结论。本轮发现 2 项高优先级问题、3 项中优先级问题；其中 4 项有运行复现，第 5 项通过测试日志与补跑确认。前台覆盖和各问题的复现范围分别记录，不能相互替代。

| 角度 | 评价 | 根据 |
| --- | --- | --- |
| 产品价值 | 清楚，适合多应用 Skill 管理 | 来源、保存版本、安装副本相互区分，减少人工复制与核对 |
| 日常体验 | 基本完整，偏工具型 | 导航、安装矩阵、单项确认和取消可用；原始英文介绍、长路径和多层版本信息增加理解成本 |

## 已确认问题

### F1 高优先级：保存失败后，未保存的安装关系变化仍留在内存

位置：[LibraryStore.swift](../../app/Sources/SkillBoxCore/LibraryStore.swift)，394–411 行。`replaceTargets`、`replaceAssignments`、`replaceOrganization` 和移除自定义应用等入口也有类似的先改内存、再保存且失败不还原的结构。

具体场景：移出一个应用，选择保留文件并停止管理。程序先从内存删除安装选择与受管副本记录，再保存。若保存失败，磁盘仍保留旧记录，内存却已变成新状态。之后另一项操作保存成功，就会把前一次失败留下的状态一起写入。

隔离复现结果：

```text
保存失败后：内存 visible=false, assignments=0, installations=0
同一时刻：磁盘 visible=true, assignments=1, installations=1
另一次无关保存成功后：磁盘 visible=false, assignments=0, installations=0
```

影响：界面报告失败后，管理关系仍可能在后续保存中消失，导致现有文件后来被识别为不受管理。本实验没有导致 Skill 文件内容丢失，不能扩大为已经证明会删除用户文件。

修复方向：统一采用候选状态保存成功后才提交到内存，或在所有相关入口失败时恢复完整旧状态。回归应包含失败后立即读取、重开、重试，以及无关操作随后成功保存四种情况。

### F2 高优先级：变化预览漏掉隐藏文件与目录变化

位置：[SkillDiff.swift](../../app/Sources/SkillBoxCore/SkillDiff.swift)，37–46 行；错误结论呈现在 [ContentView.swift](../../app/Sources/SkillBoxApp/ContentView.swift)，7690 行附近。本地和 GitHub 更新都会调用该比较器。

比较器使用 `.skipsHiddenFiles`，而真实内容校验与安装复制会保留隐藏运行内容。它还跳过目录条目，因此新增空目录、目录权限变化也无法完整呈现。

隔离复现：只把 `.config/settings.json` 从 old 改为 new，内容校验码明确改变，文件变化列表却返回空数组；只新增一个空目录也得到同样结果。当前窗口会将空列表说明为“文件内容没有变化”“版本名称发生变化，但这个 Skill 目录的内容相同”。这会给出错误的更新依据。

修复方向：让预览与真实安装使用一致的内容范围；普通 Finder 元数据可按既有规则单独排除，其他隐藏内容、条目类型和权限应能解释。完整校验不同而预览为空时，应明确说明尚未列全差异。

### F3 中优先级：底层链接边界检查把绝对路径拼成了相对路径

位置：[FileOperations.swift](../../app/Sources/SkillBoxCore/FileOperations.swift)，39–42 行；[RiskAnalyzer.swift](../../app/Sources/SkillBoxCore/RiskAnalyzer.swift)，40–47 行。

这两处通过 `appendingPathComponent` 拼接链接目标。目标本身是绝对路径时，会被错误地拼到 Skill 目录后面，再据此判断是否越界。

在项目临时目录中，创建一个指向相邻外部假文件夹的绝对路径链接。风险报告给出 `isBlocked=false`，将其归为普通链接；直接调用真实中央库导入和安装引擎均成功，安装后的链接仍可读到 Skill 外部的假文件。

边界必须保留：通过当前普通本地打包流程处理同一份样例时，它在临时打包阶段被拦截。本轮没有证明当前普通添加界面能够完整绕过拦截，也没有读取私人文件或证明任意代码执行。因此将其列为底层防护缺口，不表述成已经验证的界面攻击。

修复方向：正确区分绝对与相对链接，使用真实解析后的目标核对归属，并统一风险报告与复制检查。补齐目录别名、链接链、绝对链接和相对内部链接的回归，避免依赖某一道上游流程偶然拦截。

### F4 中优先级：全局核对仍阻塞界面响应

位置：[AppModel.swift](../../app/Sources/SkillBoxApp/AppModel.swift)，469–474、3866–3872 行；[SyncEngine.swift](../../app/Sources/SkillBoxCore/SyncEngine.swift)，`DefaultSyncPlanner.makePlan`。

`AppModel` 运行在负责界面响应的执行环境上，`reload` 同步调用完整规划器。规划器逐个读取安装目录并计算内容校验码。单项安装已有后台规划实现，全局刷新仍走同步路径。本地和 GitHub 更新中的文件比较也还有同步读取。

实测使用当前实际资料的只读快照，给一个空的隔离 AppModel 注入真实规划器；在规划器内用 `MainActor.preconditionIsolated()` 确认执行位置。6 份 Skill、17 条安装选择、13 个规划结果，一次规划耗时 `0.939821125` 秒。这是当前数据的一次测量，不是多设备平均值，也不等于整次刷新耗时。

影响：这段时间内界面事件需要等待；更大的 Skill、更多副本或慢磁盘会放大等待。不能据此认定每次启动必定卡顿。

修复方向：把全局规划与文件比较移到后台，在提交结果时核对状态仍与开始时一致；同一轮中复用内容核对结果。后台本地检查目前也会重新生成临时候选包，可进一步评估没有变化时的重复扫描和复制成本。

### F5 中优先级：全量测试脚本能漏跑测试并返回成功

位置：[test-all.sh](../../app/Scripts/test-all.sh)，41–44 行。

脚本把测试标识直接作为正则过滤条件。`selectedSkillEscapesArchivePatterns(directory:)` 中的括号没有转义，导致该次执行没有匹配测试，打印 `No matching test cases were run`，整份脚本仍返回 0。

本次已手动用函数名过滤补跑。该项的 `demo[1]`、`demo*`、`demo?` 三组样例均通过。这是验证入口的遗漏，没有证据说明这三个功能场景本身失败。

修复方向：正确处理过滤表达式，并要求每个发现的测试确实执行；遇到零匹配应让整份检查失败，不能仅依赖进程退出码。

## 做得好的地方

1. **来源与使用副本分开。** 本地开发原稿只读，中央版本经过确认再冻结，安装采用实体副本；比共用可变目录更容易解释更新范围和恢复行为。
2. **恢复能力有实际设计与测试。** 写入前留记录，复制后核对，替换采用准备与交换，外部修改会阻断覆盖；缺少备份、复制中断、状态保存失败、重启恢复等已有大量针对性测试。F1 说明这套做法尚未统一覆盖全部状态入口。
3. **AI 与文件控制分开。** 核心管理不需要 AI，介绍由用户主动触发，凭据使用系统钥匙串；AI 输出不直接决定文件删除和覆盖。
4. **网络与子进程有边界。** 能看到下载、展开、文件数量、响应大小、超时和取消保护，GitHub 更新也有按仓库合并检查与条件请求。
5. **依赖克制。** 核心主要使用系统能力，唯一包依赖固定为 Sparkle 2.10.0；应用更新复用成熟框架，减少自己维护更新器的负担。

从更长期的方向看，Skill 管理器的核心价值是让用户知道“哪一份内容、来自哪里、将改哪些位置、失败如何回到之前”。继续加强来源记录、变化可见性和故障一致性，比优先增加搜索入口或 AI 介绍更有收益。风险报告只能作为线索；静态文字匹配和安全安装都不能证明某个 Skill 在实际执行时绝对安全。

## 实际体验与证据边界

- 实际查看安装矩阵、我的 Skills 与设置/关于页面。安装矩阵能区分已安装、内容差异和应用目录不可用；本轮看到 ai-news 的 GPT 副本与记录不同，此状态未被擅自替换，也没有把它认定为产品误报。
- 实际进入 agent-team 的管理安装，打开 WorkBuddy 单项安装确认，核对目标与说明，然后取消并返回管理列表。没有确认执行安装或卸载。
- 白色界面、导航层级和安装前确认较清楚。多应用矩阵需要横向浏览；详情同时显示原始英文描述、长路径、快照编号和安装状态，对普通用户仍偏复杂。属于体验判断，不作为功能失败。
- 前台连接随后中断。发现页的新一轮搜索、真实 GitHub 添加、实际更新/删除/恢复确认没有在本轮完整点击；相关自动化通过不能替代这些前台验收。
- 没有调用用户付费 AI 接口、读取密钥、安装新依赖或发布内容。
- 对核心数据、复制、风险、差异、更新与发现边界做重点审阅；没有逐行证明全部约 3.12 万行产品 Swift 代码无缺陷。
