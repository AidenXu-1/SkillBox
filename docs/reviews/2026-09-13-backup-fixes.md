## 修复对应关系

| 评审问题 | 最终处理 | 回归证据 |
| --- | --- | --- |
| 旧失败记录抢占新成功版本的回退名额 | 失败/运行中的救援资料单独保护，普通上一版独立选择 | 真实失败恢复链 A→B失败→C→D 后可撤销到 C，救援文件保留 |
| 原生/Python 摘要不一致 | 原生改为按路径组件排序，兼容既有登记 | 含 `a/`、`a.txt` 与多层前缀的兼容测试；真实旧备份两端摘要一致 |
| 最新备份损坏或丢失仍删除旧备份 | 先规划，再验证受影响组的替代者与全部待删项，最后删除 | 两端覆盖内容改动、目录缺失、标记缺失；旧完整备份均保留 |
| 时区字符串排序错误 | Python 解析并统一为 UTC 后排序；拒绝无时区输入 | `+08:00` 与 UTC 混合登记保留实际较新的一份 |
| 清理失败时首次应用识别入口遗漏 | 登记后先保存原生发现入口，再清理旧备份 | 旧备份清理失败仍有入口；入口写失败保留两套，登记失败保留旧备份 |
| 启动忙碌漏检 | 记录一次待执行请求，四类阻塞解除后事件触发补检 | 忙碌、导入、来源设置、恢复预览及再次忙碌；手动消费请求，无循环/重复 |
| 成功操作后的清理错误丢失 | 清理问题单独保存并回读，显示于设置/提示；重试成功清除 | 核心跨重启与提示保存失败测试；实际单项卸载仍成功并显示清理失败 |

没有待删除备份时，不遍历核对整套 App 备份的所有文件；需要淘汰旧资料时才核对其替代者及待删除内容。手动检查期间使用现有忙碌状态阻止重叠写入，结束前重新读取维护错误，避免成功提示覆盖新问题。错误本身不会自动触发连续重试。
