# SkillBox Spec

> 本文件是 SkillBox 当前唯一开发准绳。辅助文档与本文件冲突时，以本文件为准并同步修正。

## 状态

- 当前版本：Spec v2.5
- 当前阶段：消费级交互闭环收口
- 最近更新：2026-09-01
- 实现门槛：高风险确认、批量预览取消和操作恢复必须具有显式、可取消、可持久且不误导的状态闭环；公开发行仍需通过全量自动化、真实主流程、无隐私信息的 DMG、SHA-256、来源清单、隔离属性模拟和干净账户安装验收

## 1. 产品定义

SkillBox 是面向 AI 产品创作者的开源 macOS 应用。它用一座本地中央仓库统一管理用户拥有的 Agent Skills，并把选定版本安全分发到多个 Agent。

它首先解决六件事：

1. 看清本机到底有哪些 Skill，以及哪一份是可信原件。
2. 看清每个 Agent 实际安装、间接加载或漂移了哪些 Skill。
3. 在写入前预览全部变化，避免静默覆盖用户文件。
4. 写入后留下恢复点，让一次同步可以撤销。
5. 用普通语言帮助用户看懂 Skill、更新内容和需要留意的行为。
6. 按用户的实际需求发现候选 Skill，并在加入前完成来源、内容和权限审查。

## 2. 用户与核心场景

- 目标用户：同时使用多个 Agent 做产品、但不愿手动维护隐藏目录的 AI 产品创作者。
- 核心场景：首次盘点散落的 Skills；建立中央仓库；选择 Skill 与 Agent 的安装关系；安全同步；检查来源更新；发现外部改动并处理；按需求发现新的 Skill；在加入前看懂用途和安全边界。
- 现状问题：Skills 分散在多个产品目录，同名内容可能相同也可能分叉；普通用户难以判断原件、安装状态和一次复制会造成什么影响。
- 第一版价值：让 Skills 一眼看清，并能预览、同步、撤销。

## 3. MVP 范围

### 必须做

- 原生 macOS 应用，中文界面，Apple Silicon，最低 macOS 15。
- 引导式首次盘点，全程只读，自动发现 Agent 与标准全局 Skills 目录。
- 扫描标准 `<skill>/SKILL.md`，支持根目录下更深层但不位于另一个 Skill 内部的 Skill。
- 使用稳定内容指纹归并完全相同的副本；同名不同内容保留为独立版本并要求用户选择。
- 中央 Skill 库、内容预览、来源信息、文件树、风险报告和 Finder 定位。
- 安装矩阵，以及未安装、已同步、待更新、外部改动、冲突、间接可见六种状态。
- 内置 Codex、Claude Code、Cursor、Kimi Code、ZCode、WorkBuddy、HanaAgent、Gemini CLI、OpenCode；支持自定义全局目标目录。
- 将 `~/.agents/skills`、`~/.config/agents/skills` 等通用目录作为可导入来源展示，不把它们伪装成 Agent。
- 从现有 Agent、本地文件夹、公开 GitHub 仓库和用户明确授权的私人 GitHub 仓库导入；多 Skill 仓库先预览和选择。
- 从电脑文件夹添加时，用户可选择“一次性导入”或“持续跟踪这个开发源”。持续跟踪以用户选择的外部项目文件夹为母板，SkillBox 只读母板并按确认过的精确包含路径生成纯净发布快照；不得移动、重命名、改写母板，也不得执行其中的脚本、构建或依赖安装命令。
- 本地开发源更新由用户手动触发。检查阶段只读取并生成临时候选；确认前不得修改中央主 Skill 或应用副本。确认后可只更新中央主 Skill，也可复用同一条可恢复事务更新未被外部修改的受管理应用副本。
- GitHub 来源可跟随“最新正式 Release”或“默认分支”。Release 优先使用作者上传的 ZIP 安装包；多个 ZIP 由用户选择，没有 ZIP 时明确提示后才可回退到源码快照。SkillBox 只自动检查版本信息，下载、更新和安装始终需要用户确认。
- GitHub 仓库只是来源，不直接等于可安装 Skill。中央库与应用只保存“可安装内容”；源码快照只用于发现、比较和生成可安装内容，不得整仓静默进入应用目录。
- 公开仓库检查与私人仓库登录彼此独立。公开仓库不得因为未登录、登录过期或 API 限流而提示用户连接私人仓库；失效登录需自动退回公开读取。
- GitHub 更新预览展示新增、修改、移除的文件、风险变化及 `SKILL.md` 前后内容。更新可只替换中央原件，也可在同一次可恢复操作中更新已管理且未被外部修改的安装副本。
- 变更预览、事务式实体复制、备份、失败恢复、操作记录和撤销。
- 只更新中央原件也必须生成操作记录并可撤销；撤销 GitHub 更新时同时恢复对应的来源版本记录。
- 本地静态风险报告。导入与扫描不得执行 Skill 内任何文件。
- 可选 AI 助手，支持 Agnes、DeepSeek、Kimi、MiniMax、GLM 和用户配置的 OpenAI 兼容接口。AI 只负责解释、归纳和二次复核，不参与文件删除、安装范围选择、覆盖授权或事务执行。
- 左侧主导航提供“发现 Skills”：按用户输入搜索公开候选，结合相关性、来源、维护状态、仓库 Star、使用量和 `SKILL.md` 真实性给出可解释推荐。发现阶段不声称已完成全包安全检查；用户点击加入后才下载完整候选并进入本地安全预览。Skill 查找只在这一板块完成，不在总览重复放置输入框。
- AI 与 Skill 发现都必须由用户主动触发；核心盘点、导入、安装、更新、撤销和本地风险阻止在未配置 AI 或外部服务不可用时仍完整可用。
- 除可选的 GitHub 来源授权和用户主动配置的 AI 服务外，无 SkillBox 账号、无遥测、无云端数据库。

### 明确不做

- 项目级 Skills、信息流式 Skill 市场、排行榜运营、付费推广或个性化广告。v1.1 只提供任务驱动的搜索和可解释候选推荐。
- 跟踪任意分支、固定到某个版本、自动下载、自动更新或自动安装。
- 将 Release 中的非 ZIP 附件或来路不明的文件当作 Skill 安装包。
- 内置 Markdown 编辑器、Skill 创建器、后台自动 AI 审查或由 AI 作出“绝对安全”结论。
- 把公共 API Key、Client Secret 或 SkillBox 共享模型密钥打包进客户端。
- 在 Agnes 不可用时把内容静默转发给 DeepSeek 或其他服务商。
- 团队协作、云同步、Windows、Linux、后台自动同步和应用自动更新。
- 监听本地开发项目的每次保存、把开发项目迁入 SkillBox 保存位置、自动运行项目构建、双向同步或把应用副本改动写回开发源。
- 管理 Agent 插件、MCP、系统内置 Skill 或第三方插件缓存。

## 4. 信息架构与主流程

### 主导航

- **总览**：已加入 SkillBox、本机找到、需要选择、应用位置和最近操作。
- **我的 Skills**：集中保存的内容、来源、使用指南、快速安装操作和 Skill 详情。
- **发现 Skills**：用户用普通语言描述想完成的事情，查看所有通过质量门槛的可解释候选、用户指南、来源知名度和加入前检查，再决定是否加入中央库。候选数量由真实质量决定，不设展示目标。
- **安装到应用**：按需调整 Skill 与应用的安装关系；点击某个交叉点后就地确认该项，不再要求用户到页面另一处找批量执行入口。
- **最近操作**：每次安装的结果、备份和「恢复到操作前」状态。
- **设置**：SkillBox 保存位置、AI 模型接入、GitHub 私人仓库连接、寻找记录与清理入口。只陈列但不能操作的说明不占用设置项。

“发现 Skills”是反复发生的独立任务，作为常驻一级导航；“添加 Skill”继续处理用户已经知道本地目录或 GitHub 地址的明确来源。总览只展示资产状态和需要处理的事项，不承担 Skill 搜索入口。

发现页保留的是「寻找记录」，不是通用聊天记录：记录只包含这次要解决的问题、后续补充条件、候选元数据和用户选中状态。用户加入第一个候选后，其他候选仍保留，便于体验不合适时再试第二个。点击「开始新的寻找」只创建新任务，不自动删除之前记录；用户可从会话菜单继续任意一条，也可在设置中单条删除、全部清空或在 Finder 中打开保存位置。不提供通用问答、文件上传、办公助手或无限期个人记忆。发现页不得绕过中央仓库直接写入任何应用目录。

### 界面语言

- 主流程面向不熟悉文件系统的用户，先说“会发生什么”，技术原因放到可展开的第二层。
- 「中央仓库」对用户显示为「我的 Skills」或「SkillBox 保存位置」；「同步」优先表达为「安装」或「更新」。
- 「指纹」改为「内容校验码」并只放在「Skill 详情」中；「事务」改为「最近操作」；「接管」改为「让 SkillBox 管理这份内容」。
- 「查看 Skill 详情」作为详情页的第二层信息入口，展开后展示完整文件目录、主 `SKILL.md` 的预览按钮和内容校验码；目录读取不得阻塞主界面。
- 所有可点击控件都必须提供悬停、按下和禁用反馈；「查看 Skill 详情」的整行标题区域都可点击，不能只依赖小箭头。
- 普通成功结果只做短暂轻提示，不得常驻或遮挡输入与主操作；进行中状态放在顶部工具区，需要用户处理的问题才在相关内容附近保留。
- 发现详情与“我的 Skills”使用同一套四块用户说明，顺序固定为「Skill 简要说明（特色、技巧）→ 适用场景 → 体验流程 → 提示词参考」。内容只保留用户判断是否需要、如何开始使用时真正有帮助的信息；示例话术可一键复制，体验流程写用户能够感受到的 2 至 5 步。
- AI 优先读取真实 `SKILL.md`，并可结合 `README.md`、`agents/openai.yaml`、`references/` 与 `agents/` 内的文本说明，以及 GitHub 作者提供的仓库简介。仓库简介与 Skill 本体冲突时以 Skill 本体为准；不得把内部规则、文件结构、脚本实现、安全检查或专业黑话写进用户说明。
- 资料不完整时，AI 可以从 Skill 的真实用途、触发条件和工作步骤中归纳用户能确认的体验，不得虚构能力、效果或产品承诺。未配置 AI 或生成失败时显示基于确定性材料的简短保底说明，不展示“作者暂未说明”等无帮助占位话。
- 使用说明按需生成：候选排序只返回 ID、等级和一句理由；用户打开某个候选时才整理四块说明，并在当前寻找记录中复用。加入后只有下载包的 `SKILL.md` 与生成说明时的来源指纹一致，才按 `Skill ID + 内容指纹 + 提示词版本` 复用；Release、默认分支或后续更新导致来源变化时，必须根据已安装内容重新整理。
- 不得把 `description` 中 `Use when` 后的原始触发片段直接当成用户说明；YAML 多行描述必须转成正常可读文字，旧的中央记录在打开新版本后自动修复。
- 未启用 AI 时，SkillBox 不生成或猜测使用方法，不得把「执行步骤」「安全检查」「内部规则」等给 Agent 的指令当成用户教程。用户主动选择“AI 帮我看懂”后，AI 可基于作者材料补充归纳，但每一项结论都必须能回到真实文件证据，并明确标为 AI 辅助说明。
- 「我的 Skills」必须支持搜索，并能按有更新、已安装和需要处理筛选。列表行只用一行展示 Skill 名称、固定尾部来源图标和最右侧的中央库占用大小，不再用第二行显示来源文字。图标与大小各占固定列，不随 Skill 名称长短左右跳动。更新与问题状态通过筛选结果和右侧详情承接，不在高频列表行里叠加状态徽标。
- GitHub 来源使用可直接识别的 GitHub 章鱼猫标志，本地来源使用蓝色实心文件夹，应用导入使用实心导入图标；不用链路、网络等需要猜测的抽象符号代替来源。悬停说明与 VoiceOver 名称统一为「GitHub 来源」、「本地来源」或「应用导入」。列表大小只计算 `Library/<skill>/content` 内的中央主 Skill，不重复计算应用安装副本、GitHub 下载缓存、历史版本或备份。
- 同一文件夹内的 Skill 移动超过 `8 pt` 后才进入拖动。进入拖动后，原卡片从列表排位中变为一块等高的空占位槽，卡片本体作为独立浮层保持蓝色选中外观并只在列表纵向轨道内跟手；指针跨过相邻行中线时，占位槽移动到预计松手位置，其他卡片在约 `180 ms` 内实时让位，使列表始终预览松手后的最终顺序。有效落点时，占位槽底部显示一根 `2 pt` 系统蓝线；落点线不绑在浮动卡片上，不得被卡片阴影或让位动画遮挡，也不显示端点或文字胶囊。指针离开有效列表、取消、松手、窗口失焦、页面消失或被拖对象刷新移除时，统一拖动会话必须回到空闲状态，不留蓝线、空位、重影或浮层。精确落点文字只供 VoiceOver 使用；跨文件夹移动继续使用右键「移动到」。开启「减少动态效果」时保留占位槽和落点线，取消换位动画。
- Skill 列表行右键菜单只提供「移动到」已有文件夹和「删除 Skill…」。删除必须复用现有可恢复流程：无受管理副本时二次确认后移入 macOS 废纸篓；有受管理副本时先让用户选择保留副本或查看全部卸载清单，不得绕过取消、预览与恢复出口。
- 「我的 Skills」页头只保留一个高强调的「添加 Skill」主操作；更新检查和私人仓库连接使用统一的次级样式。全局安装卡分开说明与操作，主安装按钮在常用窗口宽度下必须单行显示。
- 私人 GitHub 的连接入口必须同时出现在「我的 Skills」、GitHub 添加页和设置页，不能要求用户先猜到设置位置。
- 私人仓库连接必须以普通用户能理解的三步流程呈现：「确认身份 → 选择仓库 → 回到 SkillBox」。用户界面不出现 `GitHub App`、Client ID、Device Flow 等开发术语，并明确说明无需下载其他软件。
- 身份确认成功后，SkillBox 必须自动打开仓库选择页并等待 GitHub 结果；用户选好仓库后直接回到 SkillBox，不应再寻找第二个功能入口。等待期间需展示进度和“重新打开 GitHub”的恢复按钮。
- 验证码页必须明确说明：该步骤只用于确认身份，不创建仓库、不修改文件；重新开始只会换取一个会过期的临时验证码。
- GitHub 连接管理必须区分三种动作：「断开连接」只删除本机钥匙串登录信息；「清除 GitHub 信息」同时移除仓库地址和更新记录，但保留 Skill 为本地副本；「在 GitHub 撤销授权」打开 GitHub 官方设置页由用户亲自完成。
- 断开私人仓库连接不得影响公开仓库检查更新；私人仓库在下次检查时提示重新连接。
- GitHub 检查结果必须区分「GitHub 暂时无法继续检查、私人仓库需要重新连接、私人仓库需要允许访问、仓库地址失效、网络暂时不可用」；只有已确认的私人仓库才能显示登录或授权操作。
- GitHub 返回查询限制后，SkillBox 必须记录是未登录还是已登录额度受限，并遵守对应的可重试时间。用户刚成功连接 GitHub 时，应立即解除明确的未登录额度暂停；应用平常启动时不得反复解除等待，只可迁移“仓库已确认公开且旧记录没有额度类型”的历史数据。私人仓库、公开性未知和真正的已登录额度暂停仍必须继续遵守。版本状态与本次连接问题分开保存，临时故障不得抹掉已经确认的版本结论。
- GitHub 下载、解压和检查期间必须显示可见进度并允许取消；仓库没有正式 Release 时提供一键改用默认分支。
- Release 只有一个合法 ZIP 时直接下载；存在多个 ZIP 时弹出单任务选择窗，不得自动猜测。Release 没有 ZIP 时，必须明确告知将导入测试、CI 和开发文件，用户确认后才能下载源码快照。
- 所有 GitHub 下载入口，包括 Release ZIP，都必须经过相同的安全解包、大小、文件数量、路径穿越、软链接、特殊文件和 `SKILL.md` 校验。Release 身份只表示作者提供，不代表可以跳过检查。
- 源码快照中的可安装内容按固定优先级解析：作者 Release ZIP；用户明确选择的 Skill 子目录；可选的 `skillbox.json` 安装清单；根目录混合仓库的一次性内容确认。不得用全局文件名黑名单静默删除文件。
- `skillbox.json` 只允许声明相对于 Skill 根目录的精确文件或目录，必须包含 `SKILL.md`，禁止绝对路径、`..`、越界软链接和重复覆盖。未声明的仓库内容不进入中央 Skill。
- 根目录同时包含 Skill 与仓库包装时，SkillBox 展示“将安装的内容”和“仅保留在来源仓库的内容”。用户只需确认一次；确认结果保存为该来源的安装规则，后续版本沿用。已选路径消失、来源身份改变或出现可能属于 Skill 的新路径时暂停并重新确认；README、CI 等已识别仓库说明和自动化文件的变化不得反复打扰用户。
- 功能完整性优先于“看起来更干净”。没有作者纯净 ZIP、明确 Skill 子目录或 `skillbox.json` 时，所有用途不明的顶层内容默认保留；普通用户只确认结果，不负责勾选技术文件。`SKILL.md` 明确提到的本地文件或目录必须锁定保留，即使名称看起来像 README、CI 或其他仓库资料。旧版本按较宽松规则生成的安装清单必须从同一 GitHub 版本重新核对，不得用已经缺文件的中央副本继续整理。
- 多个独立 `SKILL.md` 必须作为多个候选展示并由用户选择；不得擅自把一个 Skill 依赖的仓库外文件拼入包内。
- 如果 GitHub Release、Commit 和 Skill 目录内容均未变化，只是旧数据记录格式不同，不得显示更新；如果同一个 Release 后来可使用作者上传的纯净 ZIP，界面必须说明这是“更干净的安装包”，不得称为“新版本”。
- Agent 作为品牌名的一部分时保留；概括称呼统一使用「AI 应用」或「应用」。
- 错误和风险提示先告诉用户结果与下一步，不直接展示 schema、HTTP、POSIX、软链接等内部术语；必要证据仍可在详情中查看。
- 安全提示必须先说明“添加与安装时不会运行文件”，再解释什么情况下才可能执行；用“仅说明、需要了解、需要确认、无法添加”代替笼统的技术风险标签。
- Skill 列表的左侧图标用于识别 Skill 本身，不得用普通扫描结果冒充状态。信息类和留意类发现保留在本地安全引擎中，不在 Skill 详情中生成常驻「文件检查」卡片。只有高风险或已阻止内容才显示「安装前需要确认」，并在导入或安装的相关决策点提供证据。
- “安装到应用”的安装矩阵固定紧跟页头与图例，默认从左上角展示；宽度不足时可水平滚动，任何应用列不得被永久裁切。未管理的同名目录必须在用户点击前显示独立状态，不得先显示普通加号。
- “添加 Skill”菜单只处理“从电脑添加、从 GitHub 添加”；不知道具体来源时，用户从一级导航“发现 Skills”进入。发现页只服务于寻找和选择 Skill，不扩展成通用办公助手。
- “发现 Skills”左栏只保存用户真实发送的内容与 AI 真正生成的最终回复。正在理解、召回、核验和整理属于临时运行状态，以转圈或省略号展示，不写入聊天记录；AI 或外部来源失败使用独立系统提示，不冒充 AI 回复。旧版寻找记录迁移时保留用户原话，不伪造历史 AI 回复。
- 每轮搜索必须保留用户当前需求的原始查询，AI 最多补充 3 条中文、英文或同义表达。诸如“质量不高”只更新筛选偏好，不得成为搜索词；用户明显切换场景时用新目标替换旧目标，不得机械拼接全部历史消息。
- 发现编排同时使用 skills.sh、GitHub 中的真实 `SKILL.md` 搜索和版本化可信来源目录。查询按“仓库 + Skill 路径”去重，分批补齐 Skill 内容、来源和维护证据；批次只控制网络并发与模型上下文，不得丢弃后续候选。完整一轮没有新增通过质量门槛的候选时，结果才视为趋于稳定。
- 主候选区只显示通过精品门槛的“推荐”。推荐必须能读取真实 `SKILL.md`、用途高度符合当前目标、来源可追溯，并具备可信发布者或足够强的公开质量证据。发现结果只能说明公开证据状态；完整包的内容、权限与安全阻止必须在加入预览中重新核对。弱候选只保留在内部搜索证据中，不得作为推荐展示给用户。
- GitHub Star 是公开质量证据中的高优先级信号，排序时先比较 Star，再结合安装量、作者、Release、测试和更新时间。热度不能弥补用途不匹配；低 Star 的新 Skill 只有来自可信来源且内容质量、匹配程度都足够强时才可进入推荐。
- 推荐数量不设固定上下限。所有真正通过精品门槛的候选都显示，可能为零个、一个或多个；没有精品时明确说明，不用水货补数量。来源限流或尚未查完时保留已核验结果并提供“继续深挖”。
- 发现页大窗口采用对话、候选、详情三栏。对话栏约 380 点且始终保留；中栏标题固定，右栏标题固定为“Skill 详情”。中等窗口选择候选后在同一内容区进入详情，不得通过裁掉聊天栏或输入控件适配宽度。
- 输入区分为可增长至三行的完整输入框与底部操作行；模型选择和发送按钮不得与输入文字挤在同一窄行。候选行不堆叠指标，安装量、仓库 Star 与仓库更新时间紧凑放在右侧名称下方。
- 发现页三列标题使用相同高度和同一条水平分隔线；左栏“新建寻找”使用位于记录图标左侧的加号，候选标题下不显示重复说明。Skill 详情正文与“我的 Skills”统一使用四块用户说明；仓库介绍与技术证据默认折叠。
- 推荐结果只使用“高度符合、来源可靠、较多人使用、最近仍在维护、需要了解、需要确认”等具体标签。安装量、仓库 Star、作者身份和 AI 判断都只是独立证据，不得合成为制造精确幻觉的单一百分制评分。
- GitHub Star 必须显示为“所在仓库 · 12.4k Stars”或“12.4k 仓库关注”，并附数据更新时间。一个仓库包含多个 Skill 时，各 Skill 可以共享仓库知名度事实，但不得描述为该 Skill 独占的 Star；非 GitHub 来源不显示 Star。
- 候选详情先回答“能帮什么、为什么适合你、来源如何、安装前需要了解什么”；点击“加入我的 Skills”后必须进入现有下载、完整性、安全解包和中央入库流程。
- 安全结论统一为“未发现明显问题、需要了解、需要确认、无法添加”。不得显示“绝对安全”；每条需要了解或确认的结论都必须展示文件、位置、命中内容和普通语言解释。
- AI 设置使用“AI 助手”名称，默认关闭。界面提供服务商、模型、API Key、连接测试、删除密钥和私人 Skill 发送开关；API Key 输入完成后只保存到 macOS 钥匙串。连接测试只验证当时的“服务商 + 基础地址 + 模型”，任一项变化后必须重新测试，旧密钥不得发送到未经验证的新地址或模型。
- 公开 GitHub Skill 可在用户主动寻找或打开当前版本详情时使用已配置 AI 整理说明。私人和本地 Skill 默认不发送；设置中的独立开关必须明确列出只会发送 `SKILL.md`、`README.md`、`agents/` 与 `references/` 内必要文本。确认必须绑定当时的“服务商 + 基础地址 + 模型”，任一项变化后自动失效并要求重新确认。
- 一个服务商失败后只显示“改用其他服务重试”的明确操作，不得自动更换数据接收方。所有请求都可取消，取消必须穿透 AI、多来源协调器和备用端点，不得被转成普通网络失败后继续请求。失败不得改变 Skill 的本地风险或安装状态。

### 首次盘点

1. 解释只读扫描、中央仓库和不会静默覆盖的承诺。
2. 自动识别内置 Agent、通用目录及其中的 Skills。
3. 校验结构、计算指纹、生成风险报告。
4. 完全相同的副本自动归并；同名不同内容并排展示为冲突版本。
5. 用户选择要纳入中央仓库的版本和初始安装关系。
6. 只把选择结果复制到中央仓库，原 Agent 目录保持不动。
7. 首次同步另行预览和确认；盘点完成不等于已经接管原目录。

### 日常同步

1. 用户点击安装矩阵中的一个 Skill 与应用交叉点。
2. `SyncPlanner` 只读比较中央指纹、目标内容和所有权记录；在用户确认前，不得持久化安装选择。
3. 当前交叉点直接弹出单项确认窗。若已有同名 Skill，必须明确告知「内容相同」或「内容不同」；不同时展示新增、修改和移除的文件摘要。
4. 用户确认后只持久化并执行当前这一项，不夹带页面中的其他待处理项；写入前创建备份，完成后生成操作记录。
5. 批量全部安装与卸载使用独立总清单预览。预览期间的安装选择、接管和替换授权只存在于当前内存草稿；点击「取消，不保存」必须还原到打开预览前的持久化状态，不写入任何应用文件夹。
6. 用户确认批量预览后才持久化草稿，并基于最新磁盘状态重新计划再执行。预览后目标内容变化时，旧授权不得继续覆盖新内容。
7. 失败时恢复本次操作已改动的目标；成功后允许从操作记录撤销。「恢复到操作前」先展示受影响位置和每项回退结果；打开或取消预览不改文件，只有再次显式确认才执行恢复。

- 内置应用的标准 Skills 目录不存在时，视为本机尚未安装或尚未正确初始化该应用；SkillBox 必须提示用户并阻止部署，扫描、预览和执行阶段都不得代为创建目录。
- 自定义安装位置只能由用户通过目录选择器选择一个已经存在的目录，SkillBox 不代为创建。
- Kimi Code 会读取多个品牌目录和通用目录；SkillBox 必须把由其他目录带来的可见性标为“间接可见”，不声称用户可以仅靠取消 Kimi 勾选来关闭它。
- 自定义目标由目录选择器添加，必须有明确显示名称。磁盘根目录、用户主目录、应用中央仓库根目录等宽泛或递归危险路径不得作为目标。
- 自定义目标支持改名、更换目录和移除。仍有受管理副本时不得更换目录或移除，避免遗留无法追踪的安装。

## 6. 数据与文件合同

中央数据根目录：`~/Library/Application Support/SkillBox/`

```text
SkillBox/
├── catalog.json
├── targets.json
├── assignments.json
├── installations.json
├── organization.json
├── source-state.json
├── library-state.json             # 上述核心状态的完整原子提交点
├── ai-settings.json              # 不含 API Key
├── AIReviews/<skill-id>/<fingerprint>/...
├── DiscoveryCache/               # 可清理的公开搜索缓存
├── Library/<skill-name>/content/...
├── SourceCache/                  # 只用于临时下载与比较，可随时重建
└── Transactions/<transaction-id>/
    ├── manifest.json
    └── backups/...
```

- JSON 顶层必须包含 `schemaVersion: 4`，使用临时文件加原子替换写入。`library-state.json` 是核心状态的唯一权威提交点；分项 JSON 作为可读兼容镜像先写，完整状态最后原子提交，启动时优先读取完整状态，避免进程中断后拼接出不同代际的数据。旧版只有分项 JSON 时必须无损加载并生成完整状态。Schema v1/v2/v3 数据在内存中迁移后原子写回，不得当作损坏数据丢弃。
- `SkillRecord`：稳定 UUID、规范名、显示名、描述、指纹、来源、风险摘要、中央内容路径。
- `AgentTarget`：稳定 ID、适配器 ID、自定义显示名、路径、检测状态和写入状态。
- `Assignment`：Skill 版本、目标、安装目录名和期望状态。
- `ManagedInstallation`：目标路径、Skill ID、上次部署指纹、事务 ID 和时间。
- `SyncTransaction`：预览操作、备份位置、执行结果、错误和撤销状态。
- `GitHubSourceState`：仓库稳定 ID、公开或私人属性、Skill 子目录、跟踪方式、当前版本、Commit SHA、可安装内容身份、Release ID、Asset ID、Asset 名称与 SHA-256 摘要、安装规则、GitHub 条件请求标记、上次检查时间、本次连接问题、可重试时间、忽略版本和检查开关。任何凭据都不得进入该数据。
- `GitHubPackageRecipe`：绑定仓库稳定 ID、规范仓库名、跟踪方式、Skill 子目录、规则来源、精确包含路径、已经确认过的顶层路径和确认时的版本。规则只描述“哪些内容可以安装”，不得保存凭据或临时下载路径。
- `LocalSourceState`：Skill ID、用户选择的项目根位置与持久访问书签、Skill 相对位置、当前纯净内容指纹、可用更新指纹、最近核对时间、来源状态、顶层内容身份和本地安装规则。来源路径与书签只保存在本机，不进入日志、AI 请求或操作说明。
- `LocalPackageRecipe`：Skill 相对于项目根的位置、精确包含路径、已经确认过的顶层路径和规则版本。`SKILL.md` 以及被其明确引用的本地内容必须包含；新增可能参与运行的路径、已选路径消失或引用关系变化时暂停更新并要求重新确认。
- `AIProviderConfiguration`：服务商、显示名称、基础地址、模型名称、启用状态、能力探测结果、超时和输入上限。只保存钥匙串引用，不保存 API Key。
- `AIReviewRecord`：Skill ID、内容指纹、任务类型、提示词版本、服务商、模型、时间、结构化结论、证据和局限。不得保存模型思维过程或未脱敏的原始请求。
- `SkillUsageGuideRecord`：Skill ID、内容指纹、提示词版本、生成时间和四块用户说明。发现候选加入中央库时沿用同一内容；只有内容指纹或提示词版本变化时才重新生成。
- `DiscoveryMessage`：只保存真实用户或 AI 消息、正文、时间和模型；不保存临时进度、系统故障、模型思维过程或完整原始响应。
- `DiscoveryRunState`：本轮的理解、召回、核验、评估、完成、部分完成或失败状态；应用启动时只有明确发现上一个进程留下的运行态记录才标记为意外中止。
- `AIInvocationDiagnostic`：只保存服务商、模型、HTTP 状态、结束原因、响应长度、服务端请求 ID、请求字节数、服务商返回的输入/输出 Token 数、耗时、尝试次数、输入项数和脱敏错误类别；不得保存 API Key、用户正文、思考过程或完整原始回答。
- `DiscoveryIntent`：当前目标、必要条件、偏好和排除项。筛选反馈更新当前意图，新场景替换当前目标。
- `DiscoverySearchRun`：本轮原始查询、AI 补充查询、多源完成状态、召回与送评候选数、候选快照、推荐分层、运行状态、系统提示和脱敏诊断。
- `DiscoveryCandidateEvidence`：Skill 级说明、公开安装量、仓库资料、真实文件来源、核对时间和证据状态。仓库简介必须单独保存。
- `SkillDiscoveryCandidate`：公开来源、Skill 标识、面向用户的用途、安装量、仓库级 Star、Star 获取时间、维护资料、内容身份、推荐层级、限制和安全摘要。搜索缓存可随时删除，不参与中央 Skill 状态。
- `Library/<skill-name>/content` 永远是可直接部署的纯净副本，不保存 GitHub 仓库包装。完整源码只允许存在于可清理的临时缓存或事务证据中，不参与 Skill 指纹和部署。
- 本地开发项目同样属于来源，不等于中央主 Skill。`Library/<skill-name>/content` 只保存规则选中的可使用内容；测试、设计稿、笔记和其他未选内容留在开发项目中，其变化不得制造 Skill 更新。停止跟踪或来源丢失时，中央主 Skill 与现有应用副本继续保留。
- 中央 Skill 文件夹优先使用可读的规范名称，例如 `Library/vibe-project-foundation/content`；同名不同版本使用 `名称--短编号` 避免冲突。旧 UUID 文件夹在保留内容、历史版本和记录对应关系的前提下自动迁移。
- 同名不同内容允许作为多个 `SkillRecord` 存在；同一目标同一安装目录名只能选择一个版本。
- “我的 Skills”中的单个 Skill 支持“安装到全部可用应用”和“从所有应用卸载”；两者都先生成安装预览，再由用户确认执行。
- 删除中央 Skill 前必须确认；仍存在由 SkillBox 管理的安装副本时，用户可选择「只清理 SkillBox 主 Skill」或「全部卸载并清理」。前者保留各应用目录中的现有副本并解除 SkillBox 管理关系，不读取、改写或删除这些副本；后者必须先展示全局卸载预览，只有已确认的卸载事务完成后才能删除中央 Skill。
- 上述两种清理只作用于当前 `SkillRecord` 及其受管理副本；其他同名记录、其他来源副本和未受 SkillBox 管理的文件不得被连带处理。仍存在且由当前记录独占的中央内容移入 macOS 系统废纸篓，SkillBox 不在自身数据目录继续保留第二份长期删除备份；旧版 `Deleted/` 中已存在的内容在升级后迁入系统废纸篓。移动前必须先持久化删除事务、原元数据和内容指纹；事务期间可保留一份只用于崩溃恢复的临时副本，提交成功后立即删除。
- 删除完成后在界面中提供即时「撤销」；恢复时从系统返回的实际废纸篓位置取回内容，并同时还原分类、GitHub 来源状态和仍安全适用的待安装选择。撤销恢复也必须在移动内容前持久化运行中事务；若应用在移动后、状态提交前退出，下次启动应把内容安全退回废纸篓并记录回滚结果。用户已经清空废纸篓时必须明确失败。若中央内容早已缺失或路径与另一条记录共享，只清理失效元数据，不创建空备份、不提供虚假的内容撤销。若「只清理主 Skill」时保留的应用副本内容指纹未变化，撤销可重新接管其原管理关系；若副本已变化，只恢复中央 Skill，不覆盖应用中的现有内容。
- Skill 分类与顺序使用独立的 `organization.json` 保存，不改名、不移动中央原件目录，也不改变安装关系。
- 用户可以新建、重命名、删除分类文件夹，将 Skill 拖入文件夹或拖回“未分类”，并自由调整文件夹和同组 Skill 的显示顺序。已保存的空分类仍须在列表中显示数量 `0`，保留重命名和删除入口；搜索或筛选只过滤 Skill 行，不得让分类变成只能在右键“移动到”菜单中看到的隐藏记录。
- 删除分类文件夹只取消其中 Skills 的分类并移回“未分类”，不得删除 Skill 原件或 Agent 安装副本。

## 7. 指纹、所有权与写入安全

- SHA-256 指纹覆盖规范化相对路径、文件内容、POSIX 权限和软链接目标；遍历顺序固定。
- 扫描遇到有效 Skill 根后不再把其内部 `SKILL.md` 当成独立 Skill。
- 盘点只读；导入复制进中央仓库；同步采用实体复制，不使用软链接。
- 写入前把目标当前内容复制到事务备份，在目标同级暂存目录完成复制和指纹复核。替换现有目录时使用同卷原子交换，交换后核对被换出的真实旧内容仍等于用户确认的指纹；不一致时立即交换回去并停止。移除时先把目录原子移到唯一保留位置，核对后再删除。自动恢复或回滚前必须再次确认现状仍等于事务记录的操作前或操作后指纹；出现更新的外部改动时停止，绝不覆盖。
- 已存在、未被 SkillBox 管理且内容不同的同名目录必须阻塞。用户只能显式选择导入、保留或替换。
- 未被 SkillBox 管理的同名目录必须返回中央与目标两份真实指纹，不得用空值推断内容相同。指纹相同时可由用户确认让 SkillBox 管理；指纹不同时，替换授权必须绑定到用户预览的目标指纹。
- 只有带所有权记录且当前指纹仍等于上次部署指纹的目标，才能自动更新或移除。
- 目标被外部修改后标为“外部改动”，同步与撤销都不得静默覆盖。
- 只有检测状态为“已找到”且现有目录可写的应用才能接收新部署；历史选择和过期预览不得绕过这条限制。
- 备份保留至少 30 天且至少保留最近 10 个事务；自动清理不得删除仍可撤销的最新事务。

## 8. 本地风险报告

- 校验 `SKILL.md`、Frontmatter 和完整文件清单。
- 检查可执行权限、脚本、二进制、超大文件、软链接、路径越界、网络下载、提权、删除、凭据访问和动态执行模式。
- Markdown 中的命令说明与可执行脚本中的真实行为分开呈现。
- 风险分级的完整结果始终保留在本地；普通信息和留意项不打断主流程，只有 `high` / `blocked` 级别进入面向用户的安装前确认。
- `high` 级提示必须有可直接作出选择的「查看并确认」入口；用户暂不安装时不保存确认。确认只保存本地摘要，并同时绑定 `SkillRecord` ID、当前内容指纹和稳定风险证据；应用重启后仍有效，内容或风险证据变化后自动失效并重新询问。
- 确认完成后，列表的待处理标记与详情的大幅警示必须同步收起，转为可重新查看的紧凑「你已了解这项内容」状态。`blocked` 级不允许通过确认解锁。
- 删除命令必须按作用范围分级：删除临时目录或变量指向位置默认显示为“请留意”，并展示命中的命令；直接指向根目录、用户目录等宽泛位置才显示高风险。普通提示不得使用红色警报图标。
- 越界软链接、路径穿越和超过导入上限直接阻止导入；其他高风险项需要二次确认。
- GitHub 下载上限：10 MiB 压缩数据、25 MiB 解压内容、1000 个文件。
- 下载上限必须在网络流读取期间生效，不得等整个文件进入内存后才判断。
- Release ZIP 旁边存在同名 `.sha256` 时必须自动校验；校验错误直接阻止导入。更新记录同时绑定 Release ID、Asset ID 和已验证的 SHA-256。
- `.github/workflows/*.yml` 和 `.yaml` 中仅用于 GitHub Actions 任务的 `${{ github.token }}` 或 `${{ secrets.GITHUB_TOKEN }}` 显示为“仅说明”，并明确该文件不会在本机安装时自动运行。本地脚本读取令牌、访问凭据目录、输出令牌或发送到外部网址仍保持高风险。
- 安全审查分为来源、内容、权限和上下文四层。来源检查作者、仓库、版本和维护状态；内容检查全部安装文件；权限归纳文件、命令、网络和凭据范围；AI 只对本地证据做上下文复核。
- 本地扫描必须覆盖未知网址、外部发送、凭据目录、浏览器数据、动态执行、混淆或编码载荷、提权、系统目录修改、未声明依赖和宽泛文件操作。关键词本身不能直接等于恶意，必须结合文件类型、调用链、目标范围和数据流分级。
- Skill 文本属于不可信输入。AI 请求不得启用工具调用、外部网址访问或代码执行；Skill 中要求忽略系统规则、隐瞒风险或伪造结论的文字一律作为待分析资料，不得成为控制指令。
- AI 结论中的文件路径和行号必须在本地重新验证。引用不存在、输出结构损坏、内容被截断或无法核对时丢弃该条结论；不得用无法验证的 AI 文案阻止或放行安装。
- 报告必须明确：静态检查只能提供证据和提示，不能保证 Skill 绝对安全。

## 9. 技术路线与公开接口

- Swift 6、SwiftUI、macOS 15+、arm64。
- 核心行为放入纯 Swift 模块并通过协议隔离：`AgentAdapter`、`SkillScanner`、`SourceProvider`、`RiskAnalyzer`、`SyncPlanner`、`SyncExecutor`、`SkillDiscoveryProvider`、`AIProvider`。
- `AIProvider` 的发现接口分为 `planDiscovery` 与 `evaluateCandidates`。第一阶段只形成当前目标、条件、排除项、最多 3 条补充查询和一个可选追问，整阶段输出上限 600 Token。第二阶段只对质量前沿的前 8 个真实候选做一次列表式相关性判断，整轮候选证据不超过 8000 字符，整阶段输出上限 1500 Token；使用指南的输入上限为 12000 字符，整阶段输出上限为 1200 Token。自动重试与首次请求共享同一阶段预算，不得各自重新领取一份。未进入该预算、或模型漏评的已核验候选继续走质量前沿回退，不得因 AI 预算被丢弃；AI 明确判为 `other` 的已评估候选不得通过热度规则重新进入推荐。重复候选 ID、任何未知 ID、非法 tier 或其他无法核验的响应必须整体丢弃并回退，不得进入应用排序或用户对话。服务商能力必须显式记录；DeepSeek 的结构化任务使用 JSON 模式并关闭思考输出。
- `DiscoverySearchCoordinator` 负责 skills.sh、GitHub Skill 搜索和可信来源目录的查询扩展、分页、去重、证据补全、缓存与结果稳定判断。`SkillDiscoveryProvider` 只负责单一来源；任一来源失败不得清空已核验结果。
- UI 不直接读写 Agent 目录，只消费核心模块的只读模型和显式命令。
- 本地开发源解析、纯净物化和更新判断位于核心模块；SwiftUI 只负责选择目录、确认规则、展示状态和提交显式更新命令。一个项目可以包含多个 Skill，每个 Skill 独立保存相对位置与内容规则。
- 不启用 App Store Sandbox；启用 Hardened Runtime。应用只访问内置路径、用户选择路径和自己的 Application Support 数据。
- 用户选择的本地开发源保存安全作用域书签并保留可读路径作为恢复线索；书签失效或文件夹移动时进入“找不到开发源”，只允许用户重新关联，不得把中央副本反向当成母板。
- 外部网络用于 GitHub 登录授权、用户主动导入或更新检查、用户主动发起的 Skill 搜索和 AI 辅助请求。启动时若距上次检查超过 24 小时，可在应用打开期间匿名顺序检查公开 GitHub 版本元数据；启动流程不得读取 GitHub 或 AI 的钥匙串秘密，私人来源只在用户主动操作后使用凭据。Skill 搜索和 AI 不得随启动自动发起，不设后台常驻任务。
- GitHub 更新检查必须按「仓库 + 跟踪方式」归并为单队列。同一仓库的多个 Skill 共用仓库信息、Release 或分支检查结果，不得逐 Skill 重复查询相同端点。
- Release 来源平时只检查 Latest Release 及其 Assets；存在独立 ZIP 时不再为每次检查追加 Commit 和 Tree 请求。只有完整源码回退或默认分支真的发生变化时，才继续解析具体 Skill 目录。
- 根目录混合仓库按安装规则所选文件集合的稳定身份检查更新。Commit、README、CI 或发布说明变化但可安装内容未变时，状态保持“已是最新”。
- 旧版本曾把完整源码保存为中央 Skill 时，不得后台静默删文件。应用先生成纯净候选，经过一次确认后在影子目录校验并以事务原子替换；中央记录、GitHub 来源状态和由 SkillBox 管理的应用副本必须共同成功或共同恢复。
- GitHub 检查必须保存 `ETag`，优先使用条件请求。返回未变化时保留已知版本结论，只刷新检查时间，不重新下载或重算内容。
- 「连接 GitHub」是可选的统一入口：已连接时，公开仓库版本元数据优先使用用户的 GitHub 登录额度；授权失效或某个公开仓库不在应用可访问范围时，同一次检查自动退回匿名读取。未连接时公开仓库仍可匿名检查；私人仓库始终只访问用户明确授权的范围。公开仓库的认证失败不得提示用户连接私人仓库。
- v1.1 不建设 SkillBox 服务端、公共版本索引、Webhook 或 GraphQL 批量层。更新检查、发现编排、内容脱敏和结果验证保持本机完成，不引入 SkillBox 账号或新的运维依赖。
- 私人仓库使用 GitHub App Device Flow，只申请 `Contents: read` 与必要的 Metadata 读取权限。Access Token 和 Refresh Token 只保存在 macOS 钥匙串，且使用“仅本机、设备解锁时可访问”的可用性，不写入 JSON、日志或诊断信息；客户端不包含 Client Secret 或 GitHub App 私钥。
- AI 设置支持 Agnes、DeepSeek、Kimi、MiniMax、GLM 和自定义 OpenAI 兼容接口。内置服务预填官方兼容地址和推荐模型；自定义接口由用户填写 HTTPS 地址和模型 ID。模型 ID 不写入核心业务判断，用户可在设置中调整。
- 六类服务在设置页独立管理连接状态和 API Key。用户点击服务后在同一页面填写密钥、选择模型并“保存并测试”；只有完成最小结构化输出测试的服务才能标记为已连接和设为默认。所有 API Key 只进入 macOS 钥匙串，删除一家服务的密钥不得影响其他服务。
- API Key 由用户自行提供并存入 macOS 钥匙串，且使用“仅本机、设备解锁时可访问”的可用性。SkillBox 客户端不包含共享密钥；删除连接时同时删除对应钥匙串项目。
- 应用自动启动、状态恢复和后台检查只能读取不含秘密的连接提示，不得触发 macOS 登录密码或钥匙串授权窗口。用户明确执行“连接 GitHub”或“保存并测试 API Key”时，才可为当前应用身份重新绑定旧凭据；同一应用版本完成一次授权后，后续启动不得重复询问。ad-hoc 签名升级会改变应用身份，因此新版本最多允许在下一次显式连接或保存时重新确认一次；若未来改用稳定 Developer ID 签名，可进一步减少应用更新后的重新确认。
- 发现目录、GitHub 元数据、Skill 内容与 OAuth 响应都必须边读取边计数并设置硬上限；远端声明长度或实际读取超过上限时立即终止，不得先把无限响应完整载入内存。
- AI 请求只包含相对路径、必要文本、确定性检查结果和当前任务所需差异。发送前在本地剔除 `.env`、私钥、Token、证书、本机绝对路径、用户名、二进制和无关文件。
- 默认输入优先级为 `SKILL.md`、`agents/openai.yaml`、作者明确的使用章节、被入口文件引用的文本、确定性风险附近的代码片段和更新差异。超过上限时按文件分段，不静默截断关键证据。
- AI 输出使用版本化 JSON 合同；缓存键至少包含 Skill 指纹、任务类型、提示词版本、服务商和模型。Skill 内容变化后旧结果只可作为历史记录，不得继续显示为当前结论。
- 发现服务使用可替换的 `SkillDiscoveryProvider`，并由 `DiscoverySearchCoordinator` 合并 skills.sh、GitHub 中的真实 `SKILL.md` 与版本化可信来源目录。任一来源不可用时只影响本轮完成度，不影响已加入 Skill。
- 搜索请求只发送用户输入的需求文字，不发送本地 Skill 库。AI 可补充查询并比较已经读取真实证据的小批候选，但不得虚构候选、文件或能力。候选召回和确定性核验分批执行且不设产品展示总数截断；AI 证据预算只限制当轮模型上下文。
- 寻找记录单独保存在 `~/Library/Application Support/SkillBox/SearchSessions/`，每条记录使用可读文件夹名和版本化 `session.json`。列表优先显示本地快照；只有用户主动继续或刷新时才请求外部服务。删除寻找记录不得删除已加入的 Skill。
- AI 能力在服务层统一编排，在界面层按任务出现：发现页负责需求理解与候选解释，Skill 详情负责用户说明，加入或更新决策点负责安全和变化解释。v1.1 不提供全局聊天历史、通用问答、Agent 工具调用或跨任务的个人长期记忆。
- 同一内容身份的候选复用安全结果；外部安全审计只能作为补充证据，任何来源的“已审计”标记都不能跳过 SkillBox 本地检查。
- 若未来提供免配置模型额度，必须另行设计服务端鉴权、防滥用、成本、数据保留和隐私合同，不得用客户端内置共享密钥代替。
- 开源采用 MIT License。当前公开发行从项目官方 GitHub 仓库提供 ad-hoc Hardened Runtime DMG，不使用 Developer ID，不提交 Apple 公证。DMG 同时发布 SHA-256 与来源清单；首次打开或每次更新后，用户可能需要在“系统设置 → 隐私与安全”中点击“仍要打开”并输入 Mac 登录密码。相机、麦克风、文件夹等隐私授权仍按 macOS 独立流程处理。
- 无证书发行无法让 macOS 验证开发者身份，也无法抵御官方 GitHub 仓库或发布账号被攻破后产生的恶意替包。该风险由用户明确接受；工程侧必须用开源代码、固定来源快照、产物哈希、最小包内容、隐私扫描和可复现发布证据降低风险。Developer ID 与 Apple 公证仅作为未来可选加固，不再是当前上线强制条件。

## 10. 验收标准

- [ ] 首次扫描不会创建、修改、删除或重命名任何现有 Agent 文件。
- [ ] 相同副本被正确归并，同名不同内容不会自动选边或覆盖。
- [ ] 九个内置 Agent 与自定义目录均能显示真实检测、写入和安装状态。
- [ ] 安装矩阵预览与实际写入一致，阻塞项不会被执行。
- [ ] 批量安装或卸载预览前后持久化安装选择一致；取消后不留草稿、接管或替换授权，也不修改应用文件夹。
- [ ] 高风险确认在应用重启后保留；Skill 内容或风险证据变化后重新提示，已阻止内容仍无法安装。
- [ ] 打开或取消「恢复到操作前」预览不改文件；确认后才恢复，且操作后的外部改动不被覆盖。
- [ ] 清理仍有受管理副本的中央 Skill 时可选择保留副本或全部卸载；保留路径不改应用文件，卸载路径在用户确认事务预览前不删除中央 Skill，其他同名记录不受影响。
- [ ] 正常中央内容进入 macOS 系统废纸篓并可在清空前即时撤销；SkillBox 自身不保留第二份删除备份，旧版 `Deleted/` 内容会迁入废纸篓。
- [ ] 中央内容缺失的旧记录仍可安全清理；其已占用的中央路径不得被新同名记录复用，清理旧记录也不得移动或删除新记录的内容。
- [ ] 撤销“只清理主 Skill”时只重新接管指纹未变化的原副本；已变化或缺失的副本保持不受管理，且不会被恢复操作覆盖。
- [ ] 「我的 Skills」列表行只显示名称、来源和中央库大小；拖动时原卡片变为空占位槽，其他卡片实时让位并预览松手后的顺序，跟手卡片无重影或压叠；占位槽仅用一根无端点、无文字注释的系统蓝线标明落点，松手或取消后占位槽、蓝线和浮层立即消失；右键移动与可恢复删除均能完成或取消，不留持久提示。
- [ ] 中途失败能恢复本事务已修改目标；外部改动不会被同步或撤销静默覆盖。
- [ ] GitHub 导入、更新和风险扫描满足大小、数量、路径与不执行约束。
- [ ] 本地开发源的纯净候选只包含确认路径，母板内容和指纹在导入、检查与更新全过程保持不变；包含范围外变化不误报，包含范围内变化才提示更新。
- [ ] 本地已选路径消失、新增可能运行内容或 `SKILL.md` 新引用未包含内容时暂停更新并要求确认；确认前中央主 Skill和应用副本不变化。
- [ ] 本地更新可只更新中央主 Skill或连同安全的受管理副本一起事务更新并撤销；来源移动或停止跟踪不会删除任何现有内容，重新关联前先展示差异。
- [ ] 未配置 AI、服务超时、额度不足或用户取消时，所有本地管理、安装、更新和撤销功能保持可用。
- [ ] Agnes、DeepSeek、Kimi、MiniMax、GLM 和自定义接口的连接测试、无效密钥、超时、限流、取消、结构损坏和缓存失效均有自动化覆盖。
- [ ] DeepSeek 的发现请求包含 JSON 模式和思考关闭参数；HTTP 200 的空内容、截断、损坏 JSON与字段校验失败均能准确分类，连接测试只有在最小结构化输出成功后才显示可用。
- [ ] API Key 只存在于设备解锁时可访问的本机钥匙串；JSON、日志、操作记录、诊断和 AI 请求预览中均不泄露密钥。
- [ ] 冷启动和 24 小时自动检查不读取钥匙串秘密、不出现 macOS 登录密码框；显式连接或保存可在应用身份变化后重绑定一次，同一版本后续启动保持安静。
- [ ] 私人或本地 Skill 未经单独确认不会发送；服务商、基础地址或模型切换都会使确认失效，不会静默转发相同内容。
- [ ] AI 的每条安全或完整性结论都能核对真实文件证据；不存在的路径、越界行号、提示注入和截断输出不能改变安装决定。
- [ ] “发现 Skills”能在不安装 Node/npm 的前提下搜索候选；外部目录失败时平静降级，候选加入仍经过完整下载与本地审查。
- [ ] 推荐排序覆盖相关性、来源、维护、使用量和结构信号；GitHub Star 作为高优先级知名度证据，但用途不匹配的热门 Skill 仍不得推荐，弱候选不得为补数量进入主列表。发现阶段不显示全包安全结论，加入前的完整本地检查不得被搜索证据替代。
- [ ] 运行中的寻找不会被重新加载误判为中断；AI 失败不会在聊天区生成伪造回复；AI 每轮最多评估 8 个候选，但未送评的已核验高质量候选不会因该上下文预算被丢弃。
- [ ] Skill 搜索只在左侧一级导航“发现 Skills”中完成；寻找记录可继续、可单条删除、可全部清空且可在 Finder 中打开，但不接受与 Skill 发现无关的通用办公任务。
- [ ] GitHub 候选显示真实仓库级 Star、获取时间和仓库归属；多 Skill 仓库不会把同一 Star 数误写成单个 Skill 的独立评价。
- [ ] AI 整理的用户说明固定覆盖「Skill 简要说明（特色、技巧）、适用场景、体验流程、提示词参考」，使用普通用户能理解的语言；发现候选只在用户打开时按需生成一次，加入后按内容指纹复用，本地导入遵守私人内容开关，内部规则和无依据推测不得展示。
- [ ] 公开仓库无需登录即可检查；连接 GitHub 后立即解除未登录额度暂停，已登录额度暂停仍遵守 GitHub 的恢复时间。GitHub 限流、私人仓库登录失效、仓库未授权、地址失效和网络故障分别显示正确动作。
- [ ] 多个 Skill 来自同一仓库时只发送一组仓库级检查；条件请求返回未变化时不发出后续 Commit、Tree 或下载请求。
- [ ] 自动检查的最短间隔为 24 小时；手动检查当前 Skill 可立即执行，批量检查显示仓库级进度且可中止；大型库优先处理最久未成功检查的仓库。
- [ ] 自动化测试通过，并完成核心主流程的真实鼠标前台验收。
- [ ] 全量测试、ad-hoc Hardened Runtime 签名、发布包隐私扫描、DMG 完整性、SHA-256、来源清单、隔离属性模拟、干净账户“仍要打开”安装和 GitHub Release 下载回读分别通过后，才能宣称当前发行策略下的公开发行完成。
