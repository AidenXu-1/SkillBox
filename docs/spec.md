# SkillBox Spec

> 本文件是 SkillBox 当前唯一开发准绳。辅助文档与本文件冲突时，以本文件为准并同步修正。

## 状态

- 当前版本：Spec v1
- 当前阶段：功能闭环与 UI 细节打磨
- 最近更新：2026-08-15
- 实现门槛：原型方向已经用户确认；当前先验证功能与安全边界，再进入正式 UI 优化

## 1. 产品定义

SkillBox 是面向 AI 产品创作者的开源 macOS 应用。它用一座本地中央仓库统一管理用户拥有的 Agent Skills，并把选定版本安全分发到多个 Agent。

它首先解决四件事：

1. 看清本机到底有哪些 Skill，以及哪一份是可信原件。
2. 看清每个 Agent 实际安装、间接加载或漂移了哪些 Skill。
3. 在写入前预览全部变化，避免静默覆盖用户文件。
4. 写入后留下恢复点，让一次同步可以撤销。

## 2. 用户与核心场景

- 目标用户：同时使用多个 Agent 做产品、但不愿手动维护隐藏目录的 AI 产品创作者。
- 核心场景：首次盘点散落的 Skills；建立中央仓库；选择 Skill 与 Agent 的安装关系；安全同步；检查来源更新；发现外部改动并处理。
- 现状问题：Skills 分散在多个产品目录，同名内容可能相同也可能分叉；普通用户难以判断原件、安装状态和一次复制会造成什么影响。
- 第一版价值：让 Skills 一眼看清，并能预览、同步、撤销。

## 3. MVP 范围

### 必须做

- 原生 macOS 应用，中文界面，Apple Silicon，最低 macOS 15。
- 引导式首次盘点，全程只读，自动发现 Agent 与标准全局 Skills 目录。
- 扫描标准 `<skill>/SKILL.md`，支持根目录下更深层但不位于另一个 Skill 内部的 Skill。
- 使用稳定内容指纹归并完全相同的副本；同名不同内容保留为独立版本并要求用户选择。
- 中央 Skill 库、内容预览、来源信息、文件树、风险报告和 Finder 定位。
- 安装矩阵，以及未安装、已同步、待更新、外部改动、冲突、间接可见六种状态。
- 内置 Codex、Claude Code、Cursor、Kimi Code、ZCode、WorkBuddy、HanaAgent、Gemini CLI、OpenCode；支持自定义全局目标目录。
- 将 `~/.agents/skills`、`~/.config/agents/skills` 等通用目录作为可导入来源展示，不把它们伪装成 Agent。
- 从现有 Agent、本地文件夹、公开 GitHub 仓库和用户明确授权的私人 GitHub 仓库导入；多 Skill 仓库先预览和选择。
- GitHub 来源可跟随“最新正式 Release”或“默认分支”。Release 优先使用作者上传的 ZIP 安装包；多个 ZIP 由用户选择，没有 ZIP 时明确提示后才可回退到完整源码。SkillBox 只自动检查版本信息，下载、更新和安装始终需要用户确认。
- GitHub 更新预览展示新增、修改、移除的文件、风险变化及 `SKILL.md` 前后内容。更新可只替换中央原件，也可在同一次可恢复操作中更新已管理且未被外部修改的安装副本。
- 变更预览、事务式实体复制、备份、失败恢复、操作记录和撤销。
- 只更新中央原件也必须生成操作记录并可撤销；撤销 GitHub 更新时同时恢复对应的来源版本记录。
- 本地静态风险报告。导入与扫描不得执行 Skill 内任何文件。
- 除可选的 GitHub 来源授权外，无 SkillBox 账号、无遥测、无云端数据库。

### 明确不做

- 项目级 Skills、Skill 市场、排行榜或推荐。
- 跟踪任意分支、固定到某个版本、自动下载、自动更新或自动安装。
- 将 Release 中的非 ZIP 附件或来路不明的文件当作 Skill 安装包。
- 内置 Markdown 编辑器、Skill 创建器或 AI 深度审查。
- 团队协作、云同步、Windows、Linux、后台自动同步和应用自动更新。
- 管理 Agent 插件、MCP、系统内置 Skill 或第三方插件缓存。

## 4. 信息架构与主流程

### 主导航

- **总览**：已加入 SkillBox、本机找到、需要选择、应用位置和最近操作。
- **我的 Skills**：集中保存的内容、来源、使用流程、文件检查、快速安装操作和 Skill 详情。
- **安装到应用**：按需调整 Skill 与应用的安装关系；点击某个交叉点后就地确认该项，不再要求用户到页面另一处找批量执行入口。
- **最近操作**：每次安装的结果、备份和「恢复到操作前」状态。
- **设置**：SkillBox 保存位置、数据与隐私、备份保留策略和产品信息。

### 界面语言

- 主流程面向不熟悉文件系统的用户，先说“会发生什么”，技术原因放到可展开的第二层。
- 「中央仓库」对用户显示为「我的 Skills」或「SkillBox 保存位置」；「同步」优先表达为「安装」或「更新」。
- 「指纹」改为「内容校验码」并只放在「Skill 详情」中；「事务」改为「最近操作」；「接管」改为「让 SkillBox 管理这份内容」。
- 「查看 Skill 详情」作为详情页的第二层信息入口，展开后展示完整文件目录、主 `SKILL.md` 的预览按钮和内容校验码；目录读取不得阻塞主界面。
- 所有可点击控件都必须提供悬停、按下和禁用反馈；「查看 Skill 详情」的整行标题区域都可点击，不能只依赖小箭头。
- 「这个 Skill 怎么用」只回答普通用户会关心的四件事：能帮什么、什么时候适合、可以怎样告诉 AI，以及作者可选提供的「使用时会发生什么」。示例话术必须可一键复制，体验流程最多显示 3 步。
- 使用说明按「`agents/openai.yaml` 用户展示信息 → `README.md` / `SKILL.md` 明确的用户章节 → `SKILL.md` 的 `description`」降级整理。某项缺失时自动省略对应区块；只要有一句可确定的用途，就保留一张简化卡片。
- SkillBox 不使用 AI 生成或猜测使用方法，不得把「执行步骤」「安全检查」「内部规则」等给 Agent 的指令当成用户教程。只有作者明确使用「使用时会发生什么」等面向用户的标题时，才展示体验流程。
- 「我的 Skills」必须支持搜索，并能按有更新、已安装和需要处理筛选；GitHub Skill 有新版本时在列表中直接显示。
- 私人 GitHub 的连接入口必须同时出现在「我的 Skills」、GitHub 添加页和设置页，不能要求用户先猜到设置位置。
- 私人仓库连接必须以普通用户能理解的三步流程呈现：「确认身份 → 选择仓库 → 回到 SkillBox」。用户界面不出现 `GitHub App`、Client ID、Device Flow 等开发术语，并明确说明无需下载其他软件。
- 身份确认成功后，SkillBox 必须自动打开仓库选择页并等待 GitHub 结果；用户选好仓库后直接回到 SkillBox，不应再寻找第二个功能入口。等待期间需展示进度和“重新打开 GitHub”的恢复按钮。
- 验证码页必须明确说明：该步骤只用于确认身份，不创建仓库、不修改文件；重新开始只会换取一个会过期的临时验证码。
- GitHub 连接管理必须区分三种动作：「断开连接」只删除本机钥匙串登录信息；「清除 GitHub 信息」同时移除仓库地址和更新记录，但保留 Skill 为本地副本；「在 GitHub 撤销授权」打开 GitHub 官方设置页由用户亲自完成。
- 断开私人仓库连接不得影响公开仓库检查更新；私人仓库在下次检查时提示重新连接。
- GitHub 下载、解压和检查期间必须显示可见进度并允许取消；仓库没有正式 Release 时提供一键改用默认分支。
- Release 只有一个合法 ZIP 时直接下载；存在多个 ZIP 时弹出单任务选择窗，不得自动猜测。Release 没有 ZIP 时，必须明确告知将导入测试、CI 和开发文件，用户确认后才能下载源码快照。
- Agent 作为品牌名的一部分时保留；概括称呼统一使用「AI 应用」或「应用」。
- 错误和风险提示先告诉用户结果与下一步，不直接展示 schema、HTTP、POSIX、软链接等内部术语；必要证据仍可在详情中查看。
- 安全提示必须先说明“添加与安装时不会运行文件”，再解释什么情况下才可能执行；用“仅说明、需要了解、需要确认、无法添加”代替笼统的技术风险标签。
- 文件检查在 Skill 详情中默认收起，主界面只显示提示数量和「安装时不会运行」；用户主动展开后再展示文件、命令和分级证据。
- “安装到应用”的安装矩阵固定紧跟页头与图例，默认从左上角展示；宽度不足时可水平滚动，任何应用列不得被永久裁切。未管理的同名目录必须在用户点击前显示独立状态，不得先显示普通加号。

### 首次盘点

1. 解释只读扫描、中央仓库和不会静默覆盖的承诺。
2. 自动识别内置 Agent、通用目录及其中的 Skills。
3. 校验结构、计算指纹、生成风险报告。
4. 完全相同的副本自动归并；同名不同内容并排展示为冲突版本。
5. 用户选择要纳入中央仓库的版本和初始安装关系。
6. 只把选择结果复制到中央仓库，原 Agent 目录保持不动。
7. 首次同步另行预览和确认；盘点完成不等于已经接管原目录。

### 日常同步

1. 用户点击安装矩阵中的一个 Skill 与应用交叉点。
2. `SyncPlanner` 只读比较中央指纹、目标内容和所有权记录；在用户确认前，不得持久化安装选择。
3. 当前交叉点直接弹出单项确认窗。若已有同名 Skill，必须明确告知「内容相同」或「内容不同」；不同时展示新增、修改和移除的文件摘要。
4. 用户确认后只持久化并执行当前这一项，不夹带页面中的其他待处理项；写入前创建备份，完成后生成操作记录。
5. 失败时恢复本次操作已改动的目标；成功后允许从操作记录撤销。批量全部安装与卸载仍使用独立的总清单预览。

## 5. Agent 路径合同

| Agent | 显示名称 | 默认全局目标目录 |
|---|---|---|
| Codex | Codex | `~/.codex/skills` |
| Claude Code | Claude Code | `~/.claude/skills` |
| Cursor | Cursor | `~/.cursor/skills` |
| Kimi Code | Kimi Code | `~/.kimi/skills` |
| ZCode | ZCode | `~/.zcode/skills` |
| WorkBuddy | WorkBuddy | `~/.workbuddy/skills` |
| HanaAgent | HanaAgent | `~/.hanako/skills` |
| Gemini CLI | Gemini CLI | `~/.gemini/skills` |
| OpenCode | OpenCode | `~/.config/opencode/skills` |

- 内置应用的标准 Skills 目录不存在时，视为本机尚未安装或尚未正确初始化该应用；SkillBox 必须提示用户并阻止部署，扫描、预览和执行阶段都不得代为创建目录。
- 自定义安装位置只能由用户通过目录选择器选择一个已经存在的目录，SkillBox 不代为创建。
- Kimi Code 会读取多个品牌目录和通用目录；SkillBox 必须把由其他目录带来的可见性标为“间接可见”，不声称用户可以仅靠取消 Kimi 勾选来关闭它。
- 自定义目标由目录选择器添加，必须有明确显示名称。磁盘根目录、用户主目录、应用中央仓库根目录等宽泛或递归危险路径不得作为目标。
- 自定义目标支持改名、更换目录和移除。仍有受管理副本时不得更换目录或移除，避免遗留无法追踪的安装。

## 6. 数据与文件合同

中央数据根目录：`~/Library/Application Support/SkillBox/`

```text
SkillBox/
├── catalog.json
├── targets.json
├── assignments.json
├── installations.json
├── organization.json
├── source-state.json
├── Library/<skill-name>/content/...
└── Transactions/<transaction-id>/
    ├── manifest.json
    └── backups/...
```

- JSON 顶层必须包含 `schemaVersion: 2`，使用临时文件加原子替换写入。Schema v1 数据在内存中迁移后原子写回，不得当作损坏数据丢弃。
- `SkillRecord`：稳定 UUID、规范名、显示名、描述、指纹、来源、风险摘要、中央内容路径。
- `AgentTarget`：稳定 ID、适配器 ID、自定义显示名、路径、检测状态和写入状态。
- `Assignment`：Skill 版本、目标、安装目录名和期望状态。
- `ManagedInstallation`：目标路径、Skill ID、上次部署指纹、事务 ID 和时间。
- `SyncTransaction`：预览操作、备份位置、执行结果、错误和撤销状态。
- `GitHubSourceState`：仓库稳定 ID、Skill 子目录、跟踪方式、当前版本、Commit SHA、目录 SHA、Release ID、Asset ID、Asset 名称与 SHA-256 摘要、上次检查时间、忽略版本和检查开关。任何凭据都不得进入该数据。
- 中央 Skill 文件夹优先使用可读的规范名称，例如 `Library/vibe-project-foundation/content`；同名不同版本使用 `名称--短编号` 避免冲突。旧 UUID 文件夹在保留内容、历史版本和记录对应关系的前提下自动迁移。
- 同名不同内容允许作为多个 `SkillRecord` 存在；同一目标同一安装目录名只能选择一个版本。
- “我的 Skills”中的单个 Skill 支持“安装到全部可用应用”和“从所有应用卸载”；两者都先生成安装预览，再由用户确认执行。
- 删除中央 Skill 前必须确认；仍存在已管理安装时必须先完成全局卸载。删除后的中央内容移入 SkillBox 本机“已删除”目录，避免立即永久清除。
- 删除完成后在界面中提供即时「撤销」；恢复时同时还原分类、待安装选择和 GitHub 来源状态。
- Skill 分类与顺序使用独立的 `organization.json` 保存，不改名、不移动中央原件目录，也不改变安装关系。
- 用户可以新建、重命名、删除分类文件夹，将 Skill 拖入文件夹或拖回“未分类”，并自由调整文件夹和同组 Skill 的显示顺序。
- 删除分类文件夹只取消其中 Skills 的分类并移回“未分类”，不得删除 Skill 原件或 Agent 安装副本。

## 7. 指纹、所有权与写入安全

- SHA-256 指纹覆盖规范化相对路径、文件内容、POSIX 权限和软链接目标；遍历顺序固定。
- 扫描遇到有效 Skill 根后不再把其内部 `SKILL.md` 当成独立 Skill。
- 盘点只读；导入复制进中央仓库；同步采用实体复制，不使用软链接。
- 写入前把目标当前内容复制到事务备份，在目标同级暂存目录完成复制和指纹复核，再替换目标。
- 已存在、未被 SkillBox 管理且内容不同的同名目录必须阻塞。用户只能显式选择导入、保留或替换。
- 未被 SkillBox 管理的同名目录必须返回中央与目标两份真实指纹，不得用空值推断内容相同。指纹相同时可由用户确认让 SkillBox 管理；指纹不同时，替换授权必须绑定到用户预览的目标指纹。
- 只有带所有权记录且当前指纹仍等于上次部署指纹的目标，才能自动更新或移除。
- 目标被外部修改后标为“外部改动”，同步与撤销都不得静默覆盖。
- 只有检测状态为“已找到”且现有目录可写的应用才能接收新部署；历史选择和过期预览不得绕过这条限制。
- 备份保留至少 30 天且至少保留最近 10 个事务；自动清理不得删除仍可撤销的最新事务。

## 8. 本地风险报告

- 校验 `SKILL.md`、Frontmatter 和完整文件清单。
- 检查可执行权限、脚本、二进制、超大文件、软链接、路径越界、网络下载、提权、删除、凭据访问和动态执行模式。
- Markdown 中的命令说明与可执行脚本中的真实行为分开呈现。
- 删除命令必须按作用范围分级：删除临时目录或变量指向位置默认显示为“请留意”，并展示命中的命令；直接指向根目录、用户目录等宽泛位置才显示高风险。普通提示不得使用红色警报图标。
- 越界软链接、路径穿越和超过导入上限直接阻止导入；其他高风险项需要二次确认。
- GitHub 下载上限：10 MiB 压缩数据、25 MiB 解压内容、1000 个文件。
- 下载上限必须在网络流读取期间生效，不得等整个文件进入内存后才判断。
- Release ZIP 旁边存在同名 `.sha256` 时必须自动校验；校验错误直接阻止导入。更新记录同时绑定 Release ID、Asset ID 和已验证的 SHA-256。
- `.github/workflows/*.yml` 和 `.yaml` 中仅用于 GitHub Actions 任务的 `${{ github.token }}` 或 `${{ secrets.GITHUB_TOKEN }}` 显示为“仅说明”，并明确该文件不会在本机安装时自动运行。本地脚本读取令牌、访问凭据目录、输出令牌或发送到外部网址仍保持高风险。
- 报告必须明确：静态检查只能提供证据和提示，不能保证 Skill 绝对安全。

## 9. 技术路线与公开接口

- Swift 6、SwiftUI、macOS 15+、arm64。
- 核心行为放入纯 Swift 模块并通过协议隔离：`AgentAdapter`、`SkillScanner`、`SourceProvider`、`RiskAnalyzer`、`SyncPlanner`、`SyncExecutor`。
- UI 不直接读写 Agent 目录，只消费核心模块的只读模型和显式命令。
- 不启用 App Store Sandbox；启用 Hardened Runtime。应用只访问内置路径、用户选择路径和自己的 Application Support 数据。
- 外部网络只用于 GitHub 登录授权、用户主动导入或更新检查。启动时若距上次检查超过 6 小时，可只读取版本元数据；不设后台常驻任务。
- 私人仓库使用 GitHub App Device Flow，只申请 `Contents: read` 与必要的 Metadata 读取权限。Access Token 和 Refresh Token 只保存在 macOS 钥匙串，不写入 JSON、日志或诊断信息；客户端不包含 Client Secret 或 GitHub App 私钥。
- 开源采用 MIT License；公开发行使用 Developer ID 签名、公证后的 DMG 和 SHA-256 校验和。

## 10. 验收标准

- [ ] 首次扫描不会创建、修改、删除或重命名任何现有 Agent 文件。
- [ ] 相同副本被正确归并，同名不同内容不会自动选边或覆盖。
- [ ] 九个内置 Agent 与自定义目录均能显示真实检测、写入和安装状态。
