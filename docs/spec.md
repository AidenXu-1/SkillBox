# SkillBox Spec

> 本文件是 SkillBox 当前唯一开发准绳。辅助文档与本文件冲突时，以本文件为准并同步修正。

## 状态

- 当前版本：Spec v2.51
- 当前阶段：全局 Skill 来源与多 Agent 安装模型重构
- 最近更新：2026-09-08
- 实现门槛：高风险确认、批量预览取消和操作恢复必须具有显式、可取消、可持久且不误导的状态闭环；公开发行仍需通过全量自动化、真实主流程、无隐私信息的 DMG、SHA-256、来源清单、隔离属性模拟和干净账户安装验收

### 文件夹优先排列（v2.51）

- 按用户明确指定的方向，所有自建文件夹及其内容排在列表上方，文件夹之间保留拖动排序；固定“未分类”及其 Skill 排在全部文件夹下方，包括没有文件夹、空文件夹、折叠与名称排序场景。
- 文件夹拖到末尾仍停在“未分类”之前；最后一个文件夹中 Skill 的末尾插入预览不得越过“未分类”。拖回未分类清除分类关系，原有顺序、内容和安装关系继续保留。

### 文件夹原生拖动优化（v2.50）

- 用户查看预览并回复“继续”，据此实施已展示方向。保留现有三栏、来源标识、大小、详情、右键移动与删除、文件夹重命名和删除功能。
- Skill 与文件夹使用统一的落点逻辑：Skill 放到标题归类、放到行间精确排序；文件夹可放到另一文件夹前后，包括末尾；固定未分类不可拖走。
- 拖动跟随抓取位置，邻近行平滑让位，标题归类高亮，折叠文件夹悬停展开，列表边缘渐进滚动。几何基于已知行高与实际滚动偏移，避免视图零尺寸或滚动后错误落点。
- 只在有效松手后保存整理元数据；Esc、移出列表松手、切走和失去窗口焦点取消。搜索、筛选和按名称排序时暂停拖动，手动顺序保留。原件与安装状态不因整理改变。

### 启动与单项安装响应修复（v2.49）

- 启动和刷新只识别应用专属安装位置、核对已管理副本，不递归发现 Agent 目录中的未知 Skill。移除旧自动扫描调用；本地来源依旧由用户选择，保留手动读取时的内容大小与路径约束。
- 单项确认只重新核对所选 Skill 与目标位置，保留该位置的所有权冲突检查；文件比较在界面线程之外进行。完成后只刷新该项，不等待其他应用目录扫描。真实执行、备份、写入前复查及恢复机制保持。
- 安装／卸载确认显示正在处理；完成关闭，失败保持可重试并显示原因，不报成功。处理中避免误触重复提交或把关闭确认窗误解为中止文件操作。
- 文件夹名称与排序保存只更新整理记录，不重新比对安装文件。完整拖放交互方向见 `design/ui/organizer-20260908/`；视觉确认前只提供交互预览，不改变原生拖放结构。

### 已复现对话缺陷修复（v2.48）

- 用户授权修复只读审查确认的三项问题，同时要求保护已调好的查找能力。询问是否存在适用 Skill 的新需求进入查找；它与“这个 Skill 有什么限制”等当前候选问题分开，并贯穿任务延续判断，不能在旧作者任务或待澄清状态下继承无关范围。
- 切走再切回仍保持补充暂停；停止、重启后发送新消息不能恢复旧队列。旧补充由“继续处理补充”显式恢复，新一轮中正常发送的补充仍按原规则合并执行。
- 撤回条件同时移除目标原句中的等价要求，避免“不联网”等表达重新形成已撤回的离线条件；保留同句其他要求及当前任务。
- 三栏、指定名称、作者范围、中文身份别名、推荐资格、来源核验、安装与恢复机制保持。此次不增加模型调用、不改变模型权限，不将局部修复宣称为完整 Skill 领域助手已经完成。整体语义理解层的改进另行明确范围和验收。

### 指定对象与追问修复合同（v2.47）

- 已知作者的自然表达不依赖“的”字位置；作者身份和用途分别核对，不因作者名出现在查询词中就放行其他作者。
- 指定英文名称的空格、连字符形式按完整对象处理；作者任务中的名称补充保留作者范围；明确的新查找或换任务仍重置旧范围。
- 中文别名由带公开来源的身份索引解析，映射到作者仓库和 Skill 路径后再实时核验正文；用途扩展词不得冒充身份别名。未知或歧义名称不保证全网查全，不以相似作品替代。
- 既有同名筛选、必须条件、推荐证据门槛、停止行为、三栏布局和请求上限保持；修复不新增付费服务或额外模型调用。
- 验收以用户的“帮我找卡兹克写作的skill。”→“我记得卡兹克有两个写作skill啊。”→“有个human writing的skill。”三轮最终列表，以及“小黑配图”原句为准；同时回测原完整名称和模糊推荐。通过后构建并可恢复替换正式 App，备份当前 App 和完整资料，不覆盖历史记录。

### 宣发前独立复核与修复合同（v2.46）

- 保留已经验收的三栏与精确名称查找。明确的新查找优先于“比较”“去掉”等普通关键词；比较和解释只能引用用户实际指向的已核验候选，具名对象不存在、序号越界或多个对象不明确时澄清，不擅自取前两项。
- 场景推荐的必须条件独立于用途和热度检查。免费、离线、禁止上传等条件，作者资料明确相反时不推荐，没有足够资料时标为尚未确认；不能把“未提及收费”当免费。其他必须条件也不得仅因模型排名而跳过，无法由资料确认时保留为待核对线索。偏好只影响选择，不当成必须条件。点名查找继续返回身份匹配结果，不混入场景推荐门槛。
- 必须条件和排除条件须有用户原句依据，模型提取的检索标签或新增建议不得自动变成硬条件。旧记录继续查找时先核对已有条件的用户来源，普通补充、澄清回答、继续深挖共用同一边界；撤回的条件不得从旧消息重新加入。
- 每轮直接 HTTP 请求累计最多 256 次，包含跳转，GitHub API 仍最多 12 次；共享重复读取不重复占额度。所有默认直接 HTTP 来源纳入同一计数。外部媒体工具每轮最多发起两次，独立统计调用次数，其内部 HTTP 数量未知，不把它折算为一次网络请求。
- GitHub 按普通与搜索资源分别记录额度和重置时间；普通匿名请求保留已知 12 次余量及进程内每小时 36 次上限，搜索匿名请求保留两次余量及每分钟八次上限。一个资源的主额度耗尽不得误挡另一个资源；明确的共同限流仍遵守服务端冷却。停止后取消余下工作。
- 是否查完来源由来源失败、核验延后、截断和预算事实决定；是否调用 AI 独立说明，未调用 AI 不得误报“来源尚未查完”。
- 验收包括新增失败用例、精准原句和模糊原句、超过五个结果的既有保护、停止/恢复与原生三栏；完整检查通过后构建同代安装包并可恢复替换。无新付费服务或依赖；回退为保留本轮旧 App 与完整资料库，不覆盖既有用户内容。

## 1. 产品定义

SkillBox 是面向 AI 产品创作者的开源 macOS 应用。它统一管理跨项目使用的全局 Agent Skills，并把同一个来源版本安全安装到多个 Agent。

它首先解决五件事：

1. 从本地开发文件夹或 GitHub 添加一份全局 Skill。
2. 选择把它安装到哪些 Agent，并支持统一安装、更新和卸载。
3. 在写入前预览全部变化，避免静默覆盖用户文件。
4. 写入后留下恢复点，让一次安装可以撤销。
5. 按用户的实际需求发现 GitHub 上的候选 Skill，并在加入前完成来源、内容和权限审查。

## 2. 用户与核心场景

- 目标用户：同时使用多个 Agent 做产品、但不愿手动维护隐藏目录的 AI 产品创作者。
- 核心场景一：用户在专门的本地开发文件夹中开发全局 Skill，SkillBox 只读监控该来源，用户确认后把同一安装版本分发到多个 Agent。
- 核心场景二：用户从 GitHub 获得全局 Skill，SkillBox 跟踪最新正式 Release 或默认分支，用户确认后把同一安装版本分发到多个 Agent。
- 现状问题：多个 Agent 各有一套全局 Skills 目录，普通用户不熟悉隐藏路径，同一份 Skill 需要重复安装、更新和卸载。
- 第一版价值：用户只需维护一个明确来源，SkillBox 负责多 Agent 安装、更新、卸载和恢复。
- 项目级 Skill 完全位于本产品边界之外；不扫描、不导入、不展示，也不为它设计安装或兼容逻辑。

## 3. MVP 范围

### 必须做

- 原生 macOS 应用，中文界面，Apple Silicon，最低 macOS 15。
- 自动发现 Agent 与标准全局 Skills 安装目录；Agent 目录始终是安装目标，不得成为新 Skill 的来源。
- “添加 Skill”只提供“选择本地开发文件夹”和“添加 GitHub 仓库”两个入口；每个 Skill 必须且只能关联其中一个来源。
- 本地开发文件夹与 GitHub 均需解析标准 `<skill>/SKILL.md`；多 Skill 来源先预览和选择。
- 用户手动选择本地开发文件夹时，选中的文件夹本身直接包含 `SKILL.md`，或其下包含一份或多份 Skill，都必须能够识别。手动添加时单份 Skill 的普通文件总量上限为 128 MiB；这条规则必须贯穿预览、内容确认、导入、后续检查与重新关联，不得在同一条流程中混用更小的扫描上限。通用目录扫描器默认保持 50 MiB 上限，但不用于启动自动发现安装副本。超过上限或读取失败时必须告诉用户具体原因，不得误报为“没有找到 Skill”或“来源消失”。
- 我的 Skills、内容预览、唯一来源信息、文件树、风险报告和 Finder 定位。
- 安装矩阵，以及安装、已安装、可更新、已有同名、应用不可用五种用户可见状态。
- 新用户默认在安装表中显示 GPT、Claude、WorkBuddy、ZCode、Kimi Code、Cursor、HanaAgent、Pi、DeepSeek Harness 和 Trae；支持从应用列表移除、重新加入，以及添加自定义全局目标目录。老用户已有的 Gemini CLI、OpenCode 目标和安装关系无损保留，但不进入新用户默认列表。
- 每个内置 Agent 只检查并写入它自己的标准全局 Skill 目录；`~/.agents/skills`、`~/.config/agents/skills` 等共用目录不扫描、不写入，也不得作为“已安装”或“可以使用”的判断依据。OpenCode 的专属目录 `~/.config/opencode/skills` 不属于共用目录。
- 从本地开发文件夹、公开 GitHub 仓库和用户明确授权的私人 GitHub 仓库添加；不存在一次性导入或无来源 Skill。
- 本地开发文件夹是唯一原件。SkillBox 对其只读，在应用运行且来源可访问时检测内容变化，并按确认过的精确包含路径生成纯净安装快照；不得移动、重命名、改写来源，也不得执行其中的脚本、构建或依赖安装命令。
- 本地来源变化只产生候选安装版本，不自动写入任何 Agent。用户确认后，SkillBox 冻结一次不可变安装快照，并在同一条可恢复事务中更新用户选择且未被外部修改的受管理应用副本。
- GitHub 来源可跟随“最新正式 Release”或“默认分支”。Release 优先使用作者上传的 ZIP 安装包；多个 ZIP 由用户选择，没有 ZIP 时明确提示后才可回退到源码快照。SkillBox 只自动检查版本信息，下载、更新和安装始终需要用户确认。
- GitHub 连接遇到短暂 TLS 或超时错误时，只可在不放宽证书与 HTTPS 验证的前提下自动重试一次。仍失败时保留用户刚填写的仓库与跟踪方式，区分安全连接、断网与超时，告诉用户本次没有下载或修改 Skill，并在错误弹窗提供一键“重试”。
- GitHub 仓库是唯一原件，不直接等于可安装 Skill。SkillBox 的安装快照与应用只保存“可安装内容”；源码快照只用于发现、比较和生成可安装内容，不得整仓静默进入应用目录。
- 公开仓库检查与私人仓库登录彼此独立。公开仓库不得因为未登录、登录过期或 API 限流而提示用户连接私人仓库；失效登录需自动退回公开读取。
- GitHub 更新预览展示新增、修改、移除的文件、风险变化及 `SKILL.md` 前后内容。用户确认后冻结新的安装快照，并在同一次可恢复操作中更新用户选择且未被外部修改的安装副本。
- 变更预览、事务式实体复制、备份、失败恢复、操作记录和撤销。
- 生成或替换安装快照必须留下操作记录并可撤销；撤销 GitHub 更新时同时恢复对应的来源版本记录。
- 本地静态风险报告。添加、检查和安装不得执行 Skill 内任何文件。
- 可选 AI 助手，支持 Agnes、DeepSeek、Kimi、MiniMax、GLM 和用户配置的 OpenAI 兼容接口。AI 只负责解释、归纳和二次复核，不参与文件删除、安装范围选择、覆盖授权或事务执行。
- 左侧主导航提供“发现 Skills”：按用户输入并行查询无需付费搜索服务的优质公开媒体、社区与免费 Skill 目录，默认覆盖 YouTube、B 站、公众号、Hacker News、skills.sh、GitHub 和内置可信目录。全部默认来源必须在 SkillBox 后台完成，不打开或控制浏览器，不读取 Chrome 标签页、Cookie 或登录态：YouTube 只由 `yt-dlp` 读取公开元数据且不下载视频，B 站使用匿名公开接口与当日 WBI 签名，公众号只解析搜狗微信公开搜索页。小红书和抖音不进入当前默认或显式搜索链路；未来如果提供独立平台深搜，必须使用与用户日常浏览器分离的独立环境并再次取得明确同意。平台结果先提取带证据编号的 Skill 名或 GitHub 身份线索，再回到 GitHub 搜索并核验真实 `SKILL.md`；无法精确对上候选名称或仓库的媒体内容不得冒充候选专属口碑，但也不得删除其他免费来源中已经核验、用途匹配并通过质量门槛的最终结果。排序先看能否直接完成任务，再看独立提及者数、跨平台覆盖、实际安装量、来源、维护状态、仓库 Star 和说明完整度；同一作者在同一或不同平台的重复发布只算一位提及者，拿不到作者身份的内容不计入独立人数，不同平台的播放、点赞与评论不直接相加冒充口碑。候选名称和能力必须回到 GitHub 真实文件核验，模型不得凭帖子或印象虚构 Skill。任一媒体来源超时、风控拒绝或结构变化时，保留其他媒体、GitHub、skills.sh 和可信目录中的有效结果，并逐项明确本轮未参与的来源，不得自动改用浏览器。发现阶段不声称已完成全包安全检查；用户点击加入后才通过 GitHub 下载完整候选并进入本地安全预览。Skill 查找只在这一板块完成。
- Skill 介绍使用用户自己的 Agnes API：用户在设置中填写并测试 API Key，再在某份 Skill 的详情中主动点击“获取 Skill 介绍”。该次点击就是这一次发送授权；打开应用、切换 Skill、新增 Skill 或内容变化都不得自动发起 AI 请求。
- 每次「获取 Skill 介绍」只发起一轮完整请求，单轮输出上限为 2,400 Token；不得在输出被截断后用更少额度重复发送整份 Skill 资料。被截断时保留已有介绍，并明确告知用户「返回的介绍不完整」，不得把它隐藏成笼统的服务失败。
- 核心添加、安装、更新、卸载、撤销和本地风险阻止在 Agnes 或其他 AI 服务不可用时仍完整可用。
- 无 SkillBox 账号、无遥测、无云端 Skill 库，也不建设 SkillBox AI 中转服务。Skill 介绍由客户端直接调用用户明确配置的 Agnes 官方 HTTPS 接口。

### 已确认的发现对话合同（v2.42）

- 同一输入框区分查找、补充、比较、解释、致谢、撤回条件。问题涉及当前候选时，使用已核验资料回答，不重新搜索；指代不明确或比较对象不足时追问必要信息。
- 用户主动发送解释或比较问题时，可用其已验证的当前模型完成一次有资料引用的回答，最多 3 份引用，每份摘要 500 字符、正文 1,500 字符，问题最多 2,000 字符、任务摘要最多 1,000 字符，输出总预算 600 Token。引用身份必须来自当前给定候选，材料作为不可信引用处理，不自动执行、安装或改变用户条件。AI 未启用或失败时给出明确的作者资料摘录，不冒充模型理解后的答案；AI 回答显示生成标记和可展开依据。此入口与候选排序中的模型自由文本严格分开，后者仍不可进入用户文案。
- 当前任务摘要显示目标、条件和选中对象。明确换任务时，旧结果以有来源的历史消息保留，新任务使用独立的消息起点；撤回条件时更新条件并推进上下文起点，保留原始对话而不把旧约束再次发送。
- 模型澄清问题保存为待答状态，用户补充交付物时延续原任务。长对话输入由任务状态和有限近期消息组成，不另行逐轮收费总结，不自动跨对话建立记忆。
- 处理中保留发送按钮，另设停止按钮。待处理消息按对话保存，最多 4 条、合计 1,800 字；相邻的条件补充合并为一轮，其他动作按顺序执行。停止、切换到其他对话或重启后，补充保留并提供手动继续入口，不静默执行。超长输入明确提醒并保留原文。
- 新助手消息记录来源版本与引用摘要，重新加载时保留这些消息；无法识别来源的旧助手文本维持原迁移规则。v4 仅增加对话字段，v3 升级沿用原有不重复备份大型记录的规则。消息和队列均在原本地资料库内，不读取或上传本地 Skill 库。

### 具体名称查找修复（v2.43）

- 具体名称放在句首、直接输入名称、使用“叫／名为”等命名句式时，保留完整名称进入精确查找；多词名称不截成最后一个单词。用途与作者请求保持既有路线。
- 精确名称不调用需求规划、媒体搜索或模型候选比较。skills.sh 返回的近似名称在读取正文前排除；内置目录仍需真实正文核验。
- 增加无需登录的公开同名仓库查找，一次名称请求读取一页最多 100 条仓库信息，只对最多 5 个同名、公开、未归档且未禁用的仓库核验根目录及两个固定 Skill 路径，不递归抓取或持续翻页。继续遵守每轮 12 次 GitHub API 与原进程请求预算。
- 同名仓库根目录有可读有效 SKILL.md 时，允许以仓库名找到该 Skill；集合仓库下的无关子 Skill 不继承仓库别名。多个同名对象保留作者供用户区分，未完成核验如实说明，不用相似工具替代，也不承诺公开来源覆盖未发布的本地自建 Skill。

### 名称事实贯穿查找（v2.44）

- 完整连字符或下划线名称与“这个／这份／这款 Skill”等明确类别相邻时，不依赖固定请求句首或中英文空格识别；不得拆成 project 等通用用途词。精确路线及查询由本地规则保护，不允许模型扩写成泛需求。
- 同时给出多个待找名称或只排除名称时，先本地澄清，不发搜索或模型请求；要求完整名称的澄清未解决时不降级为泛搜索，明确换任务可以离开澄清。排除名称不作为正向目标。
- 最终候选也必须符合用户明确的名称、仓库或路径，不能凭官方来源或高使用量绕过身份核对。保留旧的作者、用途、询问口碑路线和已确认的三栏界面。
- 验收包括用户原句 `我找一下vibe-project-foundation-skill这个skill`、组合表达、歧义与否定以及正式安装应用的真实结果和请求计数。免费来源未收录、不可读或受限时仍可能找不到，须如实说明，不承诺任意名称全网必达。

### 模糊需求的目录覆盖与仓库热度（v2.45）

- 搜索接口不可用而详情页仍可读时，场景路线对用途索引匹配的最多四份作品独立读取已知作者路径及目录详情，复用当轮请求与缓存；失败计数仍保留。点名路线不接入这条补充通道。详情页安装量的 K/M 近似值保留原文，资格判断使用保守的舍入区间下界，不伪造精确安装数，也不以 Star 替代使用量。

- 推荐数量继续由已核验且满足能力和品质证据的候选决定，不固定为五个。将已核对来源的独立作者作品补入版本化目录，以可维护的用途别名找到名称，再按完整名称召回目录使用量及真实正文；别名只负责召回，不创造推荐品质。
- 当前补充 Humanizer、no-ai-slop、human-writing、khazix-writer 四份公开作品，目录共 925 项。用途别名与仓库路径属于目录数据，更新脚本重读作者正文核验身份，不把作者名单写成路由分支。不承诺目录或免费搜索覆盖全部作品。
- 每轮仍最多八条查询和十二次 GitHub API。点名单份 Skill 的路线和查询保持原合同，不带入场景别名。简介先证明属于写作／改稿领域，才允许核对最多 8,000 字符的真实作者正文补足用途；API 文档中的例子不能建立写作能力，简介明确否认能力时不得用正文覆盖否认。
- 利用已读取的 Skill 目录页面补齐明确标注的 GitHub Stars，和安装使用量分开。目录只提供 7.3K 等近似值时保存原显示值，不捏造精确整数；没有字段仍显示未知。正文用途以实时作者文件为准，目录摘要不得覆盖作者说明。
- 验收必须包括原模糊需求、超过五个合格结果、四份具名作品的具体去向、热度字段，以及已修复精准原句的正式应用回归；资料不足或不适合时如实说明。

### 明确不做

- 项目级 Skills，包括扫描、导入、展示、安装、跨 Agent 兼容和项目目录管理；信息流式 Skill 市场、排行榜运营、付费推广或个性化广告。v1.1 只提供任务驱动的搜索和可解释候选推荐。
- 跟踪任意分支、固定到某个版本、自动下载、自动更新或自动安装。
- 将 Release 中的非 ZIP 附件或来路不明的文件当作 Skill 安装包。
- 内置 Markdown 编辑器、Skill 创建器、后台自动 AI 安全审查、后台自动生成 Skill 介绍，或由 AI 作出“绝对安全”结论。
- 把公共 API Key、Client Secret 或 SkillBox 共享模型密钥打包进客户端。
- 在 Agnes 不可用时把内容静默转发给 DeepSeek 或其他服务商。
- 团队协作、云同步、Windows、Linux、后台自动同步和应用自动更新。
- 把开发项目迁入 SkillBox 保存位置、自动运行项目构建、自动安装、双向同步或把应用副本改动写回开发源。
- 管理 Agent 插件、MCP、系统内置 Skill 或第三方插件缓存。
- 把 OpenCLI、Chrome 扩展、用户日常浏览器或其登录数据作为发现 Skills 的运行依赖；在当前版本搜索小红书或抖音。

## 4. 信息架构与主流程

### 主导航

- **我的 Skills**：应用打开后的默认页面；展示全局 Skill、唯一来源、已安装 Agent、快速安装操作和 Skill 详情。
- **安装到应用**：用一张可横向浏览的安装关系表批量管理全部 Skill 与全部 Agent。这里服务于跨 Skill 的集中安装和卸载，不承担来源管理、Skill 介绍或问题看板。
- **发现 Skills**：用户用普通语言描述想完成的事情，查看所有通过质量门槛的可解释候选、用户指南、来源知名度和加入前检查，再决定是否从 GitHub 添加。候选数量由真实质量决定，不设展示目标。
- **设置**：使用固定的“设置目录＋当前设置详情”双栏结构。目录只包含“AI 服务、GitHub、存储与记录、操作记录与恢复、隐私与安全”，并直接显示连接、仓库、记录和最近操作等真实状态；不再使用“通用”“数据”等含糊分类，也不使用顶部分段按钮。右侧只处理当前一类任务，SkillBox 保存位置、AI 模型接入、GitHub 私人仓库连接、寻找记录、恢复和清理入口均保留。只陈列但不能操作的说明不占用设置项。

一级导航按用户目标排列为“我的 Skills → 安装到应用 → 发现 Skills → 设置”。前两项是管理已有 Skill 的核心任务；“发现 Skills”是反复发生的附加任务，保留一级入口但排在管理任务之后；设置承接低频配置和安全出口。四个入口收进同一个边界清楚的导航容器，每行高度不低于 44 pt，未选中项也有完整热区、浅底色、边界和悬停反馈。顶部品牌区和底部原有的全局 Skill 管理范围提示用于收住留白，不增加看板、统计、新入口或另一组信息架构。

“最近操作”不占一级导航。它是安装、更新、卸载和删除之后产生的系统记录，不是用户打开 SkillBox 时要完成的独立高频目标。每次操作完成后必须就地展示结果和即时撤销；更早的记录、备份状态及「恢复到操作前」统一从“设置 → 操作记录与恢复”进入。该调整只改变入口层级，不得删除、缩短或弱化事务记录、崩溃恢复、备份和撤销合同。

“添加 Skill”只处理用户已经知道的本地开发文件夹或 GitHub 地址。单个 Skill 的安装关系在详情中快速管理，跨 Skill 的安装关系在“安装到应用”集中管理；两处必须读取和修改同一份 `Assignment`，不能形成两套状态。产品不再设置总览或冲突中心。

发现页保留的是「寻找记录」，不是通用聊天记录：记录只包含这次要解决的问题、后续补充条件、候选元数据和用户选中状态。用户加入第一个候选后，其他候选仍保留，便于体验不合适时再试第二个。点击「开始新的寻找」只创建新任务，不自动删除之前记录；用户可从会话菜单继续任意一条，也可在设置中单条删除、全部清空或在 Finder 中打开保存位置。不提供通用问答、文件上传、办公助手或无限期个人记忆。发现页只能建立 GitHub 来源，不能绕过安装快照直接写入任何应用目录。

### 界面语言

- 主流程面向不熟悉文件系统的用户，先说“会发生什么”，技术原因放到可展开的第二层。
- 用户界面不使用「中央仓库」「中央原件」「母版」或「同步」；分别表达为「来源」「当前安装版本」「已安装副本」「安装」「更新」和「卸载」。
- 「指纹」改为「内容校验码」并只放在「Skill 详情」中；面向用户时把「事务」写成「操作记录」或具体动作结果；「接管」改为「让 SkillBox 管理这份内容」。
- 「Skill 介绍」与「文件详情」是右侧详情区的两个等宽页签；每个页签整块高度不低于 44 pt 且全部可点，不得只把文字本身当热区。「文件详情」展示完整文件目录、主 `SKILL.md` 的预览按钮和内容校验码；目录读取不得阻塞主界面。
- “我的 Skills”中的介绍入口统一使用中性产品语言“AI 介绍”和“连接 AI”，不把入口命名绑定到 Agnes、DeepSeek 或其他单一服务商；具体服务商名称、模型和 Key 只在“设置 → AI”中展示和管理。
- 所有可点击控件都必须提供悬停、按下和禁用反馈；「查看 Skill 详情」的整行标题区域都可点击，不能只依赖小箭头。
- 普通成功结果只做短暂轻提示，不得常驻或遮挡输入与主操作；进行中状态放在顶部工具区，需要用户处理的问题才在相关内容附近保留。
- 失败只进入错误提示，不得同时复用成功轻提示，更不得显示绿色对勾。新错误出现时必须立即清掉上一条成功提示。
- 发现详情与“我的 Skills”使用同一套 AI 整理说明，顺序固定为「作用 → 适用场景 → 使用流程 → 启动提示词」。文字面向会正常使用电脑、但不熟悉 Agent Skill 的普通成年人：要自然、准确、不幼稚，不使用「赋能」「提升效率」「帮你梳理」「一站式」「特色和技巧」等空泛表达。「作用」先说用户要交给它什么，再说它会做的关键动作和最后交付的真实内容；「适用场景」写 2 至 4 个具体的开始时机或眼前麻烦，让用户能判断自己当下是否该用，不重复抽象收益。
- 「使用流程」是 Skill 介绍的主体，获得比其他三块更高的信息完整度优先级。它从用户发出启动话开始，按真实顺序写到拿到结果；需要先补充信息的 Skill，要说清会问哪类问题。作者材料明确写了选择项、可选值、指令或回答格式时，必须保留原名、顺序和具体格式，必要时给出一个简短回答示例；然后说清用户选择后 Skill 会继续做什么、最后交付哪些文件或内容。只有一个动作的 Skill 不强行拆步。介绍不展示 Agent 内部规则、脚本实现或安全检查。
- 「启动提示词」只负责可靠触发 Skill 并表达用户的大致目标，要简短、自然、可一键复制。默认不替用户预选答案，不额外锁定流程、方法、语气、数量或输出格式，让 Skill 保留原生询问和执行过程；只有触发必需的条件才可写进启动提示词。
- AI 优先读取真实 `SKILL.md`，并可结合 `README.md`、`agents/openai.yaml`、`references/` 与 `agents/` 内的文本说明，以及 GitHub 作者提供的仓库简介。仓库简介与 Skill 本体冲突时以 Skill 本体为准；不得把内部规则、文件结构、脚本实现、安全检查或专业黑话写进用户说明。
- 资料不完整时，AI 可以从 Skill 的真实用途、触发条件和工作步骤中归纳用户能确认的体验，不得虚构能力、效果或产品承诺。未配置 AI 或生成失败时显示基于确定性材料的简短保底说明，不展示“作者暂未说明”等无帮助占位话。
- 发现候选的详情只显示当前在线核验过的作者材料，不因打开、切换或深挖候选自动生成 AI 使用指南，也不把候选比较中的模型文案带入详情。候选加入“我的 Skills”后，只有用户主动点击“获取 Skill 介绍”才调用所选 AI；结果按 `Skill ID + 内容指纹 + 提示词版本` 保存。Release、默认分支或本地更新导致内容指纹变化时，旧介绍不再当作当前结果。
- 提示词版本升级时，同一 `Skill ID + 内容指纹` 下已保存的完整说明作为重新整理失败或 AI 不可用时的兼容保底；不得因提示词版本号不同，就把原本已有的“适用场景、使用流程、启动提示词”整体降级成只剩一句作用。内容指纹变化后仍必须失效。
- 不得把 `description` 中 `Use when` 后的原始触发片段直接当成用户说明；YAML 多行描述必须转成正常可读文字，旧的中央记录在打开新版本后自动修复。
- 未启用 AI 时，SkillBox 不生成或猜测使用方法，不得把「执行步骤」「安全检查」「内部规则」等给 Agent 的指令当成用户教程。用户主动选择“AI 帮我看懂”后，AI 可基于作者材料补充归纳，但每一项结论都必须能回到真实文件证据，并明确标为 AI 辅助说明。
- 「我的 Skills」首先用于查看已有 Skill。必须支持搜索，并能按用户创建的文件夹、本地来源、GitHub 来源和已安装状态筛选；文件夹筛选直接复用 `OrganizationState`，没有创建文件夹时不展示虚假的分类。列表行展示 Skill 名称、醒目的唯一来源图标和已安装 Agent；来源和安装信息各占固定位置，不随 Skill 名称长短左右跳动。
- GitHub 来源使用可直接识别的 GitHub 章鱼猫标志，本地来源使用蓝色实心文件夹；不存在应用导入来源。悬停说明与 VoiceOver 名称统一为「GitHub 来源」或「本地开发文件夹」。列表大小只计算当前安装快照，不重复计算应用安装副本、GitHub 下载缓存、历史版本或备份。
- 同一文件夹内的 Skill 移动超过 `8 pt` 后才进入拖动。进入拖动后，原卡片从列表排位中变为一块等高的空占位槽，卡片本体作为独立浮层保持蓝色选中外观并只在列表纵向轨道内跟手；指针跨过相邻行中线时，占位槽移动到预计松手位置，其他卡片在约 `180 ms` 内实时让位，使列表始终预览松手后的最终顺序。有效落点时，占位槽底部显示一根 `2 pt` 系统蓝线；落点线不绑在浮动卡片上，不得被卡片阴影或让位动画遮挡，也不显示端点或文字胶囊。指针离开有效列表、取消、松手、窗口失焦、页面消失或被拖对象刷新移除时，统一拖动会话必须回到空闲状态，不留蓝线、空位、重影或浮层。精确落点文字只供 VoiceOver 使用；跨文件夹移动继续使用右键「移动到」。开启「减少动态效果」时保留占位槽和落点线，取消换位动画。
- Skill 列表行右键菜单只提供「移动到」已有文件夹和「删除 Skill…」。删除必须复用现有可恢复流程：无受管理副本时二次确认后移入 macOS 废纸篓；有受管理副本时先让用户选择保留副本或查看全部卸载清单，不得绕过取消、预览与恢复出口。
- 「我的 Skills」页头只保留一个高强调的「添加 Skill」主操作；更新检查和私人仓库连接使用统一的次级样式。全局安装卡分开说明与操作，主安装按钮在常用窗口宽度下必须单行显示。

- 主候选区只显示通过受限精品门槛的“推荐”。候选必须能读取真实 `SKILL.md`、用途符合当前目标、来源可追溯，且没有归档、不可下载或本地阻止事实。候选名称只能帮助召回，不能独自建立推荐资格；相关性必须由已核验的 Skill 级摘要建立。否定识别必须同时考虑 `No`、`lacks`、`is absent`、`没有`、`缺少`、`未实现`等词族与具体能力的前后作用范围，不得因同句中另一项能力受限而误伤已明确支持的能力。独立本地品质证据只来自作者官方来源、至少 500 次 Skill 级安装量，或至少两位可区分的社区推荐者；近期维护与完整操作说明用于排序和判断可用性，不能单独把作者自己的新项目抬成强推荐。平台收录只帮助召回和末端排序，不能形成品质证据。跨语言召回由读取候选正文前的模型查询规划和免费本地扩词完成。只有已经通过本地相关性与独立品质门槛的候选才可进入模型比较；每次寻找或继续深挖只把本地排序最高、尚未送评的 6 个候选交给模型一次比较，输入只包含候选必要字段、受限正文和本地绑定后的社区作者数、平台数与归一热度，不发送媒体标题、作者原文或无关上下文。模型推荐必须附带正文原句，本地再独立核对原句存在、表达的不是否定能力、与任务相关且候选材料不含已知的评级干预语句。核验后的模型结果只可调整这些本地合格候选的末端并列顺序，不能新增、隐藏或降级推荐资格；未送评的已核验精品候选继续保留，下一次深挖从后续 6 个开始。多 Skill 宿主仓库的 Star 不得让子 Skill 进入精品门槛。发现结果只能说明公开证据状态；完整包的内容、权限与安全阻止必须在加入预览中重新核对。
- 上述精品门槛只约束场景发现与混合查找；精确查找按用户点名对象返回已经核验且没有阻止事实的真实结果，不因热度或说明篇幅不足而消失。
- 用户限定作者时，“某人的写作 Skill”“某人那个写作的 Skill”和作者名两侧空格都保留作者身份。已知中文别名解析为真实 GitHub 账号，仅按账号查询目录、skills.sh 和 GitHub，跨该作者仓库寻找；此定位阶段不扩成无作者限制的媒体搜索。先按仓库所有者过滤再消耗正文核验名额，返回和排序再检查作者一致。作者身份只证明归属，不能建立用途或品质；用途匹配时移除作者词，不能因简介提到作者或另一份 Skill 而误推。未知中文作者不猜测 GitHub 身份；现有预算和精品门槛不变。
- 完整仓库地址先读取该仓库的公开 `SKILL.md`，成功时不等待 GitHub 登录、不调用搜索或仓库资料 API；完整文件地址保留分支和路径，根目录 `SKILL.md` 不得退化成未知路径。公开直读失败后再走原有 API 核验；未给定路径且根目录不存在时才尝试仓库内查找，整个直接核验阶段最多等待 20 秒。普通句子里的 `PPT/Excel`、`PDF/Word` 不得当成仓库地址。“最好支持中文”“不要收费”等补充保留原任务并累积条件，明确的新查找使用新目标。查询条件只说明用户要求，不得冒充已经核实候选支持。
- 零推荐且公开来源未核验完时，主结果显示“暂时无法完成核验”，已知限流时直接显示可重试时间；不能把外部服务不可用写成 Skill 不存在。重试时间以可选字段保存在当前运行记录，兼容旧记录；该字段不提高存储上限。
- 一次寻找或继续深挖的全部候选来源共用请求上下文：相同地址、身份和响应格式的进行中或已完成请求只发一次；正文仅在本轮内存中共享，最多 128 项和 8 MiB，结束即释放。每轮 GitHub API 实际请求（含自动跳转）最多 12 次，匿名搜索在已知剩余额度不高于 12 次时提前停止，为用户加入留余量；本应用进程内的匿名发现请求另受滚动一小时 36 次上限约束。共享出口的其他应用可能消耗余量，因此不承诺保留额度一定可用。预算耗尽保留已核验结果并明确记录，不冒充 GitHub 已限流或完整搜索。覆盖详情记录本轮真实请求、复用和预算阻止计数，不保存地址或凭据。
- 媒体提供的精确名称或仓库逐层走目录、skills.sh、GitHub，仅将前层未核验到的对象传给后层；普通多来源召回仍可并发。skills.sh 首先读取公开正文，仓库资料只在定位文件需要时请求；正文直读成功不为热度字段额外消耗 API，缺失热度如实显示。GitHub code search 没有可用身份时不发送必然失败的匿名请求。加入时原有版本、来源和完整包安全核验保留。
- 排序先看任务和交付物是否直接匹配，再看独立社区作者数、跨平台覆盖和平台内归一后的热度信号，然后看 Skill 级安装量、作者官方来源、最近维护与说明完整度；仓库 Star 只能作为独立单 Skill 仓库的末端并列参考，不参与精品准入。热度不能弥补用途不匹配；尚无公开使用或多人推荐证据的候选可以继续召回和核验，但只留在非推荐证据中，也不消耗模型比较上下文。用户要求“去 AI 味、改得更自然”时，只检测或打分但不负责改写的 Skill 必须判为能力错配。
- 改写候选如果只服务学术论文或芬兰语等某一特定语种，而用户没有点名该领域或语种，则判为能力边界错配，不进入推荐。中文改写需求中，明确支持中文或真实正文含中文用法的同等候选优先。
- 发现链路不得依赖付费搜索、付费向量库、付费 Embedding 或 SkillBox 服务端。应用包中的固定新增代码与目录目标仍小于 1 MiB；OpenCLI 已退出运行依赖，唯一可选的免费媒体工具 `yt-dlp` 在当前 Mac 实测约 35.4 MiB。`yt-dlp` 必须忽略本机配置、禁止读取浏览器 Cookie、禁止读取其他 Cookie 并关闭磁盘缓存，只获取公开元数据。工具缺失时媒体来源平静降级，原有目录、skills.sh 与 GitHub 搜索仍须可用。不保存视频、字幕、文章正文、平台 Cookie、完整公共仓库镜像或本地向量索引。每个公开批量来源单轮最多将 1,000 个候选带入合并，每份候选正文证据在进入搜索模型前最多 8,000 字符，避免一次运行无界占用内存。内置目录的远端正文内存缓存最多保留 128 份、合计 8 MiB，6 小时后过期；skills.sh 的仓库资料与正文缓存分别最多保留 128 和 256 项。寻找记录只为最需要的 96 个候选保留最多 8,000 字符的正文摘要，其余候选保留元数据但不重复存正文；每个候选最多另存 5 条已绑定媒体证据元数据，每轮最多另存 8 条未绑定讨论元数据，典型新增小于 8 KiB，仍计入原有 64 MiB 总上限。全部寻找记录（包括旧记录迁移产生的备份）合计最多 64 MiB，达到后停止新增并请用户自行清理，不静默删除旧记录。只有用户选择的模型调用可能产生费用，Agnes 免费方案和用户自备的其他模型均沿用现有配置。
- 每轮只新增路由类型、最小精确实体和路由结果，持久化增量必须小于 2 KiB；不因路由增加新数据库、索引或缓存，不上调原有 64 MiB 寻找记录总上限。
- 推荐数量不设固定上下限。所有真正通过精品门槛的候选都显示，可能为零个、一个或多个；没有精品时明确说明，不用水货补数量。来源限流或尚未查完时保留已核验结果并提供“继续深挖”。
- 主候选区、选中状态和右侧详情必须使用同一份“推荐”列表；推荐为空时不得选中或显示被折叠的其他候选。只有实际存在推荐时，结果卡才可使用绿色成功图标；零推荐、搜索失败或中止都使用中性或留意状态。只要已有推荐，来源降级不再把整轮写成“未完成”，而是折叠为覆盖详情。
- 发现页大窗口采用对话、候选、详情三栏。对话栏约 380 点且始终保留；中栏标题动态显示“推荐 N 个”，让用户知道这是全部通过门槛的数量，标题下明确“达到质量门槛的全部保留，不凑数”；右栏标题固定为“Skill 详情”。中等窗口选择候选后在同一内容区进入详情，不得通过裁掉聊天栏或输入控件适配宽度。
- 输入区分为可增长至三行的完整输入框与底部操作行；模型选择和发送按钮不得与输入文字挤在同一窄行。候选行不堆叠指标。详情区始终并列展示“Skill 使用量”和“GitHub 仓库热度”，分别说明属于单个 Skill 与整个仓库；某项取不到时显示“暂无公开数据”，不得隐藏字段或把未知当成零。
- 发现页三列标题使用相同高度和同一条水平分隔线；左栏“新建寻找”使用位于记录图标左侧的加号。Skill 详情正文与“我的 Skills”统一使用“作用、适用场景、用户视角使用流程、启动提示词”四块说明；仓库介绍与技术证据默认折叠。
- 没有可核对的候选专属使用介绍时，展示作者原始用途、完整说明链接和应用自身的三步使用指引：核对并加入、安装到 AI 应用、在该应用提交具体任务。启动提示词必须保留待用户填写的任务，不编造候选承诺。此指引仅供界面即时展示，不作为 AI 分析或候选已验证能力保存。保持既有三栏布局；前台验收使用能同时显示对话、列表、详情的宽窗口。
- 推荐结果只使用“高度符合、来源可靠、较多人使用、最近仍在维护、需要了解、需要确认”等具体标签。安装量、仓库 Star、作者身份和 AI 判断都只是独立证据，不得合成为制造精确幻觉的单一百分制评分。
- GitHub Star 必须显示为“所在仓库 · 12.4k Stars”或“12.4k 仓库关注”，并附数据更新时间。一个仓库包含多个 Skill 时，各 Skill 可以共享仓库知名度事实，但不得描述为该 Skill 独占的 Star；非 GitHub 来源不显示 Star。
- 候选详情先回答“能帮什么、为什么适合你、来源如何、安装前需要了解什么”；点击“加入我的 Skills”后必须建立 GitHub 来源，并进入下载、完整性、安全解包和安装快照确认流程。
- 安全结论统一为“未发现明显问题、需要了解、需要确认、无法添加”。不得显示“绝对安全”；每条需要了解或确认的结论都必须展示文件、位置、命中内容和普通语言解释。
- 设置的“AI 服务”支持 Agnes、DeepSeek、Kimi、MiniMax、GLM 和自定义 OpenAI 兼容接口，用户自行申请 API Key。Agnes 连接固定用于“我的 Skills”中的 Skill 介绍；“发现 Skills”可由用户另选已连接服务。两者共用密钥管理、连接测试和删除能力，不共用自动触发状态。
- 用户点击“获取 Skill 介绍”就是当次发送授权，不再叠加第二个确认弹窗。按钮的悬停说明必须明确“点击后才会发送”。每次只发送脱敏后的 Skill 名称、描述、`SKILL.md`、`README.md`、`agents/` 与 `references/` 内有上限的文字；不发送脚本、二进制、图片、密钥、绝对路径或完整文件夹，也不运行 Skill。
- 一个服务商失败后只显示“改用其他服务重试”的明确操作，不得自动更换数据接收方。所有请求都可取消，取消必须穿透 AI、多来源协调器和备用端点，不得被转成普通网络失败后继续请求。失败不得改变 Skill 的本地风险或安装状态。

### 首次添加与安装

1. 解释 SkillBox 只管理跨项目使用的全局 Skill，并且来源只能是本地开发文件夹或 GitHub。
2. 自动识别可用 Agent 全局安装位置，但不扫描或导入其中的 Skill。
3. 用户选择本地开发文件夹或输入 GitHub 仓库；SkillBox 校验结构、生成安装内容和静态风险报告。
4. 用户选择要安装到哪些 Agent。
5. SkillBox 冻结一次不可变安装快照，展示完整安装预览。
6. 用户确认后把同一快照安装到所选 Agent；已有同名内容保持不动，除非用户查看差异并明确允许接管或替换。

### 日常安装、更新与卸载

1. 用户在某个 Skill 的详情中调整要安装的应用。
2. `SyncPlanner` 只读比较安装快照、目标内容和所有权记录；在用户确认前，不得持久化安装选择。
3. 当前交叉点直接弹出单项确认窗。若已有同名 Skill，必须明确告知「内容相同」或「内容不同」；不同时展示新增、修改和移除的文件摘要。
4. 用户确认后只持久化并执行当前这一项，不夹带页面中的其他待处理项；写入前创建备份，完成后生成操作记录。
5. 批量全部安装与卸载使用独立总清单预览。预览期间的安装选择、接管和替换授权只存在于当前内存草稿；点击「取消，不保存」必须还原到打开预览前的持久化状态，不写入任何应用文件夹。
6. 用户确认批量预览后才持久化草稿，并基于最新磁盘状态重新计划再执行。预览后目标内容变化时，旧授权不得继续覆盖新内容。
7. 失败时恢复本次操作已改动的目标；成功后允许从操作记录撤销。「恢复到操作前」先展示受影响位置和每项回退结果；打开或取消预览不改文件，只有再次显式确认才执行恢复。

## 5. Agent 路径合同

界面名称、内部适配器身份和磁盘目录是三件独立的事。品牌名称变化不得顺带修改稳定 ID、旧分配关系或真实目录。

| 内部适配器 ID | 界面显示名称 | 默认全局目标目录 |
|---|---|---|
| `codex` | GPT | `~/.codex/skills` |
| `claudeCode` | Claude | `~/.claude/skills` |
| `workBuddy` | WorkBuddy | `~/.workbuddy/skills` |
| `zcode` | ZCode | `~/.zcode/skills` |
| `kimiCode` | Kimi Code | `~/.kimi-code/skills` |
| `cursor` | Cursor | `~/.cursor/skills` |
| `hanaAgent` | HanaAgent | `~/.hanako/skills` |
| `pi` | Pi | `~/.pi/agent/skills` |
| `deepSeekHarness` | DeepSeek Harness | `~/.dsh/skills`，或已解析的 `$DSH_HOME/skills` |
| `trae` | Trae | `~/.trae-cn/skills` |

- OpenAI 已把 Codex App 合并进 ChatGPT 桌面应用，但官方仍把 Chat、Work、Codex 作为不同视图。SkillBox 按用户要求在产品界面显示「GPT」和 ChatGPT 官方图标；现有适配器 ID `codex`、固定目标 UUID、`~/.codex/skills` 路径、Assignment 与 ManagedInstallation 关系全部保持不变。显示名称变化不得触发重新检测为“新应用”。
- Kimi Code 的当前官方用户级专属目录是 `$KIMI_CODE_HOME/skills`，默认 `~/.kimi-code/skills`。旧实现中的 `~/.kimi/skills` 只作为历史错误路径识别，不再用于新目标。迁移时先只读检查旧路径是否存在受管理副本并展示清单；没有用户确认不得移动、复制或删除其中内容。
- DeepSeek Harness 先解析 `DSH_HOME`；未设置时使用 `~/.dsh`，全局目标为其下的 `skills`。环境变量解析结果必须保存为规范化目标路径，预览与执行前重新核对，不能把字符串 `$DSH_HOME` 当成文件夹名称。
- Trae 本合同指 TraeCode 桌面产品的用户级全局目录 `~/.trae-cn/skills`。TraeCode CLI 自身的 `~/.traecli/skills` 属于另一个适配器候选，不得和 Trae 共用一个目标身份。

- 内置应用的标准 Skills 目录不存在时，视为本机尚未安装或尚未正确初始化该应用；SkillBox 必须提示用户并阻止部署，扫描、预览和执行阶段都不得代为创建目录。
- “管理应用”负责决定哪些应用列出现在安装表中，并允许用户拖动排序。移出内置应用只隐藏该目标，不删除内置定义、电脑应用、目录、Assignment 或 ManagedInstallation；用户可以随时加回来。
- “管理应用”提供「恢复全部预设应用」。它一次找回所有被移出的十个默认内置应用，只改变显示列表，不创建目录、不安装或卸载 Skill、不删除自定义应用，也不重排当前已有列；找回的应用按默认清单顺序追加到现有列末尾。安装表中的「恢复默认顺序」只负责列排序，两者必须使用完整名称，不能共用含糊的「恢复默认」。
- 自定义安装位置只能由用户通过目录选择器选择一个已经存在的目录，SkillBox 不代为创建。添加时必须填写用户看得懂的应用名称，内部生成稳定目标 ID；名称以后可以改，ID 不随名称变化。
- 对内置 Agent 的安装判断必须逐列读取上表中的专属目录。即使某个 Agent 实际还会尝试读取其他品牌目录或共用目录，SkillBox 也不探测、不展示、不据此改变安装状态；用户在矩阵中看到的关系始终与该 Agent 专属目录一一对应。
- 自定义目标由目录选择器添加，必须有明确显示名称。磁盘根目录、用户主目录、SkillBox 数据根目录等宽泛或递归危险路径不得作为目标。
- 自定义目标支持改名、更换目录和移除。更换目录前必须确认旧目录没有受管理副本；仍有副本时先让用户选择“先卸载副本”或“保留文件并停止管理”。移除目标本身不得删除应用或目录。
- 内置应用从安装表移出时同样检查受管理副本。没有副本可直接隐藏；有副本时必须让用户明确选择“先卸载副本”或“保留文件并停止管理”，不得用一个含糊的删除按钮同时完成两种结果。

## 6. 数据与文件合同

中央数据根目录：`~/Library/Application Support/SkillBox/`

```text
SkillBox/
├── catalog.json
├── targets.json
├── assignments.json
├── installations.json
├── organization.json
├── source-state.json
├── library-state.json             # 上述核心状态的完整原子提交点
├── ai-settings.json              # 不含 API Key
├── AIReviews/<skill-id>/<fingerprint>/...
├── DiscoveryCache/               # 可清理的公开搜索缓存
├── Library/<skill-name>/content/...
├── SourceCache/                  # 只用于临时下载与比较，可随时重建
└── Transactions/<transaction-id>/
    ├── manifest.json
    └── backups/...
```

- JSON 顶层必须包含 `schemaVersion: 4`，使用临时文件加原子替换写入。`library-state.json` 是核心状态的唯一权威提交点；分项 JSON 作为可读兼容镜像先写，完整状态最后原子提交，启动时优先读取完整状态，避免进程中断后拼接出不同代际的数据。旧版只有分项 JSON 时必须无损加载并生成完整状态。Schema v1/v2/v3 数据在内存中迁移后原子写回，不得当作损坏数据丢弃。
- `SkillRecord`：稳定 UUID、规范名、显示名、描述、指纹、来源、风险摘要、中央内容路径。
- `AgentCatalogEntry`：稳定适配器 ID、当前界面名称、官方图标资源、默认路径解析规则和是否进入新用户默认列表。品牌名称只属于展示层，不得被当成路径或数据迁移依据。
- `AgentTarget`：稳定 ID、适配器 ID、自定义显示名、规范化路径、是否显示在安装表、用户排序、检测状态和写入状态。内置目标的隐藏状态与磁盘可用状态必须分开保存。
- `Assignment`：Skill 版本、目标、安装目录名和期望状态。
- `ManagedInstallation`：目标路径、Skill ID、上次部署指纹、事务 ID 和时间。
- `SyncTransaction`：预览操作、备份位置、执行结果、错误和撤销状态。
- `GitHubSourceState`：仓库稳定 ID、公开或私人属性、Skill 子目录、跟踪方式、当前版本、Commit SHA、可安装内容身份、Release ID、Asset ID、Asset 名称与 SHA-256 摘要、安装规则、GitHub 条件请求标记、上次检查时间、本次连接问题、可重试时间、忽略版本和检查开关。任何凭据都不得进入该数据。
- `GitHubPackageRecipe`：绑定仓库稳定 ID、规范仓库名、跟踪方式、Skill 子目录、规则来源、精确包含路径、已经确认过的顶层路径和确认时的版本。规则只描述“哪些内容可以安装”，不得保存凭据或临时下载路径。
- `LocalSourceState`：Skill ID、用户选择的项目根位置与持久访问书签、Skill 相对位置、当前纯净内容指纹、可用更新指纹、最近核对时间、来源状态、顶层内容身份和本地安装规则。来源路径与书签只保存在本机，不进入日志、AI 请求或操作说明。
- `LocalPackageRecipe`：Skill 相对于项目根的位置、精确包含路径、已经确认过的顶层路径和规则版本。`SKILL.md` 以及被其明确引用的本地内容必须包含；新增可能参与运行的路径、已选路径消失或引用关系变化时暂停更新并要求重新确认。
- `AIProviderConfiguration`：服务商、显示名称、基础地址、模型名称、启用状态、能力探测结果、超时和输入上限。只保存钥匙串引用，不保存 API Key。
- `AIReviewRecord`：Skill ID、内容指纹、任务类型、提示词版本、服务商、模型、时间、结构化结论、证据和局限。不得保存模型思维过程或未脱敏的原始请求。
- `SkillUsageGuideRecord`：已加入“我的 Skills”的 Skill ID、内容指纹、提示词版本、生成时间，以及作用、适用场景、用户视角使用流程和启动提示词。只有用户主动点击获取介绍时才生成；发现候选不生成或沿用该记录。
- `DiscoveryMessage`：只保存用户原话、正文和时间；不保存候选相关的模型回复、临时进度、系统故障、模型思维过程或完整原始响应。
- `DiscoveryRunState`：本轮的理解、召回、核验、评估、完成、部分完成或失败状态；应用启动时只有明确发现上一个进程留下的运行态记录才标记为意外中止。
- `AIInvocationDiagnostic`：只保存服务商、模型、HTTP 状态、结束原因、响应长度、服务端请求 ID、请求字节数、服务商返回的输入/输出 Token 数、耗时、尝试次数、输入项数和脱敏错误类别；不得保存 API Key、用户正文、思考过程或完整原始回答。
- `DiscoveryIntent`：当前目标、必要条件、偏好和排除项。筛选反馈更新当前意图，新场景替换当前目标。
- `DiscoverySearchRun`：本轮原始查询、AI 补充查询、来源失败数、查询失败数、触及上限的查询数、候选核验失败数、召回与送评候选数、候选快照、推荐分层、运行状态、系统提示和脱敏诊断。
- `DiscoveryCandidateEvidence`：Skill 级说明、公开安装量、仓库资料、真实文件来源、“作者官方维护／平台收录”级别、核对时间和证据状态。仓库简介必须单独保存。
- `SkillDiscoveryCandidate`：公开来源、Skill 标识、面向用户的用途、安装量、仓库级 Star、Star 获取时间、维护资料、内容身份、推荐层级、限制和安全摘要。搜索缓存可随时删除，不参与受管理 Skill 状态。
- `Library/<skill-name>/content` 保存当前不可变安装快照，不保存 GitHub 仓库包装。完整源码只允许存在于明确的本地来源、可清理的临时缓存或事务证据中，不参与安装指纹。
- 本地开发文件夹或 GitHub 是唯一来源。`Library/<skill-name>/content` 只保存规则选中的可安装内容；来源丢失时保留历史安装快照与现有应用副本，但必须重新关联原类型来源后才能发布新版本。
- 安装快照文件夹优先使用可读的规范名称，例如 `Library/vibe-project-foundation/content`。同名来源必须在添加时阻止或由用户选择替换现有来源，不再创建多个平级同名主记录；旧 UUID 或同名多记录为无损迁移保留，不能继续扩大。
- “我的 Skills”中的单个 Skill 支持“安装到全部可用应用”和“从所有应用卸载”；两者都先生成安装预览，再由用户确认执行。
- 删除受管理 Skill 前必须确认；仍存在由 SkillBox 管理的安装副本时，用户可选择「保留应用中的副本」或「全部卸载并删除」。前者保留各应用目录中的现有副本并解除 SkillBox 管理关系，不读取、改写或删除这些副本；后者必须先展示全局卸载预览，只有已确认的卸载事务完成后才能删除来源关联和安装快照。
- 上述两种清理只作用于当前 `SkillRecord` 及其受管理副本；其他同名记录、其他来源副本和未受 SkillBox 管理的文件不得被连带处理。仍存在且由当前记录独占的中央内容移入 macOS 系统废纸篓，SkillBox 不在自身数据目录继续保留第二份长期删除备份；旧版 `Deleted/` 中已存在的内容在升级后迁入系统废纸篓。移动前必须先持久化删除事务、原元数据和内容指纹；事务期间可保留一份只用于崩溃恢复的临时副本，提交成功后立即删除。
- 删除完成后在界面中提供即时「撤销」；恢复时从系统返回的实际废纸篓位置取回内容，并同时还原分类、GitHub 来源状态和仍安全适用的待安装选择。撤销恢复也必须在移动内容前持久化运行中事务；若应用在移动后、状态提交前退出，下次启动应把内容安全退回废纸篓并记录回滚结果。用户已经清空废纸篓时必须明确失败。若中央内容早已缺失或路径与另一条记录共享，只清理失效元数据，不创建空备份、不提供虚假的内容撤销。若「只清理主 Skill」时保留的应用副本内容指纹未变化，撤销可重新接管其原管理关系；若副本已变化，只恢复中央 Skill，不覆盖应用中的现有内容。
- Skill 分类与顺序使用独立的 `organization.json` 保存，不改名、不移动来源或安装快照目录，也不改变安装关系。
- 用户可以新建、重命名、删除分类文件夹，将 Skill 拖入文件夹或拖回“未分类”，并自由调整文件夹和同组 Skill 的显示顺序。已保存的空分类仍须在列表中显示数量 `0`，保留重命名和删除入口；搜索或筛选只过滤 Skill 行，不得让分类变成只能在右键“移动到”菜单中看到的隐藏记录。
- 删除分类文件夹只取消其中 Skills 的分类并移回“未分类”，不得删除 Skill 原件或 Agent 安装副本。

## 7. 指纹、所有权与写入安全

- SHA-256 指纹覆盖规范化相对路径、文件内容、POSIX 权限和软链接目标；遍历顺序固定。
- 扫描遇到有效 Skill 根后不再把其内部 `SKILL.md` 当成独立 Skill。
- 添加与更新时只读来源并冻结安装快照；向 Agent 安装采用实体复制，不使用软链接。
- 写入前把目标当前内容复制到事务备份，在目标同级暂存目录完成复制和指纹复核。替换现有目录时使用同卷原子交换，交换后核对被换出的真实旧内容仍等于用户确认的指纹；不一致时立即交换回去并停止。移除时先把目录原子移到唯一保留位置，核对后再删除。自动恢复或回滚前必须再次确认现状仍等于事务记录的操作前或操作后指纹；出现更新的外部改动时停止，绝不覆盖。
- 已存在、未被 SkillBox 管理且内容不同的同名目录必须阻塞。用户只能显式选择保留或用来源生成的安装快照替换。
- 未被 SkillBox 管理的同名目录必须返回中央与目标两份真实指纹，不得用空值推断内容相同。指纹相同时可由用户确认让 SkillBox 管理；指纹不同时，替换授权必须绑定到用户预览的目标指纹。
- 只有带所有权记录且当前指纹仍等于上次部署指纹的目标，才能自动更新或移除。
- 目标被外部修改后标为“外部改动”，同步与撤销都不得静默覆盖。
- 只有检测状态为“已找到”且现有目录可写的应用才能接收新部署；历史选择和过期预览不得绕过这条限制。
- 备份保留至少 30 天且至少保留最近 10 个事务；自动清理不得删除仍可撤销的最新事务。

## 8. 本地风险报告

- 校验 `SKILL.md`、Frontmatter 和完整文件清单。
- 检查可执行权限、脚本、二进制、超大文件、软链接、路径越界、网络下载、提权、删除、凭据访问和动态执行模式。
- Markdown 中的命令说明与可执行脚本中的真实行为分开呈现。
- 风险分级的完整结果始终保留在本地；普通信息和留意项不打断主流程，只有 `high` / `blocked` 级别进入面向用户的安装前确认。
- `high` 级提示必须有可直接作出选择的「查看并确认」入口；用户暂不安装时不保存确认。确认只保存本地摘要，并同时绑定 `SkillRecord` ID、当前内容指纹和稳定风险证据；应用重启后仍有效，内容或风险证据变化后自动失效并重新询问。
- 确认完成后，列表的待处理标记与详情的大幅警示必须同步收起，转为可重新查看的紧凑「你已了解这项内容」状态。`blocked` 级不允许通过确认解锁。
- 删除命令必须按作用范围分级：删除临时目录或变量指向位置默认显示为“请留意”，并展示命中的命令；直接指向根目录、用户目录等宽泛位置才显示高风险。普通提示不得使用红色警报图标。
- 越界软链接、路径穿越和超过导入上限直接阻止导入；其他高风险项需要二次确认。
- GitHub 下载上限：10 MiB 压缩数据、25 MiB 解压内容、1000 个文件。
- 下载上限必须在网络流读取期间生效，不得等整个文件进入内存后才判断。
- Release ZIP 旁边存在同名 `.sha256` 时必须自动校验；校验错误直接阻止导入。更新记录同时绑定 Release ID、Asset ID 和已验证的 SHA-256。
- `.github/workflows/*.yml` 和 `.yaml` 中仅用于 GitHub Actions 任务的 `${{ github.token }}` 或 `${{ secrets.GITHUB_TOKEN }}` 显示为“仅说明”，并明确该文件不会在本机安装时自动运行。本地脚本读取令牌、访问凭据目录、输出令牌或发送到外部网址仍保持高风险。
- 安全审查分为来源、内容、权限和上下文四层。来源检查作者、仓库、版本和维护状态；内容检查全部安装文件；权限归纳文件、命令、网络和凭据范围；AI 只对本地证据做上下文复核。
- 本地扫描必须覆盖未知网址、外部发送、凭据目录、浏览器数据、动态执行、混淆或编码载荷、提权、系统目录修改、未声明依赖和宽泛文件操作。关键词本身不能直接等于恶意，必须结合文件类型、调用链、目标范围和数据流分级。
- Skill 文本属于不可信输入。AI 请求不得启用工具调用、外部网址访问或代码执行；Skill 中要求忽略系统规则、隐瞒风险或伪造结论的文字一律作为待分析资料，不得成为控制指令。
- AI 结论中的文件路径和行号必须在本地重新验证。引用不存在、输出结构损坏、内容被截断或无法核对时丢弃该条结论；不得用无法验证的 AI 文案阻止或放行安装。
- 报告必须明确：静态检查只能提供证据和提示，不能保证 Skill 绝对安全。

## 9. 技术路线与公开接口

- Swift 6、SwiftUI、macOS 15+、arm64。
- 核心行为放入纯 Swift 模块并通过协议隔离：`AgentAdapter`、`SkillScanner`、`SourceProvider`、`RiskAnalyzer`、`SyncPlanner`、`SyncExecutor`、`SkillDiscoveryProvider`、`AIProvider`。
- `DiscoveryRequestRouter` 先从用户原话和上轮已确定目标中提取链接、仓库、路径、Skill 名和作者，`RoutedSkillDiscoveryProvider` 再只调用该路由允许的来源。精确查找不调用 `planDiscovery` 或 `evaluateCandidates`；场景与混合查找才可在路由固定后使用模型补充查询。
- `AIProvider` 的发现接口分为 `planDiscovery` 与 `evaluateCandidates`。第一阶段只形成当前目标、条件、排除项、最多 7 条补充查询和是否需要追问的布尔值，模型生成的追问文案不进入产品，整阶段输出上限 800 Token；补充查询在继续深挖时继续用于免费来源召回和本地相关性判断。第二阶段只接收已经通过本地相关性与独立品质门槛、按本地证据排在最前且尚未送评的 6 个候选，每次寻找或继续深挖只执行一组比较，每组证据不超过 12,000 字符，不再进行多组晋级和最终比较。每次候选比较输出上限 1,500 Token；使用指南只服务于已加入 Skill，输入上限为 12,000 字符，输出上限为 2,400 Token。未进入模型预算的已核验候选不得丢失。每次模型必须逐一返回本组全部真实候选，漏评、重复、未知 ID、非法 tier、缺少可核对原句、引用否定能力或原句疑似提示注入时，整组丢弃并回到本地结果。模型结果只可解决本地合格候选的末端并列，不能新增、隐藏或降级推荐资格；reply、reason 和其他候选相关自由文本全部丢弃。服务商能力必须显式记录；DeepSeek 的结构化任务使用 JSON 模式并关闭思考输出。
- 发现链路中的每次模型需求整理或候选比较都有 20 秒真实墙上时钟上限，不依赖服务商是否正确回应取消。到时或用户点击停止后必须立即释放界面状态；需求整理超时时继续使用发送前已形成的本地语义计划查找免费公开来源，候选比较超时时保留本地质量排序，两者都不得将已核验结果清空或让寻找无限转圈。
- `DiscoverySearchCoordinator` 负责 skills.sh、GitHub Skill 搜索和可信来源目录的查询扩展、分页、去重、证据补全、缓存与结果稳定判断。`SkillDiscoveryProvider` 只负责单一来源；独立来源并发执行、结果按固定来源顺序合并。直接候选来源最长等待 55 秒，单个媒体查询最长等待 18 秒，媒体名称核验最长等待 25 秒，整条媒体支路最长等待 48 秒；外层等待必须严格长于内层组合预算，不能在下游仍有合法时间时提前丢弃整条支路。任一来源失败或超时不得清空其他来源已经核验的结果，用户取消必须及时传递到全部进行中任务。
- skills.sh 的原始查询与补充查询同时发出，每个搜索请求上限为 12 秒，候选正文与仓库资料请求上限为 10 秒，公开 raw 直读上限为 8 秒。外层来源超时一旦到达，必须立即交付其他已完成来源；即使某个底层任务没有及时响应取消，也不得把 55 秒截止拖成数分钟。
- UI 不直接读写 Agent 目录，只消费核心模块的只读模型和显式命令。
- 本地开发源解析、纯净物化和更新判断位于核心模块；SwiftUI 只负责选择目录、确认规则、展示状态和提交显式更新命令。一个项目可以包含多个 Skill，每个 Skill 独立保存相对位置与内容规则。
- 不启用 App Store Sandbox；启用 Hardened Runtime。应用只访问内置路径、用户选择路径和自己的 Application Support 数据。
- 用户选择的本地开发源保存安全作用域书签并保留可读路径作为恢复线索；书签失效或文件夹移动时进入“找不到开发源”，只允许用户重新关联，不得把安装快照反向当成来源。
- 外部网络用于 GitHub 登录授权、用户主动添加或更新检查、用户主动发起的 Skill 搜索和 AI 辅助请求。Skill 介绍只能由当前 Skill 详情中的明确按钮触发。启动时若距上次检查超过 24 小时，可在应用打开期间匿名顺序检查公开 GitHub 版本元数据；启动流程不得读取 GitHub 或用户配置 AI 的钥匙串秘密。任何 AI 任务都不得随启动、切换 Skill 或内容变化自动发起，不设后台常驻任务。
- GitHub 更新检查必须按「仓库 + 跟踪方式」归并为单队列。同一仓库的多个 Skill 共用仓库信息、Release 或分支检查结果，不得逐 Skill 重复查询相同端点。
- Release 来源平时只检查 Latest Release 及其 Assets；存在独立 ZIP 时不再为每次检查追加 Commit 和 Tree 请求。只有完整源码回退或默认分支真的发生变化时，才继续解析具体 Skill 目录。
- 根目录混合仓库按安装规则所选文件集合的稳定身份检查更新。Commit、README、CI 或发布说明变化但可安装内容未变时，状态保持“已是最新”。
- 旧版本曾把完整源码保存为中央 Skill 时，不得后台静默删文件。应用先生成纯净候选，经过一次确认后在影子目录校验并以事务原子替换；中央记录、GitHub 来源状态和由 SkillBox 管理的应用副本必须共同成功或共同恢复。
- GitHub 检查必须保存 `ETag`，优先使用条件请求。返回未变化时保留已知版本结论，只刷新检查时间，不重新下载或重算内容。
- 「连接 GitHub」是可选的统一入口：已连接时，公开仓库版本元数据优先使用用户的 GitHub 登录额度；授权失效或某个公开仓库不在应用可访问范围时，同一次检查自动退回匿名读取。未连接时公开仓库仍可匿名检查；私人仓库始终只访问用户明确授权的范围。公开仓库的认证失败不得提示用户连接私人仓库。
- Skill 介绍复用现有 `AIProvider` 与 `AIKeyStore`：客户端用钥匙串中用户自己的 Agnes Key，直接请求官方 HTTPS `POST /v1/chat/completions`，默认模型为 `agnes-2.5-flash`。请求不得跟随“发现 Skills”当前选中的其他服务商，Agnes 不可用时不得静默切换 DeepSeek。
- 更新检查、发现编排、内容脱敏和结果验证仍在本机完成；不建设 SkillBox AI 中转服务、公共版本索引、Webhook、GraphQL 批量层、SkillBox 账号或云端 Skill 库。
- 私人仓库使用 GitHub App Device Flow，只申请 `Contents: read` 与必要的 Metadata 读取权限。Access Token 和 Refresh Token 只保存在 macOS 钥匙串，且使用“仅本机、设备解锁时可访问”的可用性，不写入 JSON、日志或诊断信息；客户端不包含 Client Secret 或 GitHub App 私钥。
- AI 设置支持 Agnes、DeepSeek、Kimi、MiniMax、GLM 和自定义 OpenAI 兼容接口。内置服务预填官方兼容地址和推荐模型；自定义接口由用户填写 HTTPS 地址和模型 ID。模型 ID 不写入核心业务判断，用户可在设置中调整。
- 六类服务在设置页独立管理连接状态和 API Key。用户点击服务后在同一页面填写密钥、选择模型并“保存并测试”；只有完成最小结构化输出测试的服务才能标记为已连接和设为默认。所有 API Key 只进入 macOS 钥匙串，删除一家服务的密钥不得影响其他服务。
- API Key 由用户自行提供并存入 macOS 钥匙串，且使用“仅本机、设备解锁时可访问”的可用性。SkillBox 客户端不包含共享密钥；删除连接时同时删除对应钥匙串项目。
- 应用自动启动、状态恢复和后台检查只能读取不含秘密的连接提示，不得触发 macOS 登录密码或钥匙串授权窗口。只有用户明确执行“连接 GitHub”“保存并测试 API Key”或“获取 Skill 介绍”时，才允许 macOS 为当前应用身份显示钥匙串确认；读取成功后继续使用钥匙串中的原 Key，不要求用户重新粘贴。同一应用版本完成一次“始终允许”后，后续启动和主动使用都不得重复询问。ad-hoc 签名升级会改变应用身份，因此新版本最多允许在下一次用户主动操作时重新确认一次；若未来改用稳定 Developer ID 签名，应直接延续旧版本授权，不人为要求每次更新后重新确认。
- 发现目录、GitHub 元数据、Skill 内容与 OAuth 响应都必须边读取边计数并设置硬上限；远端声明长度或实际读取超过上限时立即终止，不得先把无限响应完整载入内存。
- AI 请求只包含相对路径、必要文本、确定性检查结果和当前任务所需差异。发送前在本地剔除 `.env`、私钥、Token、证书、本机绝对路径、用户名、二进制和无关文件。
- 默认输入优先级为 `SKILL.md`、`agents/openai.yaml`、作者明确的使用章节、被入口文件引用的文本、确定性风险附近的代码片段和更新差异。超过上限时按文件分段，不静默截断关键证据。
- AI 输出使用版本化 JSON 合同；缓存键至少包含 Skill 指纹、任务类型、提示词版本、服务商和模型。Skill 内容变化后旧结果只可作为历史记录，不得继续显示为当前结论。
- 发现服务使用可替换的 `SkillDiscoveryProvider`，由本地路由层选择精确、场景或混合链路，再由 `DiscoverySearchCoordinator` 在该链路内合并允许的媒体推荐线索、Hacker News、skills.sh、GitHub 中的真实 `SKILL.md` 与版本化可信来源目录。任一来源不可用时只影响本轮完成度，不影响已加入 Skill。
- 搜索请求只发送用户输入的需求文字，不发送本地 Skill 库。AI 可补充查询并比较已经读取真实证据的小批候选，但不得虚构候选、文件或能力。候选召回和确定性核验分批执行且不设产品展示总数截断；AI 证据预算只限制当轮模型上下文。
- 需求规划可同时发送当前发现对话的有限上下文：最多 6 条近期消息和 3 份候选引用，选中对象优先，上下文合计不超过 2,000 字符；原有目标摘要与最新输入各不超过 2,000 字符。资料先脱敏，外部摘要只作证据，不作为指令。不为每轮历史另行调用模型总结，不提高原有查询或输出预算。明确切换任务时，不继承旧目标、旧作者查询及旧对话引用；新结果不合并旧任务候选。对负面反馈中明确给出的新仓库，优先执行新目标。旧对话追问与补充交付物必须保留原任务身份。三栏布局保留；用户已确认连续对话、任务摘要与消息排队方向，按下述对话合同实现。
- 寻找记录单独保存在 `~/Library/Application Support/SkillBox/SearchSessions/`，每条记录使用可读文件夹名和版本化 `session.json`。列表优先显示本地快照；只有用户主动继续或刷新时才请求外部服务。删除寻找记录不得删除已加入的 Skill。
- AI 能力在服务层统一编排，在界面层按任务出现：发现页负责需求理解与候选解释，Skill 详情负责用户说明，加入或更新决策点负责安全和变化解释。v1.1 不提供全局聊天历史、通用问答、Agent 工具调用或跨任务的个人长期记忆。
- 同一内容身份的候选复用安全结果；外部安全审计只能作为补充证据，任何来源的“已审计”标记都不能跳过 SkillBox 本地检查。
- 任何环境都不得在客户端内置共享 Agnes Key，也不得以“免配置”名义代用户发起请求。
- 开源采用 MIT License。当前公开发行从项目官方 GitHub 仓库提供 ad-hoc Hardened Runtime DMG，不使用 Developer ID，不提交 Apple 公证。DMG 同时发布 SHA-256 与来源清单；首次打开或每次更新后，用户可能需要在“系统设置 → 隐私与安全”中点击“仍要打开”并输入 Mac 登录密码。相机、麦克风、文件夹等隐私授权仍按 macOS 独立流程处理。
- 无证书发行无法让 macOS 验证开发者身份，也无法抵御官方 GitHub 仓库或发布账号被攻破后产生的恶意替包。该风险由用户明确接受；工程侧必须用开源代码、固定来源快照、产物哈希、最小包内容、隐私扫描和可复现发布证据降低风险。Developer ID 与 Apple 公证仅作为未来可选加固，不再是当前上线强制条件。

## 10. 验收标准

- [ ] 应用只发现 Agent 全局安装位置，不扫描项目级 Skill，也不把 Agent 目录中的副本建立为来源。
- [ ] 添加入口只接受本地开发文件夹或 GitHub；每个新 Skill 有且只有一个来源。
- [ ] 手动选择一份本地 Skill 的根文件夹时，即使其普通文件总量超过自动扫描的 50 MiB 上限、但不超过手动添加的 128 MiB 上限，也能进入来源确认；扫描失败显示实际原因，不误报“没有找到 Skill”。
- [ ] 十个新用户默认内置 Agent、老用户已有兼容目标与自定义目录均能显示真实检测、写入和安装状态。
- [ ] 安装矩阵预览与实际写入一致，阻塞项不会被执行。
- [ ] 批量安装或卸载预览前后持久化安装选择一致；取消后不留草稿、接管或替换授权，也不修改应用文件夹。
- [ ] 高风险确认在应用重启后保留；Skill 内容或风险证据变化后重新提示，已阻止内容仍无法安装。
- [ ] 用户在风险详情中确认当前内容后，当前 Skill 详情必须立即从橙色待确认切换为绿色已确认，不得依赖切换 Skill 或重新打开页面才刷新。
- [ ] 打开或取消「恢复到操作前」预览不改文件；确认后才恢复，且操作后的外部改动不被覆盖。
- [ ] 一级导航依次为「我的 Skills、安装到应用、发现 Skills、设置」，不出现独立「最近操作」；每次写入完成后仍有即时结果与撤销，更早记录可从「设置 → 操作记录与恢复」进入。
- [ ] 设置页目录依次为「AI 服务、GitHub、存储与记录、操作记录与恢复、隐私与安全」，每行完整可点击并显示真实摘要；右侧只呈现当前设置任务。查看某家 AI 服务不得静默改变“发现 Skills”正在使用的服务，切换发现服务必须通过“使用服务”控件明确完成。
- [ ] 删除仍有受管理副本的 Skill 时可选择保留副本或全部卸载；保留路径不改应用文件，卸载路径在用户确认事务预览前不删除来源关联和安装快照。
- [ ] 正常中央内容进入 macOS 系统废纸篓并可在清空前即时撤销；SkillBox 自身不保留第二份删除备份，旧版 `Deleted/` 内容会迁入废纸篓。
- [ ] 中央内容缺失的旧记录仍可安全清理；其已占用的中央路径不得被新同名记录复用，清理旧记录也不得移动或删除新记录的内容。
- [ ] 撤销“只清理主 Skill”时只重新接管指纹未变化的原副本；已变化或缺失的副本保持不受管理，且不会被恢复操作覆盖。
- [ ] 「我的 Skills」列表行能直接看见唯一来源和已安装 Agent；拖动时原卡片变为空占位槽，其他卡片实时让位并预览松手后的顺序，跟手卡片无重影或压叠；占位槽仅用一根无端点、无文字注释的系统蓝线标明落点，松手或取消后占位槽、蓝线和浮层立即消失；右键移动与可恢复删除均能完成或取消，不留持久提示。
- [ ] 单个 Skill 右侧从顶部依次呈现名称与管理安装、来源／当前安装版本／版本情况、横向安装摘要、下划线式「Skill 介绍／文件详情」切换；介绍只用中性浅灰内容卡展示「作用、适用场景、使用流程、启动提示词」，其中使用流程是主体，必须在作者已明确规定时展示提问内容、选择项原名、可选值、回答格式、后续动作和真实交付物；启动提示词只触发 Skill 并表达大致目标，不预选后续答案或限制原生体验。正常来源不展开维护面板，只有可更新或来源异常时出现操作提示。“全部安装、全部卸载、管理安装”都先进入与当前 Skill 绑定的可取消预览。
- [ ] “安装到应用”的 Skill 列标题可直接选择全部、真实文件夹或未分类，选择全部时展示所有行，搜索可以叠加；单元格能区分安装、已安装、可更新、已有同名和应用不可用，界面不出现“已可用、间接可用、间接可见、比较内容、需要确认”。Agent 列头以可追溯的官方产品图标、名称和本机目录状态显示，不存在字母或自制图形占位；按住表头后独立浮层与鼠标一比一跟手，原位显示整列占位，相邻整列实时让位，左右边缘自动滚动，跨槽位提供轻触觉反馈；松手只保存一次最终顺序，拖出可见表格、按 Esc、窗口失焦或对象消失均取消。新增 Agent 追加到末尾，排序不会改变任何安装关系或目标路径。
- [ ] “管理应用”可移出和恢复内置应用列，可添加、改名和删除自定义应用；移除动作不删除电脑上的应用、目录或文件。存在受管理副本时，用户必须明确选择先卸载或保留文件并停止管理。
- [ ] 移出一个或多个预设应用后，「恢复全部预设应用」可一次全部找回；自定义应用、现有列顺序、安装关系和磁盘文件保持不变。安装表的「恢复默认顺序」只恢复排序，不找回或移除任何应用。
- [ ] GPT 的界面名称变化不创建新目标、不改变 `codex` 适配器、固定 UUID、`~/.codex/skills`、Assignment 或 ManagedInstallation；Kimi Code 旧路径迁移在用户确认前零文件改动。
- [ ] 中途失败能恢复本事务已修改目标；外部改动不会被同步或撤销静默覆盖。
- [ ] GitHub 添加、更新和风险扫描满足大小、数量、路径与不执行约束。
- [ ] 本地开发源的纯净候选只包含确认路径，来源内容和指纹在检查与安装全过程保持不变；包含范围外变化不误报，包含范围内变化才提示更新。
- [ ] 本地已选路径消失、新增可能运行内容或 `SKILL.md` 新引用未包含内容时暂停更新并要求确认；确认前安装快照和应用副本不变化。
- [ ] 本地或 GitHub 更新只有在用户确认后才能替换安装快照并更新所选受管理副本；来源移动或失效不会删除任何现有内容，重新关联前先展示差异。
- [ ] 未配置 AI、服务超时、额度不足或用户取消时，所有本地管理、安装、更新和撤销功能保持可用。
- [ ] Agnes、DeepSeek、Kimi、MiniMax、GLM 和自定义接口的连接测试、无效密钥、超时、限流、取消、结构损坏和缓存失效均有自动化覆盖。
- [ ] DeepSeek 的发现请求包含 JSON 模式和思考关闭参数；HTTP 200 的空内容、截断、损坏 JSON与字段校验失败均能准确分类，连接测试只有在最小结构化输出成功后才显示可用。
- [ ] API Key 只存在于设备解锁时可访问的本机钥匙串；JSON、日志、操作记录、诊断和 AI 请求预览中均不泄露密钥。
- [ ] 冷启动和 24 小时自动检查不读取钥匙串秘密、不出现 macOS 登录密码框；“保存并测试”或“获取 Skill 介绍”可在应用身份变化后主动读取旧 Key 并完成一次系统确认，用户取消时零发送，同一版本后续启动和主动使用保持安静。
- [ ] 打开应用、切换 Skill、新增 Skill、来源检查或内容变化都不得读取 Agnes Key 或发送 Skill 文字；只有用户在当前 Skill 中点击“获取 Skill 介绍”才请求一次。并发重复点击共用一个进行中请求，失败保留已有介绍且允许用户再次点击重试。
- [ ] AI 的每条安全或完整性结论都能核对真实文件证据；不存在的路径、越界行号、提示注入和截断输出不能改变安装决定。
- [ ] “发现 Skills”能在不安装 Node/npm、不打开浏览器、不读取浏览器登录态的前提下使用目录、skills.sh、GitHub、Hacker News、B 站与公众号搜索候选；可选 `yt-dlp` 缺失或任一公开媒体来源失败时平静降级，候选加入仍经过完整下载与本地审查。
- [ ] 同一输入框能自动区分精确、场景和混合查找：点名 Skill、仓库或 GitHub 路径时不搜媒体、不用模型比较，精确未找到时不用相似结果替代；只描述任务时优先展示可绑定公开社区推荐且已核对 `SKILL.md` 的候选，并在媒体不稳定或未写明名称时继续交付其他免费来源中用途匹配、质量达标的已核验结果；作者加能力或已知 Skill 加口碑问题进入混合查找。
- [ ] 推荐排序覆盖任务匹配、独立提及者、跨平台覆盖、Skill 级安装量、来源、维护、说明完整度和结构信号；同一作者跨平台重复发布只计一人，不把不同平台互动数直接相加。用途和交付物直接匹配优先于 GitHub Star，低热度但正文完整的候选能进入比较，用途不匹配的热门 Skill 仍不得推荐。发现阶段不显示全包安全结论，加入前的完整本地检查不得被搜索证据替代。
- [ ] 真实用户语句“我需要找去文案 AI 味的 skill”必须在完整应用流程中显示已核验的中文或通用改写候选；只诊断、学术专用、芬兰语专用或其他隐藏候选不得占用首屏与详情。无推荐或来源未完成时不显示绿色成功状态。
- [ ] 运行中的寻找不会被重新加载误判为中断；AI 失败不会在聊天区生成伪造回复；候选比较中的模型自由文本不会进入聊天或候选详情。AI 每轮只评估本地排序最高且尚未送评的 6 个候选，不做第二次组间比较，继续深挖时进入下一批；未送评的已核验高质量候选不会因模型上下文预算被丢弃。
- [ ] 中文 PPT、表格、PDF、写作、视频、设计、研究、邮件、日历、浏览器和 Swift 等常见需求在没有 AI 规划时仍能召回英文 Skill；安全审查、网站无障碍、新建 PPTX、Excel 分析、PDF 阅读与泛领域深度研究的固定基准同时校验应命中项和易混淆的排除项。目录结果展示前已重读真实 `SKILL.md`，低 Star 不构成送评门槛。
- [ ] 发现功能不需要任何付费搜索或索引服务；应用包内固定新增小于 1 MiB，唯一可选免费媒体工具 `yt-dlp` 在当前 Mac 的额外占用约 35.4 MiB，不创建视频／文章缓存、完整仓库镜像或本地向量库，模型调用之外没有新增第三方费用。未绑定的媒体讨论每轮最多保存 8 条元数据，并继续受全部寻找记录 64 MiB 总上限约束。
- [ ] Skill 搜索只在左侧一级导航“发现 Skills”中完成；寻找记录可继续、可单条删除、可全部清空且可在 Finder 中打开，但不接受与 Skill 发现无关的通用办公任务。
- [ ] GitHub 候选显示真实仓库级 Star、获取时间和仓库归属；多 Skill 仓库不会把同一 Star 数误写成单个 Skill 的独立评价。
- [ ] AI 整理的用户说明固定覆盖「作用、适用场景、用户视角使用流程、启动提示词」，使用普通用户能理解的大白话；「作用」能直接对应真实交付，「适用场景」能让用户判断启动时机，两者都不使用空泛效果语；流程能区分“先询问信息再继续”和“一步完成后交付结果”的真实体验，提示词可一键复制。“我的 Skills”中只在用户主动点击后生成或重新生成，内部规则和无依据推测不得展示。
- [ ] 公开仓库无需登录即可检查；连接 GitHub 后立即解除未登录额度暂停，已登录额度暂停仍遵守 GitHub 的恢复时间。GitHub 限流、私人仓库登录失效、仓库未授权、地址失效和网络故障分别显示正确动作。
- [ ] 多个 Skill 来自同一仓库时只发送一组仓库级检查；条件请求返回未变化时不发出后续 Commit、Tree 或下载请求。
- [ ] 自动检查的最短间隔为 24 小时；手动检查当前 Skill 可立即执行，批量检查显示仓库级进度且可中止；大型库优先处理最久未成功检查的仓库。
- [ ] 自动化测试通过，并完成核心主流程的真实鼠标前台验收。
- [ ] 全量测试、ad-hoc Hardened Runtime 签名、发布包隐私扫描、DMG 完整性、SHA-256、来源清单、隔离属性模拟、干净账户“仍要打开”安装和 GitHub Release 下载回读分别通过后，才能宣称当前发行策略下的公开发行完成。
