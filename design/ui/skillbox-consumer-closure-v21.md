# SkillBox v21：消费级交互闭环

## 目标

这版集中解决三类“提示出现了，但事情没有真正结束”的体验问题。目标用户是第一次接触 Agent Skill、不了解权限、指纹、事务等概念的普通 AI 用户。

统一体验原则：

1. **每条提示都给出口**：用户能立即处理、暂缓或退出，界面不会留下无法消除的警告。
2. **确认前不保存**：预览、目标选择、替换授权都只是本次草稿；只有最后确认才写入。
3. **高影响操作先预览**：恢复、卸载、替换都先说清会影响什么，再让用户决定。
4. **状态会收口**：待处理使用橙色；处理完成后变为安静的绿色或中性色，并保留“重新查看”。

## 闭环一：安装风险确认

状态固定为：

`待了解 → 查看并确认 → 已了解`

- 风险卡内直接提供「查看并确认」，不再只有展开/收起。
- 确认页先用白话说明“什么时候可能发生”，再展示技术证据。
- 「暂不安装」不会留下已确认状态。
- 确认完成后，大块橙色警告收成一条浅绿色状态，保留「重新查看」。
- 确认只对当前 Skill 内容版本和当前风险项有效。Skill 内容、风险项或来源版本变化后，自动回到「待了解」。

建议绑定键：`skillID + contentFingerprint + riskFindingSignature`。

## 闭环二：批量安装与卸载取消不留痕

- 应用勾选、安装目标和冲突处理在确认前都只存在于临时草稿。
- 预览页明确写「现在只是预览，确认前不会保存任何安装选择」。
- 「返回调整」保留本次内存草稿，方便继续修改。
- 「取消，不保存」丢弃整份草稿，包括替换授权，并恢复打开流程前的状态。
- 只有点击「确认安装」或「确认卸载」后，才保存目标关系并开始事务。

验收底线：打开预览后直接取消，再重启 SkillBox，安装关系、冲突授权和目标状态必须与操作前完全相同。

## 闭环三：恢复、移除与替换统一预览

- 「恢复到操作前」不再点击后直接执行。
- 预览必须列出每个受影响的应用、动作和数量。
- 如果目标文件在操作后被外部修改，预览中提前说明会停下并保留现状。
- 最后按钮使用动作本身命名，例如「确认恢复 5 个位置」，不使用含糊的「确定」。
- 移除和替换复用同一套预览结构，避免同类高影响操作出现三套交互。

## 文案与视觉规则

- 面向用户只写「当前内容版本」，不显示“指纹”“风险签名”等内部词。
- 橙色用于尚待决定，红色只用于明确破坏性结果，绿色用于已经完成且无需继续处理。
- 主按钮写清结果，例如「我已了解，继续安装」「确认恢复 5 个位置」。
- 二级技术证据允许展开查看，但不能挡住普通用户完成主流程。
- 弹窗进入和退出使用同一路径，默认无弹跳；系统开启“减少动态效果”时改为短淡入淡出。

## 原型页面

- `?scene=risk`：风险卡待确认状态。
- `?scene=risk&dialog=1`：风险说明与确认页。
- `?scene=risk&confirmed=1`：风险已经了解后的收口状态。
- `?scene=bulk`：批量安装预览与真正取消。
- `?scene=restore`：恢复到操作前预览。

## 实现边界

本轮只确认视觉和交互方向，不修改正式 SwiftUI。用户确认后再进入实现，并按 TDD 分成三个独立切片，分别验证风险状态持久化、取消回滚、恢复预览和前台交互。
