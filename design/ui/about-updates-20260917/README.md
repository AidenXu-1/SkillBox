## 已确认的设计选择

- 删除成功提示保留 6 秒，鼠标停留或键盘焦点进入时暂停，离开后重新计时。保留撤销和关闭按钮。应用重新打开时不再自动弹出旧删除提示。
- 提示关闭只隐藏界面，恢复记录继续保存；需要在“操作记录与恢复”中提供准确可用的“恢复 Skill”入口。原有 `UndoPreviewContent.canConfirm` 主要覆盖安装位置/保存版本，不能直接假定纯中央删除已可在历史中恢复。
- 关于：当前图标、名称、简短介绍、实际版本与构建号、复制版本信息。
- 软件更新：默认自动检查；默认关闭自动下载，可由用户开启。关闭自动检查时同时关闭/禁用自动下载。更新只针对 SkillBox App，与 Skill 来源更新分开。
- 检查中、无更新、有新版、下载中、可重启、失败均就地反馈，保留重试/取消；发现新版展开更新说明，不叠加常驻全局提示。
- 使用公开稳定更新源，不要求登录 GitHub。仓库、作者、日志与 Issues 以默认浏览器打开，反馈入口仅打开网页，不自动提交。
- 不添加捐赠、登录、评价、遥测或发布频道等额外选项。菜单中的“关于 SkillBox”与“检查更新…”同步通往同一入口。

## 根因与实施位置

当前工作树开始时干净。`ContentView.swift` 的普通 StatusToast 有 3.5 秒关闭任务，但底部 DeleteUndoToast 只依赖 `model.lastDeletedSkill`，没有计时。`AppModel.start` 启动路径还会用 `mostRecentRestorableDeletion()` 重新填回上次删除；`dismissDeleteUndo()` 仅清除内存，重启后还会重新出现。

实施时将“恢复凭据”和“短暂可见的提示”分开，不删除持久记录以隐藏提示。延时关闭按删除事件身份核对，避免旧计时关闭新提示；历史恢复复用现有 `restoreDeletedSkill` 的内容核对，不绕开文件冲突和废纸篓已清空等处理。

涉及位置：ContentView/AppModel、应用入口菜单、新的更新协调对象、包依赖、Info.plist、打包脚本、发行脚本与对应行为/包态测试。正式实施前将确认结果补到 Spec。

## 自动更新可行性与尚待验证的条件

- 本轮核对源码版本为 0.2.4（17）；GitHub API 读取最新公开 Release 为 v0.2.4，附件仅有 DMG、SHA-256、release.json。项目当前没有 Sparkle 依赖、更新清单地址或更新签名公钥。未从附件名推断内容已签名。
- 建议新依赖 Sparkle 2：负责下载、验证与应用替换。替代方案是自行实现完整更新器，维护范围显著更大；只跳转下载网页不能满足应用内更新。
- 当前 ADR-0010 使用 ad-hoc 签名和 Hardened Runtime，不购买 Apple 开发者证书。Sparkle 官方明确提示此组合的 Library Validation 兼容问题，必须先在隔离候选验证 framework 嵌入、嵌套程序签名和实际启动。不得为了接入默默降低全局系统安全设置或改成购买证书。
- 更新包需要 Ed25519 签名以及固定的 HTTPS appcast；密钥留在钥匙串/CI Secrets，仓库与 App 只包含公钥。下载校验失败不得执行或安装。依赖版本锁定，保留必要许可。
- 版本比较必须包含构建号，避免本机 0.2.4（17）误退回公开 0.2.4（14）。需要确认架构/macOS 要求，过滤草稿及预发布；无更新源不能显示“已是最新”。
- 安装前等待 Skill 文件操作结束，完成应用包替换；正常更新不备份或改写用户资料。仅有应用替换期间的临时空间占用，成功后清理，不累计历史 App。失败时让原应用保持可用，不强行中断 Skill 安装事务。此处为用户对新应用内更新方案的明确简化，取代此前套用一份/七天完整备份的设计；不据此删除已有备份或改变 Skill 安装/删除操作的恢复规则。
- 旧版没有更新器，首次获得更新功能仍需手动安装一次带更新器的版本，此后方可应用内升级。
- 设计阶段未生成密钥；实施后已在钥匙串生成签名密钥，公开源和版本尚未发布；本机 App 替换和公共发行分别核验。自动更新完成的证据必须包括隔离安装的旧候选真实升级到新候选，不能只用按钮截图或编译通过代替。
