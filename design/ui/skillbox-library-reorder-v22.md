# SkillBox v22：Skill 列表整理与上下文操作设计

## 本轮目标

这版只处理「我的 Skills」左侧列表的三件事：

1. 拖动排序时，始终看清最终会落到哪个 Skill 的上方或下方。
2. 列表卡片只保留 Skill 名称、来源类型和中央库存储大小。
3. 右键菜单只提供与当前 Skill 直接相关的「移动到」与「删除 Skill」。

这是交互候选，用户确认前不进入正式 SwiftUI。

## 卡片信息层级

- 第一行：Skill 名称。
- 第二行：`GitHub 来源 / 本地来源 · 存储大小`。
- 左侧首字母图标只用于快速扫视，不增加新的信息字段。
- 去掉用途描述、仓库名、文件数量和更新时间。这些内容继续放在右侧详情页。
- 存储大小只计算 `Library/<skill-name>/content` 的中央纯净副本，不包含 GitHub 下载缓存、备份和各 AI 应用里的安装副本。

## 拖动反馈

- 按下开始拖动后，原位置保留一张低透明占位卡，避免列表瞬间塌陷。
- 跟随指针的卡片轻微浮起，使用白色实面、细蓝描边和柔和投影；不做夸张旋转或弹跳。
- 每张目标卡按上下各 `50%` 分区。指针进入上半区，显示「放到 XXX 上方」；进入下半区，显示「放到 XXX 下方」。
- 目标位置真实腾出约 `22 pt` 空间，并显示 `2 pt` 系统蓝插入线、左侧空心圆端点和文字胶囊。三种信号同时存在，避免仅靠颜色表达。
- 指针跨过卡片中线时，插入线直接切换到另一侧；释放后以无回弹、可打断的短弹簧落位。开启「减少动态效果」时改为短淡入淡出。
- 无效目标不显示蓝线；跨文件夹时文件夹标题整体高亮，落下后保持当前选中项。

## 右键菜单

- 菜单锚定在右键位置，使用 macOS 熟悉的紧凑上下文菜单。
- 第一组只有「移动到」，子菜单列出「未分类」和当前已有文件夹；当前位置显示勾选。
- 第二组只有红色「删除 Skill…」，固定放在最后并用分隔线隔开。
- 删除后进入现有可恢复删除流程：主 Skill 移入 macOS 废纸篓，并在「最近操作」提供撤销。菜单本身不承担复杂删除范围选择。

## 交互与可访问性

- 整行都可拖动，悬停时才出现低强调拖动把手，降低默认视觉噪声。
- 插入位置同时提供 VoiceOver 描述，例如「放到 agent-team 下方」。
- 键盘和辅助操作使用与拖动相同的排序模型，不另造一套结果。
- 高对比度模式加粗插入线；减少透明度模式将菜单改为不透明背景。

## 与平台规范的对应

- 列表文字保持短而可扫，详细说明放到右侧详情。
- 拖动目的地只有在可接受时显示明确插入点。
- 上下文菜单只保留当前对象最常用的动作。
- 删除位于菜单末尾，使用破坏性颜色，并继续保留撤销出口。

## 预览入口

- `?state=normal`：普通列表。
- `?state=above`：拖到 `zhaoji-writing` 上方。
- `?state=below`：拖到 `obsidian-feishu-sync` 下方。
- `?state=menu`：右键菜单和「移动到」子菜单。
- 页面本身也支持直接拖动和右键点击。
