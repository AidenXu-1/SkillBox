# SkillBox v20：本地开发源

## 目标

让用户把长期迭代的本地项目文件夹设为 Skill 的开发母板，同时让 SkillBox 与各 AI 应用继续只保存经过确认的纯净可使用版本。

数据流固定为：

`用户项目文件夹（母板） → 可使用内容规则 → SkillBox 主 Skill（发布快照） → 已安装应用副本`

SkillBox 只读取母板，不移动、不重命名、不反向改写，也不执行其中的脚本或构建命令。

## 关键交互

### 1. 首次从电脑添加

- 默认推荐「持续跟踪这个开发源」。
- 用户也可以选择「只导入这一次」，保持现有一次性导入行为。
- 界面先展示会进入 SkillBox 的可使用内容，以及只留在开发项目里的内容。
- `SKILL.md` 永远包含；其明确引用的本地文件不能被排除。

### 2. Skill 详情中的来源卡

- 显示开发源位置、最近核对时间和当前状态。
- 主操作随状态变化：检查更新、查看更新、重新关联、确认可使用内容。
- 次级菜单提供在 Finder 中显示、编辑可使用内容、停止跟踪。
- 停止跟踪只把当前主 Skill 变为普通本地副本，不删除母板、中央内容或应用副本。

### 3. 更新预览

- 分开显示「会更新的可使用内容」与「已忽略的开发文件变化」。
- 用户可选择只更新 SkillBox 主 Skill，或同时更新未被外部修改的应用副本。
- 确认前不修改任何保存内容；确认后复用现有备份、事务、撤销和指纹保护。

### 4. 来源移动或消失

- 保留 SkillBox 主 Skill和所有现有应用副本。
- 状态改为「找不到开发源」，主操作变为「重新关联」。
- 新位置必须先核对 Skill 身份与内容差异，不能直接覆盖。

## v1 边界

- 手动检查本地更新，不监听每次保存。
- 不把开发项目迁入 SkillBox 保存位置。
- 不运行构建、清理、安装依赖等项目命令。
- 不用 AI 猜测哪些文件应当发布。
- 不做双向同步，也不把应用内改动写回母板。
- 一份项目可识别多个 Skill，但每个 Skill 独立保存自己的相对位置和可使用内容规则。

## TDD 公共验收边界

1. **纯净打包**：给定母板与精确包含路径，生成的候选只含这些内容；母板目录和文件指纹保持不变。
2. **更新判断**：包含范围外变化不提示更新；包含范围内变化提示更新；已选路径消失或出现新的可能运行内容时进入“需要确认”，中央原件保持不变。
3. **事务更新**：检查与预览不写入中央库或应用；确认后可选择只更新主 Skill，或通过现有事务同时更新安全的应用副本，并可撤销。
4. **持久化与重连**：重启后仍能恢复母板位置、Skill 相对路径与内容规则；来源不可用时保留现有内容，重新关联前必须预览差异。

## 原型页面

- `?screen=link`：首次关联开发源。
- `?screen=detail`：Skill 详情中的开发源卡片。
- `?screen=update`：本地更新预览。
